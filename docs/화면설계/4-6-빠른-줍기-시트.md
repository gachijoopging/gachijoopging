# 4-6 빠른 줍기 시트

**목적** 사진 없이 카테고리 한 번 눌러 줍기를 바로 기록하고, 이번 활동에서 지금까지 주운 개수를 카테고리별로 본다.
**원본** `../legacy/android-res/layout/sheet_pickup.xml` (분류별 줄 `item_pickup_stat.xml`) · **변경** 보기만 하던 "이번 활동 수거 목록" 시트에 입력이 들어왔다. 분류 완료 목록(카테고리·개수 줄) → 카테고리 7종 격자(2줄, 4+3)로 바뀌고 칸이 곧 버튼이다. 미분류 절은 사라졌다(AI 는 4-5 에서 확인하고 저장한다). 손잡이·제목·닫기 버튼 자리는 그대로
**진입** 4-3 활동 중의 "줍기" 알약 · **이탈** 닫기·스크림·아래로 끌기·뒤로 가기 → 4-3. 저장은 시트를 닫지 않아도 이어진다(낙관 저장)

## 배치

옛 XML 의 세로 순서(손잡이 → 제목 → 빈 문구 → 스크롤 목록 → 닫기)를 따른다. 스크롤 목록 자리에 카테고리 7종 격자가 들어가며 격자는 한 화면에 다 들어가 스크롤하지 않는다. 시트 높이는 내용만큼(약 절반). 스낵바는 시트 위가 아니라 4-3 화면 바닥에 떠서 시트를 닫아도 남는다.

## 인터랙션

- 스크롤: 없음. 격자 7칸이 한 화면에 들어간다. 스테퍼 줄이 펼쳐져도 시트가 그만큼 자란다
- 당겨서 새로고침: 없음
- 길게 누르기: 카테고리 칸을 길게 누르면(0.4초) 스테퍼 줄이 펼쳐진다. 스테퍼의 − / + 를 길게 누르면 0.3초마다 1씩 이어서 바뀐다
- 탭: 칸을 누르면 +1. 칸의 숫자가 살짝 커졌다 돌아오고, 0 → 1 이면 테두리가 진해진다. 연속 탭은 그대로 누적된다(담배꽁초를 세 번 누르면 3)
- 되돌리기: 스낵바가 떠 있는 5초 안에만 가능하다. 모은 탭을 전부 취소하고 스낵바 "되돌렸어요" 를 짧게(2초, 액션 없음) 보인다. 부분 되돌리기는 없다 — 하나만 빼려면 스낵바가 사라진 뒤 4-7 활동 종료 요약에서 고친다(`PATCH` · `DELETE /activities/{id}/items/{itemId}`)
- 시트: 스크림 탭·아래로 끌기·닫기·뒤로 가기 모두 4-3 으로. 닫혀도 스낵바와 5초 타이머는 4-3 에 남아 되돌리기가 계속 된다. 스테퍼가 열린 채 닫으면 N 은 버린다(담지 않는다)
- 뒤로 가기: 시트를 닫는다. 확인은 묻지 않는다(버릴 것이 없다)
- 키보드: 없음. 수량은 − / + 로만 바꾼다
- 시트 다시 열기: 스낵바가 살아 있는 동안 다시 열면 아직 안 보낸 탭이 더해진 숫자로 보인다. 그 뒤 탭은 같은 스낵바에 이어 모인다
- 전환: 시트는 아래에서 올라온다. 다이얼로그는 모달. 4-1 로 갈 때는 4-3 을 스택에서 지운다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 시트가 열리면 ② 제목으로 포커스가 간다. "이번 활동 줍기 12개"
  - 카테고리 칸: 칸 하나를 한 요소로 "담배꽁초, 8개, 하나 담기". 탭 힌트 "여러 개 담으려면 길게 누르기". 아이콘은 읽지 않는다. 탭하면 새 숫자를 읽어 준다(live region)
  - 스테퍼: "담배꽁초 빼기" · "담배꽁초 더하기" · [담기] 는 "담배꽁초 5개 담기". 비활성이면 비활성으로 읽힌다
  - 닫기: "닫기"
  - 스낵바: 나타나는 순간 문구를 읽어 준다(live region). 되돌리기 버튼은 스크린리더에서 5초 뒤에도 사라지지 않고 포커스를 옮기거나 다른 탭을 할 때까지 남는다
  - 손잡이·스크림: 장식이라 읽지 않는다
- 최소 터치 크기 예외: 없음. 칸은 폭의 1/4 로 44dp 를 넘는다. 스테퍼의 − / + 는 각각 44dp. 되돌리기는 스낵바 오른쪽 끝 44dp

## 옛 화면과의 차이

- 제목 "이번 활동 수거 목록 N개" → "이번 활동 줍기 N개". "수거" 를 "줍기" 로
- 미분류 절(`unclassHeader` · `unclassList` · "분류가 필요해요" · "미분류")과 분류 완료 절(`statsHeader` · `statsList`) → 카테고리 7종 격자 하나. 옛 `item_pickup_stat` 의 이모지 원·이름·개수가 칸 하나로 접혔고, 칸이 곧 버튼이다. 미분류는 4-5 에서 저장 전에 끝나므로 이 시트에 오지 않는다
- 빈 문구 "아직 수거한 항목이 없어요. 쓰레기를 촬영하면 여기에 쌓여요." → "아직 주운 게 없어요. 카테고리를 누르면 바로 담겨요." 촬영 없이도 담을 수 있게 됐다
- 항목별 삭제 확인("이 항목을 삭제할까요?")과 분류하기(`cd_pickup_edit`) → 없음. 대신 5초 되돌리기. 건별 수정은 4-7 에서
- "%s 담았어요" 토스트는 유지하되 여러 카테고리를 "·" 로 잇고 [되돌리기] 가 붙었다(4-5 와 같은 꼴)
- 닫기 버튼·손잡이는 그대로
- 스테퍼는 새로 생겼다. 옛 앱의 수동 입력은 4-5 의 "직접 분류" 칩 한 번에 한 개였다

## 미결

- 오프라인 대기열: `ItemInput.id`(앱 생성 uuid) 로 같은 항목 재전송은 200 으로 흡수되므로 대기열이 두 번 보내도 줍기가 두 번 쌓이지 않는다(4-5 와 같은 규칙). 대기열 보존 기간은 미정
- 되돌리기: 응답 `ActivitySummary.items` 에 생성된 `Item.id` 가 오므로 보낸 뒤에도 `DELETE /activities/{id}/items/{itemId}` 로 되돌릴 수 있다. 이 문서는 요청 수를 줄이기 위해 5초 묶음 전송을 유지했다. 묶음 없이 즉시 전송 + 저장 뒤 되돌리기로 바꿀지는 구현 때 정한다
- 저장을 5초 뒤에 보내므로 그 사이에 활동을 종료(4-3 → 4-7)하면 아직 안 보낸 묶음이 있다. 종료 요청 전에 대기열을 먼저 비워야 한다 — 4-3·4-7 설계서에서 정한다
- 스낵바 5초·길게 누르기 0.4초·수량 상한 99 는 내가 정한 값이다. 계약은 `quantity` 에 `minimum: 1` 만 있다
