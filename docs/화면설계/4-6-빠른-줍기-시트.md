# 4-6 빠른 줍기 시트

**목적** 사진 없이 카테고리를 눌러 즉시 줍기를 기록하고, 수량 입력과 되돌리기를 시트 안에서 제공한다.
**원본** `../legacy/android-res/layout/sheet_pickup.xml` (`item_pickup_stat.xml`) · **변경** 읽기 전용 목록을 4-5와 같은 2열 카테고리 카드와 수량 입력으로 바꿨다. 미분류 절을 없애고 즉시 저장·저장 후 되돌리기를 추가했다.
**진입** 4-3 줍기 알약 · 4-4 오프라인 안내의 빠른 줍기 · **이탈** 닫기·스크림·아래로 끌기·뒤로 → 4-3

## 배치

손잡이 → 제목·안내 → 2열 카드 7개 → 최근 입력·되돌리기 → 닫기. 카드는 4행이며 마지막 행은 한 칸이다. 작은 화면·큰 글자에서는 장식 여백부터 줄이고 본문을 스크롤한다. 글자나 48dp 조작 영역은 줄이지 않는다. 되돌리기는 모달 뒤의 4-3 스낵바에 가리지 않고 시트 내부에 보인다.

```
┌──────────────────────────────────────┐
│ ①              ▬▬▬▬                  │
│ ② 이번 활동 줍기 12개                 │
│    하나 담기 또는 수량을 입력하세요     │
│ ③ ┌────────────────┬────────────────┐│
│   │ 담배꽁초 총 8개│ 캔 총 1개      ││
│   │ [하나 담기]    │ [하나 담기]    ││
│   │ − [1] + [담기]│ − [1] + [담기]││
│   ├────────────────┼────────────────┤│
│   │ 플라스틱 총 3개│ 종이 총 0개    ││
│   │ 동일한 입력    │ 동일한 입력    ││
│   ├────────────────┼────────────────┤│
│   │ 유리 총 0개    │ 비닐 총 0개    ││

│   │ 일반 총 0개    │                  │

│ ⑤ 캔 1개 담았어요 · 저장됨 [되돌리기]   │
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 손잡이·시트 | 4-3 위 바닥 시트 | `BottomSheet` | 끌기·스크림으로 닫기 |
| ② | 제목·안내 | "이번 활동 줍기 N개", 서버 `itemCount`에 미동기화 추가·되돌리기를 반영한 값. "하나 담기 또는 수량을 입력하세요" | `Txt` section/caption | — |
| ③ | 카테고리 카드 | 담배꽁초·캔·플라스틱·종이·유리·비닐·일반 순서. `byCategory` 합계 표시, 4-5와 같은 아이콘·2열 카드 | `Tile` + `Icon` + `Txt` | [하나 담기]로 해당 종류 +1 |
| ③ | 수량 입력 | 추가할 수량, 기본 1. − / 숫자 직접 입력 / +와 [담기]. 버튼이 좁으면 담기는 다음 줄. 1 이상 정수, −는 1에서 비활성 | 4-5 공통 스테퍼 + `Field` numeric + `Button` | [담기]로 N개 추가. 필드·버튼 각 48dp 이상 |
| ⑤ | 최근 입력·되돌리기 | 마지막 입력의 종류·수량 및 "저장 중 / 동기화 대기 / 저장됨". 시트 안에서 계속 접근 가능 | `Banner` + `Button` ghost | 전송 전 취소 또는 저장된 `Item.id` 삭제 |
| ④ | 닫기 | 시트를 닫아도 저장·동기화 계속 | `Button` primary lg | 4-3 |

한 번 담을 때 `ItemInput.id` UUID를 만들고 계정별 기기 저장소에 먼저 영구 보존한 뒤 `POST /activities/{id}/items`를 즉시 보낸다. `photoId` null, `category`·`quantity`·`id`만 전달하고 AI 필드는 생략한다. 5초 배치 버퍼는 없다. 응답 `itemCount`·`byCategory`에 아직 응답하지 않은 로컬 작업을 더해 표시하여 늦은 응답이 최신 수량을 덮지 않게 한다.

되돌리기는 마지막 담기 작업 단위다. 미전송 요청이면 대기열에서 취소한다. 전송 중이면 응답을 확인한 뒤, 저장됨이면 즉시 `DELETE /activities/{id}/items/{itemId}`를 보낸다. 삭제 의도도 디스크에 저장해 네트워크 실패·앱 종료 후 재시도한다. 완료 전에는 "되돌리는 중 / 동기화 대기"이며 중복 탭을 막는다. 취소한 생성 요청을 나중에 다시 전송하지 않는다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | 로컬 활동·대기열 합계로 즉시 표시. 서버를 기다리지 않는다 | 전부 |
| 새로고침 | 별도 새로고침 없음. 복귀 시 4-3의 서버 값과 로컬 대기열을 함께 반영 | 평소와 같다 |
| 빈 | "아직 주운 게 없어요. 하나 담기 또는 수량을 입력하세요", 모든 합계 0 | 전부 |
| 저장 중 | 개수 즉시 증가, ⑤ 저장 중. 작업별 같은 UUID 재사용 | 추가 입력·닫기·되돌리기(응답 뒤 삭제) |
| 오류 | 입력·요청 id·대기열 유지, ⑤ "저장하지 못했어요" [다시 시도]. 필드 검증 오류는 필드 아래 표시 | 유효 입력·재시도·닫기 |
| 오프라인 | "기기에 저장했어요 · 동기화 대기". 같은 요청을 연결 복구·앱 재실행 때 순서대로 전송 | 담기·되돌리기·닫기 모두 가능 |
| 권한 거부 | 카메라·걸음수·위치 권한 없이 빠른 줍기를 기록할 수 있다 | 전부 |
| 부분 실패 | 대기열 앞 작업 실패 시 뒤 작업과 종료 요청 보류. 미동기화 작업·오류·재시도 안내 | 재시도·닫기 |
| 일시정지 중 | 시간·거리·걸음 누적만 정지하며 줍기는 정상 | 전부 |
| 직접 입력 오류 | 빈 값·음수·소수·범위 초과는 입력칸 아래 오류. 해당 [담기] 비활성 | 숫자 수정·다른 카드·닫기 |
| 되돌리는 중 | 취소·삭제 의도 보존, 처리 상태 표시. 완료하면 합계 확정 | 중복 되돌리기 외 조작 |

서버 오류는 `code`로 처리한다. 401은 토큰 갱신 후 같은 요청 재시도, 로그인 필요 시에도 원래 계정 데이터를 보존한다. 403·404는 "활동 상태를 확인해 주세요. 미동기화 기록은 기기에 남아 있어요"와 상태 재조회, 422는 값 오류·수정 안내, 429·5xx는 재시도다. 어떤 오류도 미동기화 기록을 자동 삭제하지 않는다.

## 인터랙션

- 스크롤: 시트 본문 세로 스크롤. 닫기·되돌리기까지 접근 가능하다.
- 당겨서 새로고침: 없음.
- 길게 누르기: 필수 기능 없음. 다량 입력은 항상 보이는 숫자 필드로 수행한다.
- 담기: 하나 담기·N개 담기 모두 즉시 로컬 저장 후 전송. 작업 id별 중복 응답을 합계에 다시 더하지 않는다.
- 되돌리기: 시트 내부 최근 작업 액션에서 실행하며 시트가 열린 동안 시간만으로 사라지지 않는다. 다음 작업 이후 과거 개별 수정·삭제는 5-3 기록 상세에서 한다.
- 시트: 스크림·끌기·닫기·뒤로 모두 4-3. 이미 담은 요청과 되돌리기는 취소하지 않는다.
- 뒤로 가기: 키보드가 열렸으면 먼저 키보드 닫기, 그다음 시트 닫기.
- 키보드: 숫자를 탭하면 숫자 키패드. 완료로 입력 확정. 필드 오류·담기 버튼을 키보드 위로 스크롤한다.
- 시트 다시 열기: 계정별 로컬 활동·대기열·최근 작업을 복원한다.
- 종료 연계: 4-3은 모든 줍기·삭제 작업과 종료 스냅샷을 보존한 뒤 즉시 4-7로 이동한다. 줍기·되돌리기를 서버에 반영한 후 종료 요청을 보낸다. 이전 종료 동기화가 끝날 때까지 새 활동만 막는다.

## 접근성

- 제목으로 초기 포커스, 카테고리 이름·합계·저장 상태를 읽는다. 아이콘은 장식이다.
- [하나 담기]는 "캔 하나 담기", − / 숫자 / +는 각각 "캔 수량 줄이기 / 추가 수량 / 늘리기", [담기]는 "캔 5개 담기"로 읽는다.
- [되돌리기]는 "최근 캔 1개 담기 되돌리기". 모달 내부 포커스 순서에 포함하며 상태 변화만 알린다.
- 모든 버튼·숫자 입력 최소 48dp. 2열에 들어가지 않으면 카드 내부 버튼을 다음 줄로 보내며 글자·터치 영역을 줄이지 않는다.

## 옛 화면과의 차이

- 수거 목록을 줍기 입력으로 바꿨다. 미분류 목록 대신 AI 확인은 4-5에서 수행한다.
- 4+3 배열을 2열로 바꾸고 −/+와 직접 숫자 입력을 공통 사용한다.
- 5초 대기 전송 대신 즉시 영구 저장·전송한다. 되돌리기는 저장된 항목도 삭제하며 시트 내부에서 실행한다.
- 이후 항목 카테고리·수량 수정·삭제는 5-3 기록 상세에서 한다.

## 미결

- 수량 서버 상한은 계약·구현에서 확정해야 한다. UI는 임의의 99 상한을 두지 않는다.
- 내구성 대기열·생성 멱등성·삭제 재시도·종료 전 순서 보장과 프로세스 종료 복구의 구현 검증이 필요하다.
