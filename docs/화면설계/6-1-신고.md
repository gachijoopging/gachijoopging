# 6-1 신고

**목적** 게시물·댓글·크루원·크루 채팅 메시지 중 부적절한 것을 크루장에게 알린다.
**원본** `../legacy/android-res/layout/fragment_report.xml`(사유 행 `item_report_reason.xml`) · **변경** 신고 대상이 게시물·댓글뿐 아니라 사용자·크루 채팅 메시지까지 넓어졌다(계약 `targetType`). 접수 뒤 화면 안 완료 상태(`doneState`) → 뒤로 가며 Snackbar. 대상 미리보기 줄이 새로 생겼다
**진입** 5-4 타인 프로필 안전 시트 [신고하기](`targetType` USER, 크루원만 이 행을 본다) · 5-2 게시물 상세 더보기 시트 [신고](POST) · 5-2 댓글 길게 누르기 [신고](COMMENT) · 3-7 크루 채팅 말풍선 길게 누르기 [신고하기](CHAT_MESSAGE) · 3-6 공지 상세 댓글 메뉴 [신고](NOTICE_COMMENT) · **이탈** 접수 성공 시 진입한 화면으로 돌아가며 Snackbar · 뒤로 가기로도 진입한 화면

## 배치

옛 XML 의 세로 순서(헤더 → 안내문구 → 사유 목록 → (기타일 때만) 메모 → 제출 버튼)를 그대로 따르되, 안내문구 위에 무엇을 신고하는지 보여주는 대상 미리보기 카드를 새로 넣었다. 헤더만 고정, 그 아래가 통째로 세로 스크롤이다(옛 `ScrollView` 그대로). 접수에 성공하면 옛 화면처럼 이 자리에서 완료 문구를 보여주는 대신, 다른 신고류 흐름(5-9 차단 해제 등)과 맞춰 진입한 화면으로 돌아가며 Snackbar 로 알린다.

## 인터랙션

- 스크롤: 헤더 아래가 세로 스크롤(옛 `ScrollView` 그대로). 제출 버튼은 스크롤 영역 맨 아래
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: 없음. 확인 대화상자 없음(제출은 바로 나간다)
- 뒤로 가기: 진입한 화면으로 돌아간다. 사유·메모를 골랐어도 확인 없이 버린다. 전송 중에는 막는다(비활성)
- 키보드: 메모를 탭하면 키보드가 올라오고 최대 4줄까지 늘어난 뒤 안에서 스크롤. 500자에 닿으면 더 입력되지 않는다
- 전환: 5-4 · 5-2 · 3-7 에서 푸시. 성공하면 그 화면으로 pop

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로 가기"
  - ② 카드: 한 요소로 묶어 "신고 대상, 상혁" 처럼 읽고, 본문 인용이 있으면 이어서 읽는다

## 옛 화면과의 차이

- 접수 뒤 화면 안 완료 상태(`doneState` — 체크 아이콘 · "신고를 접수했어요" · [돌아가기]) → pop 하며 `Snackbar` "신고를 접수했어요" 로 바꿨다(5-9 차단 해제 등 다른 화면과 흐름을 맞췄다)
- 신고 대상이 게시물·댓글·사용자에 더해 크루 채팅 메시지까지 늘었다(3-7 이 신규로 신고를 갖게 되면서). 계약 `targetType` 의 NOTICE_COMMENT는 3-6 공지 상세 댓글 메뉴에서 이 화면으로 온다
- 무엇을 신고하는지 보여주는 대상 미리보기(②)가 새로 생겼다. 옛 화면은 사유 목록만 있고 대상 표시가 없었다
- 사유 다섯 항목의 한글 표기(스팸·도배 / 혐오·욕설 / 부적절한 사진 / 사생활 침해 / 기타)는 이 문서가 새로 붙였다. 옛 XML 은 텍스트 없이 빈 행(`item_report_reason`)만 두고 코드에서 채웠을 것으로 보여 실제 문구를 확인할 수 없었다(아래 미결)
- 안내 문구·메모 라벨·"*필수"·제출 버튼 라벨·완료/실패 토스트 문구(`rp_desc`·`rp_etc_label`·`rp_etc_required`·`rp_submit`·`toast_reported`·`toast_report_failed`)는 그대로 가져왔다. 메모 placeholder 는 "운영진 검토용" 을 "크루장 검토용" 으로 바꿨다(크루 모델엔 운영진이 없다)
- "기타" 선택 시에만 메모가 나타나고 필수가 되는 규칙(`rp_etc_required`)은 그대로 유지했다
- 크루원만 신고할 수 있고 크루장은 처리만 한다는 제약은 이 화면이 아니라 진입하는 화면들(5-4·5-2·3-7)이 이미 걸어 둔 것이라 이 문서는 다시 다루지 않았다

## 미결

- **사유 다섯 항목의 한글 표기가 계약·리소스 어디에도 없다.** `POST /reports` 의 `reason` enum(SPAM·HATE·INAPPROPRIATE_PHOTO·PRIVACY·OTHER)은 토큰뿐이고 옛 XML(`item_report_reason`)도 빈 행이라 실제 문구를 알 수 없다. 이 문서가 새로 붙인 한글 표기(스팸·도배 / 혐오·욕설 / 부적절한 사진 / 사생활 침해 / 기타)는 확정이 필요하다
- **대상 미리보기 정보의 전달 방식.** 이 화면은 닉네임·사진·본문 앞부분을 진입한 화면에서 넘겨받는다고 가정했다. 그런데 5-4·5-2·3-7 문서의 이탈 절은 "6-1 신고 (`targetType` ○○ · `targetId` = ○○)"처럼 두 값만 명시하고, 미리보기용 텍스트·사진까지 함께 넘기는지는 적혀 있지 않다. 계약에도 `targetId` 하나로 대상 미리보기를 다시 조회하는 경로(예: `GET /reports/preview`)가 없다. 세 진입 화면 문서와 맞춰 확정이 필요하다
- **409 의 정확한 뜻.** `POST /reports` 요약에 409 응답만 있고 무엇의 충돌인지 설명이 없다. 이 문서는 "같은 사용자가 같은 대상을 이미 신고했을 때"로 해석해 "이미 신고한 대상이에요" 문구를 새로 붙였다. 서버 구현 확정 시 이 해석을 다시 확인해야 한다
- **"기타" 사유 메모 필수를 서버가 강제하는지 모른다.** 계약은 `memo` 를 선택 필드로만 두고 사유별 필수 규칙이 없다. 클라이언트만 막고 있어 다른 경로(예: API 직접 호출)로는 메모 없이 "기타" 신고가 들어올 수 있다
- `화면.md` 이동 지도에 5-2(PD)·3-7(CH) → RP(6-1) 간선이 없다(현재 UP(5-4) 하나뿐). 이 문서의 진입 목록대로 지도를 보강해야 한다
