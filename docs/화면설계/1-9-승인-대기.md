# 1-9 승인 대기

**목적** 가입 신청을 낸 사람이 어느 크루의 승인을 기다리는지 확인하고, 원하면 신청을 취소해 크루 선택으로 돌아간다.
**원본** 신규 — `fragment_invite_redeem.xml`의 가운데 상태 묶음과 `view_empty_state.xml`의 안내 구성을 재조립 · **변경** 옛 초대는 승인 없이 바로 소속됐다. 새 화면은 초대 코드 가입 뒤 PENDING 상태를 명확히 보여 주고 취소를 제공한다.
**진입** 1-8 초대 코드 입력에서 `POST /crews/join-requests` 201·200 · 앱 실행·복귀 때 `GET /users/me`의 `membership.status` PENDING · **이탈** 승인됨 → 1-10 위치 권한 안내 → 2-1 홈 · 신청 취소 → 1-6 크루 만들기/가입하기 · 뒤로 가기 → 앱 종료

## 배치

옛 초대 처리 화면의 가운데 정렬 상태 묶음(아이콘 → 제목 → 설명 → 보조 행동)을 따른다. 서버에서 받은 크루 이름을 큰 카드로 보이고, 아래에 크루장 승인 안내와 신청 취소 버튼을 둔다. 신청이 승인되거나 취소될 때까지 스크롤할 내용은 없다.

```
┌──────────────────────────────────────┐
│ ①             ⏳                       │
│       크루장 승인을 기다리고 있어요       │
│                                      │
│ ② ┌────────────────────────────────┐ │
│    │  한강줍깅크루                    │ │
│    │  가입 신청을 보냈어요             │ │
│    └────────────────────────────────┘ │
│                                      │
│ ③ 크루장이 승인하면 크루원이 돼요.      │
│    앱을 닫아도 신청은 그대로 남아요.     │
│                                      │
│ ④ [          신청 취소          ]      │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 상태 아이콘 | 모래시계 아이콘 | `Icon`(timer-sand) | — |
| ① | 큰 제목 | "크루장 승인을 기다리고 있어요" | `Txt` display | — |
| ② | 신청 크루 카드 | `crew.name` (`GET /crews/join-requests/mine`) · 부제 "가입 신청을 보냈어요" | `Card` + `Txt` title + `Txt` caption | — |
| ③ | 안내 문구 | "크루장이 승인하면 크루원이 돼요." / "앱을 닫아도 신청은 그대로 남아요." | `Banner` neutral | — |
| ④ | 신청 취소 버튼 | "신청 취소". 신청이 PENDING일 때만 보인다 | `Button` ghost lg | 확인 대화상자 → `DELETE /crews/join-requests/mine` → 1-6 |

`GET /crews/join-requests/mine`의 `data.status`가 PENDING이면 이 화면을 유지한다. APPROVED면 `GET /users/me` 재확인 뒤 MEMBER 분기로, REJECTED·CANCELED 또는 `data` null이면 신청이 없다는 상태로 1-6으로 간다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | ① 제목과 아이콘은 보이고 ② 카드 자리는 `Loading` "신청을 확인하고 있어요". ④는 숨김 | 없음 |
| 새로고침 | 앱 복귀·당겨서 새로고침 때 ② 카드 값은 남기고 상단에 작은 스피너. `GET /crews/join-requests/mine`을 다시 부른다 | ④는 평소처럼 |
| 빈 | `data`가 null이거나 status가 CANCELED·REJECTED. "가입 신청이 없어요." / "크루를 만들거나 초대 코드로 가입해 보세요." `EmptyState`와 [크루 선택하기] 버튼 | 크루 선택하기 → 1-6 |
| 오류 | 첫 조회가 4xx·5xx면 "신청을 불러오지 못했어요." / "네트워크 상태를 확인하고 다시 시도해 주세요." `ErrorState` | 다시 시도 → 재조회 |
| 오프라인 | 이전 PENDING 카드가 있으면 그대로 보이고 ③ 아래 `Banner` "인터넷 연결을 확인해 주세요.". 값이 없으면 오류 상태 | ④는 누르면 취소 요청이 실패할 수 있음을 아래 Snackbar로 알린다 |
| 권한 거부 | **해당 없음.** 위치·카메라·사진·알림 권한을 쓰지 않는다 | — |
| 부분 실패 | **해당 없음.** 신청 상태 조회 하나만 받는다 | — |
| 승인됨 | 재조회에서 `membership.status` MEMBER 또는 신청 status APPROVED. `Snackbar` "크루 가입이 승인됐어요." 뒤 1-10으로 전환 | 전환 전 모두 비활성 |
| 거절됨 | 재조회에서 status REJECTED. "가입 신청이 승인되지 않았어요." / "다른 크루의 초대 코드로 다시 신청할 수 있어요." `EmptyState` | 크루 선택하기 → 1-6 |
| 취소 중 | ④ 라벨 자리에 스피너. ①~④ 모두 비활성 | 없음 |

신청 취소 확인 대화상자: 제목 "가입 신청을 취소할까요?" · 본문 "한강줍깅크루에 다시 가입하려면 초대 코드를 입력해야 해요." · 버튼 [계속 기다리기] / [신청 취소]. 204면 `Snackbar` "가입 신청을 취소했어요." 뒤 1-6으로 간다. 4xx·5xx·오프라인이면 대화상자를 닫고 "신청을 취소하지 못했어요. 다시 시도해 주세요." `Snackbar`, PENDING 카드를 유지한다.

## 인터랙션

- 스크롤: 없음. 작은 화면에서는 ②~④만 세로 스크롤한다
- 당겨서 새로고침: 있음. PENDING 상태를 다시 확인한다
- 길게 누르기: 없음
- 시트: 없음
- 뒤로 가기: 신청을 유지한 채 앱을 종료한다. 1-8·1-6으로 돌아가지 않는다. 다시 열면 `membership.status` PENDING 분기로 이 화면에 온다
- 키보드: 없음
- 전환: 1-9→1-10은 신청 화면과 1-6·1-8을 스택에서 지운다. 취소·거절·신청 없음 → 1-6은 대체 전환이다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - ①: "가입 신청 대기 중"
  - ②: "한강줍깅크루, 가입 신청을 보냈어요"
  - ③: 안내 문구 전체
  - ④: "한강줍깅크루 가입 신청 취소"
  - 승인·거절·오류 상태 전환은 나타나는 즉시 읽는다(live region)
- 최소 터치 크기 예외: 없음. ④와 EmptyState의 주 버튼은 44dp 이상이다

## 옛 화면과의 차이

- 옛 초대 화면은 스피너 뒤 곧바로 소속되는 흐름이었다. 새 화면은 가입 신청 PENDING을 독립 화면으로 유지한다
- 옛 다시 시도·취소 텍스트 버튼은 상태 오류에만 있었고, 새 [신청 취소]는 사용자가 대기 자체를 끝내는 행동이다
- 초대 링크·모임 용어·즉시 참여 메시지를 없애고 초대 코드·크루장 승인·크루원 용어로 바꿨다
- 옛 화면에 없던 크루 이름 카드·승인 안내·거절 상태를 새로 넣었다

## 미결

- 가입 신청이 REJECTED가 되었을 때 크루장에게 거절 사유를 입력하게 할지, 신청자에게 보여 줄지 계약에 없다. 현재는 사유 없이 안내 문구만 보인다
- 앱이 열려 있을 때 승인 결과를 얼마나 빨리 받는지(앱 복귀·당겨서 새로고침만 / 푸시 알림 / 소켓)는 계약에 없다. 현재는 앱 복귀·새로고침과 `membership.status` 재확인으로 처리한다
- 신청 취소 확인 대화상자 문구는 새 문구다
