# 4-5 AI 분류 확인

**목적** 방금 찍은 사진에서 AI 가 찾은 쓰레기를 카테고리별 수량으로 보여 주고, 사용자가 고친 뒤 한 번에 줍기로 저장한다.
**원본** `../legacy/android-res/layout/fragment_ai_classify.xml` (후보 줄 `item_ai_candidate.xml`) · **변경** "후보 하나 고르기(라디오) + 직접 분류 칩" → 카테고리 7종 수량 조절(−/+). 사진 한 장에서 찾은 물체를 전부 담는다. 다시 촬영·이대로 담기 두 버튼과 사진·배너 자리는 그대로
**진입** 4-4 사진 촬영에서 `POST /media` 가 200 으로 끝난 직후 — `inference.status` 가 OK 든 UNAVAILABLE 이든 온다 · **이탈** 이대로 담기 성공 → 4-3 활동 중 · 다시 촬영 → 4-4 · 뒤로 가기 → 버림 확인 뒤 4-3

## 배치

옛 XML 의 세로 순서(헤더 → 사진 카드 → 배너 → "맞게 분류됐나요?" → 후보 목록 → "직접 분류" 칩 → 버튼 줄)를 따른다. 후보 목록과 직접 분류 칩이 하나로 합쳐져 카테고리 7종 격자(2줄, 4+3)가 됐고 칸마다 수량 조절이 붙었다. 헤더 아래가 세로 스크롤이고 버튼 줄은 스크롤 안 맨 아래에 있다(옛 화면과 같다). 사진이 세로로 길면 최대 520dp 까지만 차지한다.

## 인터랙션

- 스크롤: 세로. 헤더 아래 전체(사진·배너·격자·버튼 줄). 사진이 길거나 배너가 있을 때 버튼 줄이 아래로 밀리므로 스크롤한다
- 당겨서 새로고침: 없음
- 길게 누르기: 수량 조절의 − / + 를 길게 누르면 0.3초마다 1씩 이어서 바뀐다. 다른 길게 누르기는 없다
- 시트: 없음
- 뒤로 가기: 헤더 뒤로와 Android 뒤로 모두 `Dialog` "촬영 결과를 버릴까요?" / "담지 않은 촬영 결과는 저장되지 않아요." / [계속 분류] · [버리고 돌아가기]. 버리고 돌아가기 → 4-3(이 화면과 4-4 를 스택에서 지운다). 7칸이 모두 0 이고 AI 도 아무것도 안 찾았으면 묻지 않고 바로 4-3 으로. 저장 중에는 뒤로 가기를 무시한다
- 키보드: 없음. 수량은 − / + 로만 바꾼다(직접 입력 없음)
- 수량 조절: 누를 때마다 숫자가 살짝 커졌다 돌아온다. 0 → 1 이 되면 칸 테두리가 진해지고, 1 → 0 이면 옅어진다. AI 가 채운 값을 0 으로 내려도 "AI" 알약은 남는다(그 카테고리는 AI 가 찾았다는 뜻이고, 0 이면 요청에 넣지 않는다)
- 전환: 4-4 → 4-5 는 푸시. 저장 성공·버리기로 4-3 에 돌아갈 때는 4-4 · 4-5 를 함께 스택에서 지운다. 다시 촬영은 4-5 를 지우고 4-4 로 되돌아간다. 다이얼로그는 모달

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로 버튼: "뒤로"
  - 사진: "방금 촬영한 수거물"(배지 문구를 사진의 설명으로 쓴다). 배지 자체는 따로 읽지 않는다
  - 배너: 나타나는 순간 문구를 읽어 준다(live region). 앞의 이모지(🛠️ 🔍 🤔)는 읽지 않는다
  - 찾은 개수: "AI 가 3개 찾았어요"
  - 카테고리 칸: 칸 하나를 한 요소로 "플라스틱, 2개, AI 가 찾음" · AI 가 아니면 "담배꽁초, 0개". 아이콘은 읽지 않는다
  - − / +: "플라스틱 빼기" · "플라스틱 더하기". 비활성이면 비활성으로 읽힌다. 수량이 바뀌면 새 숫자를 읽어 준다(live region)
  - 이대로 담기: "이대로 담기, 3개". 저장 중엔 "저장 중" 으로 바뀌고 나머지가 비활성으로 읽힌다
  - 다이얼로그: 제목·본문을 읽고 두 버튼으로 포커스가 간다
- 최소 터치 크기 예외: 없음. − / + 는 각각 44dp. 칸이 좁아 아이콘·이름은 눌리지 않고 − / + 만 터치 영역이다

## 옛 화면과의 차이

- 후보 목록(`candidateList`, `item_ai_candidate` 라디오 줄) + "직접 분류" 칩(`etcRow`) → 카테고리 7종 격자 하나. 고르는 것이 아니라 수량을 맞춘다. 서버가 돌려준 박스 여러 개를 앱이 최고 신뢰도 하나만 남기던 것을 카테고리별 수량으로 전부 살린다
- 신뢰도 숫자("AI 신뢰도 N%")·막대(`bar`) → 없음. 배너 판정에만 쓴다
- 오프라인 배너(`failedBanner`, "📴 오프라인이라 AI 분석을 할 수 없어요…") → 없음. 업로드가 4-4 에서 끝나야 이 화면에 오므로 여기서 오프라인은 저장 단계에서만 만난다
- "🛠️ 지금은 AI 분석을 쓸 수 없어요" 와 "🔍 사진에서 쓰레기를 찾지 못했어요" 는 뒷문장만 "직접 분류를 고르면" → "직접 골라 담으면" 으로 바꿨다(직접 분류 절이 없어졌다). "🤔 확실하지 않아요" 의 뒷문장도 "아래에서 직접 골라 주세요" → "수량을 한 번 확인해 주세요"
- "이대로 담기" 에 합계 "· N개" 를 붙였다. 옛 버튼은 후보를 고르기 전까지 비활성이었고, 새 버튼은 합이 0 이면 비활성이다
- "다시 촬영"·사진 카드·배지·버림 확인 다이얼로그 문구(`ai_back_*`)는 그대로
- 성공 토스트 "%s 담았어요" 는 여러 카테고리를 "·" 로 이어 쓴다

## 미결

- 오프라인 대기열: `ItemInput.id`(앱 생성 uuid) 로 같은 항목 재전송은 200 으로 흡수되므로 대기열 재전송이 줍기를 두 번 쌓지 않는다. 대기열의 보존 기간(앱 종료·활동 종료 뒤)은 미정
- `ItemInput` 은 `bbox` 를 하나만 받는데 이 화면은 카테고리별로 박스 여러 개를 수량 하나로 묶는다. `bbox` 는 보내지 않기로 했다. 박스 위치가 필요하면(5-3 기록 상세의 사진 표시 등) 요청 모양을 바꿔야 한다
- `aiPredictedCategory` 는 "AI 가 A 라 했는데 사용자가 B 로 고침" 을 남기려는 필드다. 수량 조절 방식에서는 A 를 0 으로 내리고 B 를 1 올리는 것이 "고침" 인지 알 수 없어, AI 가 찾은 카테고리에 같은 값을 넣기만 한다. 정확도 측정에 이 필드를 쓰려면 방식을 다시 본다
- 불확실 배너의 기준 0.5 는 내가 정한 값이다. 서버 모델 기준(옛 앱의 unclassified 판정값)과 맞춰야 한다
- 수량 상한 99 는 내가 정한 값이다. 계약은 `quantity` 에 `minimum: 1` 만 있다
- 다시 촬영·버리기를 하면 이미 업로드된 사진(`photoId`)이 줍기 없이 서버에 남는다. 지우는 경로가 계약에 없다 — 남겨 두는지, `DELETE` 를 추가하는지
- 카테고리 아이콘은 MDI 글리프로 골랐다. 옛 앱은 이모지(🥤 등)를 썼고 그 대응표는 Kotlin 에 있어 `docs/legacy/` 에 없다. 4-6 빠른 줍기 시트와 같은 아이콘을 써야 한다
- 저장 성공 스낵바 "플라스틱 2 · 캔 1 담았어요" 는 4-3 에서 뜬다. 4-3 설계서와 문구를 맞춘다
