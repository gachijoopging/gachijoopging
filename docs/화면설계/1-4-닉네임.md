# 1-4 닉네임

**목적** 소셜 신규 가입자가 닉네임과 필수 동의를 완료한다. 프로필 사진은 5-8에서 나중에 정한다.
**원본** `../legacy/android-res/layout/fragment_nickname.xml` · **변경** 소셜 전용. 이메일 가입·사진·중복 검사 버튼을 제거했다.
**진입** 1-1 소셜 `isNew` true · 로그인/앱 재실행에서 소셜 온보딩 미완료 확인 · **이탈** 완료 후 소속 NONE → 1-6, PENDING → 1-9, MEMBER → 2-1.

## 배치

헤더 → 배지·제목·설명 → 닉네임 → 필수/선택 동의 → 다음 순서. 사진 영역은 없다. 장식 여백을 먼저 줄이고 작은 화면·큰 글씨·키보드에서는 본문 전체를 스크롤한다.

```
┌──────────────────────────────────────┐
│ ① 닉네임 설정                        │
│ ② [🌱 프로필 만들기]                 │
│    어떻게 불러 드릴까요?             │
│    닉네임은 피드와 크루에서 보여요.   │
│ ③ 닉네임 [2~12자]                    │
│    (필드 오류)                       │
│ ④ □ 필수 약관 동의       [내용 보기] │
│    □ 필수 개인정보 동의 [내용 보기] │
│    □ 선택 동의 항목     [내용 보기] │
│ ⑤ [다음]                             │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 헤더 | 닉네임 설정 | `Txt` title | — |
| ② | 배지·제목·설명 | 프로필 만들기 / 어떻게 불러 드릴까요? / 닉네임은 피드와 크루에서 보여요 | `Chip` deep + `Txt` | — |
| ③ | 닉네임·오류 | `nickname`, 줄바꿈 제거·앞뒤 공백 제거 뒤 2~12자. 별도 문자 제한 없음 | `Field` | 입력 |
| ④ | 동의·전문 보기 | 1-3과 동일한 필수/선택 구분. 기본 미선택, 실제 항목·전문·저장 계약 미결 | 기존 선택 컨트롤 + `Button` ghost | 전문 보기 후 값·선택 유지 |
| ⑤ | 다음 | 유효한 닉네임과 필수 동의 충족 시 활성, 선택 미동의 허용 | `Button` primary lg | `PATCH /users/me` (`nickname`), 동의 저장·완료 확인 후 소속 분기 |

중복은 저장 시 `409 NICKNAME_TAKEN`으로 확인한다. “이미 사용 중인 닉네임이에요. 다른 이름을 입력해 주세요.”를 ③ 아래에 표시한다. 2~12자 길이 오류도 ③ 아래, 식별 불가능한 422·요청 오류는 폼 배너로 표시한다. 실제 필수 동의 내용·저장이 준비되지 않은 상태를 완료로 보지 않는다.

## 인터랙션

- 스크롤: 장식부터 줄인 뒤 본문 전체 스크롤. 입력·동의·다음 버튼과 전문 전체를 보존한다.
- 당겨서 새로고침·시트: 없음. 길게 누르기는 OS 입력 메뉴만 제공한다.
- 뒤로 가기: 키보드를 먼저 닫고, 이후에는 앱을 벗어날 수 있다. 로그아웃이나 온보딩 완료로 처리하지 않는다. 재실행 때 완료 상태를 조회해 이 단계를 재개한다.
- 키보드: 한 줄, 자동 대문자 없음. 완료 키는 유효성 검사와 ⑤의 동일한 조건을 따른다. 비활성 버튼 자체는 클릭을 받지 않는다.
- 전환: 완료 시 이 화면을 스택에서 제거. `isNew` false여도 온보딩 미완료이면 소속 분기보다 이 단계가 우선한다.

## 접근성

- ③은 “닉네임, 2자에서 12자”, 오류와 연결하고 live region으로 안내한다.
- 필수/선택·선택 상태·전문 보기 대상을 읽는다. ⑤는 비활성/저장 중 상태를 읽는다.
- 터치 크기는 48dp 이상. 배지의 새싹은 장식이며 입력·전문 글씨 크기를 줄이지 않는다.

## 옛 화면과의 차이

- 이메일 가입은 1-3에서 끝낸다. 이 화면에는 닉네임만 입력하고 프로필 사진은 5-8로 미뤘다.
- 별도 중복 검사 없이 저장 시 확인한다. 필수·선택 동의를 분리하고 미완료 복귀 경로를 제공한다.

## 미결

- 1-3과 공유할 실제 약관·개인정보 전문·선택 항목·버전·동의 저장 계약이 필요하다.
- `GET /users/me`의 `profileComplete` false면 이 화면을 재개한다. true는 닉네임 설정 완료만 뜻하며 동의 완료로 추정하지 않는다. 동의 완료 조회·전이 계약은 별도로 필요하다.
