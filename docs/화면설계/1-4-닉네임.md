# 1-4 닉네임

**목적** 새로 가입한 사람이 크루원에게 보일 닉네임(과 원하면 사진)을 정한다.
**원본** `../legacy/android-res/layout/fragment_nickname.xml` · **변경** 배치는 그대로. 이메일 가입은 옛 앱과 달리 이 화면에서 가입 요청(`POST /auth/signup`)을 보낸다. "중복 검사" 버튼을 뺐다(중복은 저장할 때 서버가 알려 준다). 헤더의 단계 표시 "1 / 2" 를 뺐다(2단계였던 동네 설정이 사라졌다). 설명 문구의 "모임" 을 "크루" 로 바꿨다
**진입** 두 모드. **이메일 가입 모드** — 1-3 회원가입에서 `email`·`password` 를 들고 온다(1-3 은 서버를 부르지 않았다) · **소셜 첫 가입 모드** — 1-1 시작에서 `POST /auth/kakao` · `/auth/google` 응답 `isNew` 가 true 일 때(토큰은 이미 저장됨) · **이탈** 저장 성공 → 1-6 크루 만들기/가입하기(새 가입자는 소속 크루가 없다) · 이메일 모드에서 이메일 중복이면 1-3 으로 되돌아간다 · 이메일 모드 뒤로 가기 → 1-3

화면은 두 모드가 같다. 다른 것은 ⑤ 완료가 보내는 요청과 뒤로 가기뿐이다.

## 배치

옛 XML 의 순서(헤더 → 배지 → 큰 제목 → 설명 → 사진 자리 → 닉네임 라벨 → 입력창 → 오류 문구 → 다음 버튼)를 그대로 따른다. 입력창 오른쪽에 붙어 있던 "중복 검사" 버튼만 빠져 입력창이 가로를 다 쓴다. 헤더 아래가 세로 스크롤 영역이고, 키보드가 올라오면 다음 버튼까지 보이도록 밀려 올라간다.

```
┌──────────────────────────────────────┐
│ ① ‹  프로필 설정                        │  ← ‹ 는 이메일 모드만
├──────────────────────────────────────┤
│ ② [🌱 프로필 만들기]                    │
│    어떻게 불러 드릴까요?                  │
│    닉네임과 사진은 피드와 크루에서          │
│    다른 크루원에게 보여요.                 │
│                                      │
│ ③          ╭ ─ ─ ─ ╮                 │
│            ┆ 프로필 사진 ┆                │
│            ┆   자리   ┆                │
│            ╰ ─ ─ ─ ╯                 │
│             사진 선택                   │
│                                      │
│ ④ 닉네임                               │
│    ┌──────────────────────────────┐   │
│    │ 2~12자                        │   │

```

|---|---|---|---|
| 비어 있음 | 입력창을 떠났을 때(포커스 아웃) 또는 비활성인 다음 버튼 자리를 눌렀을 때 | "닉네임을 입력해 주세요." | 비활성 |

| 2~12자 | — | 없음. 오류 문구가 떠 있었으면 글자를 고치는 순간 지운다 | 활성 |
| 13자 이상 | **생기지 않는다.** 입력창이 12자에서 더 받지 않는다 | — | — |

## 인터랙션

- 스크롤: 헤더 아래가 세로 스크롤. 키보드가 올라오면 ⑤ 다음 버튼이 키보드 위로 보이도록 밀린다. 키보드가 없으면 한 화면에 다 들어간다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: 없음. 사진 고르기는 OS 사진 선택기(앱 안 시트가 아니다)
- 뒤로 가기: **이메일 모드** — 헤더 뒤로 버튼과 시스템 뒤로 가기 모두 1-3 으로 돌아간다. 아직 서버에 아무것도 보내지 않았고 1-3 의 이메일·비밀번호 값은 그대로 남아 있다. 여기서 입력한 닉네임·고른 사진은 버린다. **소셜 모드** — 뒤로 버튼이 없다. 계정은 이미 만들어졌고 닉네임은 크루원에게 보이는 이름이라 건너뛸 수 없다 — 시스템 뒤로 가기는 무시한다(1-1 은 스택에서 이미 지워져 있다). 두 모드 모두 저장 중에는 무시
- 키보드: 진입 즉시 ④ 에 포커스. 키보드의 완료(Done) 키는 ⑤ 와 같다 — 2~12자면 저장, 아니면 검증 문구를 띄운다. 입력창 밖을 누르면 키보드가 내려간다
- 사진 자리 탭: OS 사진 선택기가 열리고 한 장을 고른다. 고르면 원 안이 사진으로 바뀌고 라벨이 "사진 바꾸기" 가 된다. 선택기에서 취소하면 그대로다. 사진은 저장(⑤) 때 함께 올린다 — 고르는 순간 올리지 않는다
- 전환: 1-3 → 1-4 는 푸시. 1-6 으로 갈 때는 이 화면과(이메일 모드면) 1-3·1-1 까지 스택에서 지운다 — 1-6 에서 뒤로 가기로 가입 화면에 돌아오지 않는다. 이메일 409 로 1-3 에 돌아가는 것은 팝. 오류 문구는 나타날 때만 짧게 페이드

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - ① 뒤로 버튼(이메일 모드): "뒤로" · 헤더 제목: "프로필 설정"
  - ② 배지: "프로필 만들기"(🌱 는 읽지 않는다) · 큰 제목·설명: 본문 그대로
  - ③ 사진 자리 + 라벨: 하나로 묶어 "프로필 사진 선택, 선택 안 함" / 골랐으면 "프로필 사진, 바꾸기". "프로필 사진 자리" 안내 글자는 따로 읽지 않는다
  - ④ 입력창: 라벨 "닉네임", 힌트 "2자에서 12자". 오류 문구는 나타나는 순간 읽어 주고(live region) 입력창과 연결한다
  - ⑤ 다음: "다음". 비활성이면 비활성으로 읽힌다. 저장 중이면 "저장 중"
  - `Snackbar`: 나타나는 순간 문구를 읽어 준다
- 최소 터치 크기 예외: 없음. ③ 은 86dp 원과 라벨을 합쳐 한 터치 영역. ④ 입력창·⑤ 버튼은 44dp 이상

## 옛 화면과의 차이

- 옛 앱은 1-3 에서 계정을 만든 뒤 여기서 프로필만 고쳤다 → 새 계약 `POST /auth/signup` 이 `nickname` 을 필수로 받아, 이메일 가입은 이 화면의 "다음" 이 가입 요청을 보낸다. 그래서 이메일 중복 오류가 이 화면에서 나와 1-3 으로 되돌린다
- "중복 검사" 버튼(`checkButton`)과 성공 문구 "사용할 수 있는 닉네임이에요." → 없음. 중복은 `POST /auth/signup` · `PATCH /users/me` 의 409 로만 알게 되고 같은 자리에 "이미 사용 중인 닉네임이에요…" 가 뜬다
- 헤더 부제 "1 / 2"(`nick_step`) → 없음. 2단계였던 동네 설정(`fragment_hood`)이 사라졌다. 헤더 뒤로 버튼(`backButton`)은 이메일 모드에만 남기고 소셜 모드에서 숨겼다
- 설명 "닉네임과 사진은 피드와 모임에서 다른 사람에게 보여요." → "닉네임과 사진은 피드와 크루에서 다른 크루원에게 보여요."
- 금칙어 문구 "사용할 수 없는 단어가 포함돼 있어요…"(`nick_banned`) → 쓰지 않는다. 계약에 해당 오류 코드가 없다(미결)
- 배지·큰 제목·사진 자리·"사진 선택"·라벨·플레이스홀더 "2~12자"·"다음"·"닉네임을 입력해 주세요."·"이미 사용 중인 닉네임이에요…" 문구는 그대로
- "닉네임은 2자 이상이어야 해요." · "닉네임은 2~12자로 입력해 주세요." · `Snackbar` 문구 3개 · "사진 바꾸기" · "사진 지우기" 는 새로 정했다
- 저장 중 표시(버튼 스피너·전부 비활성)는 새로 정했다 — 옛 XML 에는 없다

## 미결

- 소셜 모드에서 `SocialToken` 의 `nickname`("첫 가입일 때만") 은 쓰지 않는다. `isNew` 응답을 받은 뒤 `PATCH /users/me` 로 보내기로 했으므로 계약의 그 필드는 남는 자리다
- 소셜 첫 가입 직후(`isNew` true) 서버가 넣어 두는 초기 닉네임이 무엇인지(카카오·구글 프로필 이름? 빈 값?) — 있다면 입력창에 미리 채워 줄 수 있다
- **닉네임 사용 가능 확인 API 가 없다.** 중복은 `POST /auth/signup` · `PATCH /users/me` 를 보내야만 409 로 안다. 옛 화면의 "중복 검사" 를 살리려면 확인 경로가 계약에 추가돼야 한다
- 닉네임 허용 문자. 계약은 길이 2~12 만 정한다. 공백·이모지·특수문자 허용 여부, 앞뒤 공백 처리(이 문서는 "지우고 센다" 로 썼다)를 정해야 한다
- 금칙어(`nick_banned`)를 서버가 걸러 주는지. 걸러 준다면 `Error` 의 `code` 에 별도 값이 없어 422 VALIDATION 과 구분할 수 없다
- `PATCH /users/me` 의 `nickname` 에 `minLength`·`maxLength` 가 없다(`/auth/signup` 에는 2·12 가 있다). 계약 머리말의 "닉네임 2~12자" 를 근거로 썼다
- 사진 자리를 이 화면에 남길지. 5-8 프로필 수정에서도 올릴 수 있으니 온보딩에서는 닉네임만 받고 사진을 빼면 `POST /media` 단계와 부분 실패 상태가 함께 사라진다
- 소셜 모드의 뒤로 가기 무시가 맞는지. 대안은 뒤로 가기 = 로그아웃(`POST /auth/logout` 뒤 1-1) 인데, 새 가입자가 이름 없이 계정만 남기는 길이 된다
- 이메일 모드에서 `POST /auth/signup` 422 는 닉네임 칸으로 돌렸다. 서버가 비밀번호 규칙(최대 길이 등)으로 422 를 내면 잘못된 칸에 뜬다 — 1-3 미결과 같은 항목
