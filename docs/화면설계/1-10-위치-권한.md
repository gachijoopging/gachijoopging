# 1-10 위치 권한 안내

**목적** 크루에 소속된 사람이 홈에 들어가기 전에 OS 위치 권한을 받는다. 활동의 경로·거리 기록과 크루원에게 보이는 위치 공유가 모두 이 권한 위에서 돈다.
**원본** `../legacy/android-res/layout/fragment_location_gate.xml` · **변경** 배치·버튼 두 개·"권한 창이 더 이상 뜨지 않아요" 문구는 그대로. 설명에서 "우리 동네"·"내 주변" 을 빼고 활동·크루원 기준으로 다시 썼다. 대략적 위치만 허용한 경우를 새로 다룬다
**진입** 로그인(1-1 소셜 · 1-2 이메일) 뒤 `membership.status` 가 MEMBER 인데 위치 권한이 없을 때 · 크루 만들기(1-7) 완료 뒤 · 승인 대기(1-9)에서 승인이 확인된 뒤 · 앱 실행(자동 로그인) 때 MEMBER 인데 권한이 없을 때 · 활동 시작 시트(4-2)를 열려는데 권한이 빠져 있을 때(OS 설정에서 끈 경우) · **이탈** 권한이 "앱 사용 중에만 허용"(정확한 위치)으로 확인되면 홈(2-1). 4-2 에서 왔으면 원래 화면(4-1 줍깅 탭)으로 돌아간다. "나중에" 경로는 없다(옛 화면과 같다)

권한이 **이미 허용돼 있으면 이 화면을 띄우지 않고** 바로 2-1 로 간다(1-1 · 1-2 미결의 답). 이 화면은 서버를 부르지 않는다 — 보는 것은 OS 권한 상태 하나다.

## 배치

옛 XML 의 세로 순서(제목 → 설명 → 허용 버튼 → 설정 버튼)를 그대로 따른다. 전부 세로 가운데 정렬로 화면 한가운데 모여 있고 좌우 여백 20dp. 두 버튼은 옛 XML 처럼 둘 다 평소 숨김이며 권한 상태에 따라 **둘 중 하나만** 나타난다. 안내 배너 ③ 은 옛 XML 에 뷰가 없던 `location_gate_blocked` 문구의 자리로, 설명과 버튼 사이에 넣었다. 헤더·뒤로 버튼 없음. 한 화면에 다 들어가며 스크롤하지 않는다.

## 인터랙션

- 스크롤: 없음. 한 화면에 다 들어간다. 위아래 남는 높이는 가운데 정렬이 흡수한다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: 없음. OS 권한 창과 OS 설정은 앱 안 시트가 아니라 OS 가 띄운다
- 뒤로 가기: 로그인·온보딩에서 왔을 때는 이 화면이 스택의 뿌리라 앱을 벗어난다(Android 기본). 1-1 · 1-2 · 1-6 ~ 1-9 는 이미 스택에서 지워져 있어 되돌아가지 않는다. 4-2 에서 왔을 때는 원래 화면(4-1)으로 돌아가고 4-2 는 열지 않는다. OS 권한 창이 떠 있을 때 뒤로 가기는 OS 가 "거부" 로 처리한다
- 앱 복귀: OS 설정에서 돌아오거나 화면을 켜서 앱이 앞으로 올 때마다 권한을 다시 읽는다. 허용으로 바뀌어 있으면 아무것도 누르지 않아도 2-1(또는 원래 화면)로 넘어간다
- 키보드: 없음
- 전환: 2-1 로 갈 때는 이 화면을 스택에서 지운다 — 홈에서 뒤로 가기로 이 화면에 되돌아오지 않는다. 4-2 에서 왔을 때는 모달로 덮고 끝나면 닫는다. ③ 배너와 ④↔⑤ 교체는 나타날 때만 짧게 페이드

  - ② 설명: 본문 그대로 읽는다. 문구가 바뀌면(대략적 위치만 · 4-2 진입) 바뀐 문구를 읽어 준다(live region)

## 옛 화면과의 차이

- 설명 "가치줍깅은 내 주변 활동과 우리 동네를 기준으로 동작해서, 위치 권한 없이는 사용할 수 없어요." → "활동 중 걸은 경로와 거리를 기록하고, 위치 공유를 켰을 때 크루원에게 내 위치를 보여 주는 데 위치를 써요.\n위치 권한 없이는 활동을 시작할 수 없어요." 동네·내 주변 개념을 끄고, 위치를 쓰는 곳(경로 기록·위치 공유)을 그대로 밝혔다
- 제목 "위치 권한이 필요해요"·"위치 권한 허용"·"설정으로 이동"·"권한 창이 더 이상 뜨지 않아요. 설정에서 켜 주세요." 는 그대로. 마지막 문구는 옛 XML 에 뷰가 없어 ③ 배너 자리를 새로 잡았다
- 옛 앱은 동네 선택 뒤에 이 화면을 거쳤다 → 소속 확정(MEMBER) 뒤에 거친다. 이미 허용돼 있으면 건너뛰는 규칙, 4-2 직전 재진입, 앱 복귀 때 자동 재확인은 새로 정했다
- 대략적 위치만 허용한 경우의 문구와 다시 묻기는 새로 정했다 — 옛 XML·strings 에 없다
- 하드 게이트("나중에" 없음)는 옛 화면과 같다

## 미결

- 게이트가 여전히 하드인지. 옛 화면은 위치 없이 앱을 쓸 수 없었고 이 설계도 그대로 두었지만, 새 앱에서 위치가 필요한 것은 활동(4-2 이후)뿐이라 홈·피드·모이깅은 권한 없이도 돌 수 있다. "나중에" 를 두고 4-2 직전에만 막는 소프트 게이트로 바꿀지 결정이 필요하다. 소프트로 가면 진입이 4-2 직전 하나로 줄고 1-1 · 1-2 · 1-4 · 1-7 · 1-9 의 "1-10 을 거쳐 2-1" 을 전부 고쳐야 한다
- 백그라운드 위치("항상 허용")를 묻지 않는 것은 내가 정했다. 활동 중 추적이 포그라운드 서비스로만 도는 것을 전제로 한다. 화면을 끈 뒤에도 위치가 끊기지 않는지 기기에서 확인해야 하고, 끊기면 4-2 에서 "항상 허용" 을 추가로 묻는 화면이 필요하다
- 알림 권한을 4-2 에서 묻는 것으로 적었다. 4-2 설계에서 받아 줘야 한다
- 새 설명 문구 두 종류와 4-2 진입 첫 문장, 설정 열기 실패 `Snackbar` 문구는 내가 정한 안이다. 확정이 필요하다
- "이번만 허용" 을 고른 사람이 실행마다 이 화면을 보는 것을 그대로 둘지, 두 번째부터는 문구를 바꿔 알려 줄지
- 4-2 에서 왔을 때 원래 화면이 4-1 줍깅 탭이라고 적었다. 4-2 활동 시작 시트를 어디서 여는지(4-1 인지 다른 곳도 있는지)는 4-2 설계와 맞춰야 한다
