# 5-8 프로필 수정

**목적** 크루원에게 보이는 사진·닉네임·소개를 고친다.
**원본** `../legacy/android-res/layout/fragment_edit_profile.xml` · **변경** "중복 검사" 버튼을 뺐다(중복은 저장할 때 서버가 알려 준다). 소개 입력창이 새로 생겼다. 사진 변경이 즉시 선택기로 가던 것 → 카메라/앨범/삭제 시트로 바뀌었다. 저장 버튼은 바뀐 게 있고 닉네임이 유효할 때만 눌린다
**진입** 5-5 내 정보의 아바타 · 소개 · [프로필 수정] · 5-7 설정의 "프로필 수정" 행 · **이탈** 저장 성공 → 5-5 (pop) · 뒤로 가기(바뀐 게 없으면 바로, 있으면 확인 대화상자 뒤) → 5-5

## 배치

옛 XML 의 세로 순서(헤더 → 사진 자리 → 닉네임 라벨 → 입력창[+중복 검사] → 오류 문구 → 저장 버튼)를 그대로 따른다. 중복 검사 버튼만 빠져 입력창이 가로를 다 쓰고, 닉네임 오류 문구와 저장 버튼 사이에 소개 라벨·입력창·오류 문구 묶음이 새로 들어간다. 헤더만 고정, 그 아래가 세로 스크롤이며 키보드가 올라오면 저장 버튼까지 보이도록 밀려 올라간다.

```
┌──────────────────────────────────────┐
│ ① ‹  프로필 수정                        │
├──────────────────────────────────────┤
│ ②          ╭ ─ ─ ╮                   │
│            ┆ 얼굴 ┆                    │
│            ╰ ─ ─ ╯                   │
│            사진 변경                    │
│                                      │
│ ③ 닉네임                        8/12   │
│    ┌──────────────────────────────┐   │
│    │ 관열                           │   │
│    └──────────────────────────────┘   │
│    이미 사용 중인 닉네임이에요. …          │  ← 평소 숨김
│                                      │
│ ④ 소개                        12/200  │
│    ┌──────────────────────────────┐   │
│    │ 한강 서쪽 담당                    │   │
│    │                                │   │
│    └──────────────────────────────┘   │
│                                      │
│ ⑤ [            저장             ]     │
└──────────────────────────────────────┘
```

② 를 누르면 뜨는 사진 변경 시트.

```
┌──────────────────────────────────────┐
│              프로필 사진 변경             │
│  📷  카메라로 촬영                       │
│  🖼  앨범에서 선택                       │
│  🗑  사진 삭제                          │  ← 사진 자리에 사진이 있을 때만
└──────────────────────────────────────┘
```

| 1 | ② 를 누르면 시트가 뜬다. 사진 자리에 지금 보이는 사진(원래 사진이든 방금 고른 사진이든)이 있으면 "사진 삭제" 도 함께 보인다 | — |
| 2 | "카메라로 촬영" → OS 카메라 | 촬영하면 사진 자리를 그 사진으로 바꾼다(dirty). 취소하면 그대로 |
| 2 | "앨범에서 선택" → 게시물 작성과 같은 Android 시스템 포토 피커(1장) | 고르면 위와 같다. 취소하면 그대로 |
| 2 | "사진 삭제" | 사진 자리를 `nickname` 첫 글자로 되돌린다(dirty). 원래 사진이 없었다면 이 항목 자체가 안 보이므로 일어나지 않는다 |

닉네임 검증(1-4 닉네임과 같다). 앞뒤 공백을 지우고 줄바꿈을 제거한 뒤 2~12자를 센다. 내부 공백과 다른 문자를 임의 제한하지 않으며 비밀번호에는 이 정규화를 적용하지 않는다.

| 조건 | 언제 보이나 | 오류 문구 | 저장 버튼 |
|---|---|---|---|
| 비어 있음 | 입력창을 떠났을 때(포커스 아웃) | "닉네임을 입력해 주세요." | 비활성 |
| 1자 | 입력창을 떠났을 때 | "닉네임은 2자 이상이어야 해요." | 비활성 |
| 2~12자 | — | 없음. 떠 있었으면 글자를 고치는 순간 지운다 | dirty 하면 활성 |
| 13자 이상 | **생기지 않는다.** 입력창이 12자에서 더 받지 않는다 | — | — |

저장. 바뀐 항목만 서버로 보낸다 — 닉네임을 안 건드렸으면 `nickname` 자체를 보내지 않으므로 내 원래 닉네임이 중복으로 걸리는 일이 없다.

| 순서 | 하는 것 | 결과 | 다음 |
|---|---|---|---|
| 1 | 저장을 누르면, 새 사진을 골랐을 때만 먼저 `POST /media` (`purpose` PROFILE) | 200 | 받은 `mediaId` 를 들고 2 로 |
| 1 | 같은 요청(새 사진을 골랐을 때만) | 4xx/5xx/오프라인 | `PATCH /users/me` 는 보내지 않는다. `Snackbar` "사진을 올리지 못했어요. 다시 시도해 주세요." 고른 사진·입력값은 남기고 저장 버튼을 다시 활성으로 되돌린다 |
| 2 | 바뀐 필드만 담아 `PATCH /users/me` — `nickname`(바뀌었으면) · `intro`(바뀌었으면) · `photoMediaId`(새 사진이면 1 의 `mediaId`, 삭제했으면 null) | 200 | 5-5 로 돌아가고(pop) `Snackbar` "프로필을 저장했어요." |
| 2 | 같은 요청 | 409 `NICKNAME_TAKEN` | 닉네임 입력창 아래 "이미 사용 중인 닉네임이에요. 다른 이름을 입력해 주세요." 사진은 1 에서 받은 `mediaId` 를 그대로 들고 있는다(다시 올리지 않는다) |
| 2 | 같은 요청 | 422 `VALIDATION` | 오류 필드에 맞춰 닉네임 또는 소개 입력창 아래 설명 표시 |
| 2 | 같은 요청 | 그 외 4xx/5xx/오프라인 | `Snackbar` "저장하지 못했어요. 다시 시도해 주세요." 받아 둔 `mediaId` 는 남겨 다시 누를 때 재사용한다(사진을 다시 올리지 않는다) |

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | ① 은 바로 보인다. ② 사진 자리는 빈 원, ③④ 는 회색 자리(스켈레톤), ⑤ 는 비활성 | 뒤로 가기(아직 dirty 가 아니라 확인 없이 바로 나간다) |
| 새로고침 | **해당 없음.** 당겨서 새로고침이 없는 입력 화면이다 | — |
| 빈 | **해당 없음.** 입력 화면이라 값이 없는 것은 상태가 아니다 — `intro` 가 빈 문자열이면 플레이스홀더가 보일 뿐이다 | 평소와 같다 |
| 오류 | `GET /users/me` 가 인증 외 4xx/5xx 면 ②③④ 자리를 `ErrorState` ("불러오지 못했어요" / "연결 상태를 확인하고 다시 시도해 주세요." / [다시 시도]) 하나로 덮는다. ① 은 그대로 | 다시 시도 → 재요청 · 뒤로 가기 |
| 오프라인 | 첫 진입에 값이 없으면 오류와 같다. 이미 값을 받아 폼을 보여 준 뒤 오프라인이 되면 화면은 평소와 같고, 저장을 누르면 저장 흐름의 오프라인 결과(`Snackbar` 실패 문구)로 끝난다. 카메라·앨범은 기기 기능이라 오프라인이어도 된다 | 전부. 저장은 실패로 끝난다 |
| 권한 거부 | 카메라 거부는 사진 없이 닉네임·소개 저장 가능. 재요청 가능한 경우만 다시 요청, 영구 거부는 OS 설정 안내. 시스템 사진 선택기는 전체 앨범 권한을 요구하지 않으며 취소 시 기존 사진 유지 | 사진 선택·텍스트 수정 가능 |
| 부분 실패 | 새 사진을 골랐는데 `POST /media` 가 실패한 경우와, `POST /media` 는 됐는데 `PATCH /users/me` 가 실패한 경우 — 위 "저장" 흐름 표 참고. 두 경우 모두 화면에 남아 다시 저장을 누를 수 있다 | 전부. 사진 자리를 다시 눌러 사진을 바꾸거나 지울 수 있다 |
| 저장 중 | ⑤ 라벨 자리에 스피너. 새 사진이 있으면 `POST /media` → `PATCH /users/me`, 없으면 `PATCH /users/me` 만 끝날 때까지 | 아무것도 눌리지 않는다(①②③④⑤ 모두 비활성). 뒤로 가기도 무시 |

## 인터랙션

- 스크롤: 헤더 아래가 세로 스크롤(옛 `ScrollView` 그대로). 키보드가 올라오면 ⑤ 저장 버튼이 키보드 위로 보이도록 밀린다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: ② 를 누르면 "프로필 사진 변경" 시트(카메라로 촬영/앨범에서 선택/사진 삭제). 스크림을 누르거나 뒤로 가기로 닫힌다
- 뒤로 가기: dirty 가 아니면 바로 5-5 로 돌아간다(pop). dirty 면 확인 대화상자 "나갈까요?" / "저장하지 않은 변경사항이 사라져요." [취소] · [나가기](위험) — [나가기] 를 고르면 바뀐 내용을 버리고 5-5 로 돌아간다. 저장 중에는 무시
- 키보드: 자동 포커스 없음. 입력창을 탭하면 키보드가 올라오고, 키보드의 완료(Done) 키는 키보드만 내린다(저장은 ⑤ 를 따로 눌러야 한다). 입력창 밖을 누르면 키보드가 내려간다
- 전환: 5-5 → 5-8 은 푸시. 저장 성공은 pop. 사진 변경 시트·나갈까요 대화상자는 모두 모달. 카메라·사진 선택기는 OS 화면

## 접근성

- 모든 내용과 동작을 유지한다. 작은 화면·큰 글자에서는 장식과 미리보기 높이를 먼저 줄이고 본문을 스크롤하며, 글자와 48dp 터치 영역은 줄이지 않는다.

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로"
  - 사진 자리 + 라벨: 하나로 묶어 "프로필 사진, 사진 변경"
  - 닉네임 입력창: 라벨 "닉네임", 힌트 "2자에서 12자". 글자 수는 "8자, 12자 중" 으로 읽는다. 오류 문구는 나타나는 순간 읽어 준다(live region)
  - 소개 입력창: 라벨 "소개", 힌트 "최대 200자". 글자 수는 "12자, 200자 중" 으로 읽는다
  - 저장: "저장". 비활성이면 비활성으로 읽힌다. 저장 중이면 "저장 중"
  - 사진 변경 시트: 뜨는 순간 제목을 읽어 주고, 각 항목은 "카메라로 촬영" · "앨범에서 선택" · "사진 삭제" 그대로
  - `Snackbar`·나갈까요 대화상자: 뜨는 순간 문구를 읽어 준다(live region)
- 최소 터치 크기 예외: 없음. 사진 자리는 86dp(1-4 와 같다). 입력창·저장 버튼은 48dp 이상. 시트 항목은 48dp 이상

## 옛 화면과의 차이

- "중복 검사" 버튼(`checkButton`, `action_check_dup`) → 없음. 중복은 `PATCH /users/me` 의 409 로만 안다(1-4 닉네임과 같은 선택)
- 저장 버튼이 항상 눌리는 방식(빈 채로 눌러도 저장이 되고, 바뀐 게 없으면 토스트 "변경된 내용이 없어요."(`ep_no_change`)) → dirty·유효성 조건으로 저장 버튼 자체를 비활성화한다. 토스트 문구는 쓰지 않는다
- 사진 변경(`ep_change_photo` "✏️ 사진 변경")이 눌렀을 때 바로 선택기로 가던 것 → 카메라로 촬영/앨범에서 선택/사진 삭제 세 선택지를 가진 시트로 바뀌었다. 이미 있는 사진을 지울 방법이 옛 화면에는 없었다
- 소개(`intro`) 입력창은 신규. 옛 화면엔 사진·닉네임뿐이었다 — 5-5 내 정보의 소개 자리를 탭하면 이 화면으로 오게 되면서 편집 대상이 됐다
- 닉네임·소개 글자 수 표시("8/12", "12/200")는 신규
- 헤더 제목 "프로필 수정"으로 통일. 부제 "내 정보"(`ep_sub`)는 다른 화면과 통일하기 위해 헤더에 넣지 않았다
- 쓰이지 않던 문자열 `ep_photo_title`("프로필 사진 변경")·`ep_photo_desc`("사진을 선택하면 원형 프로필에 맞춰 미리 보여 드려요.")·`ep_photo_cta`("사진 적용")는 옛 레이아웃 어디에서도 실제로 쓰이지 않았다 — 만들다 만 사진 미리보기·자르기 단계로 보이며, 이 화면은 사진은 가입 뒤 이 화면에서 즉시 미리보기 후 저장 때 함께 업로드하는 방식을 그대로 쓴다

## 미결

- 구현 검증: `PATCH /users/me`의 닉네임 2~12자·앞뒤 공백/줄바꿈 정규화·저장 시 중복 검사와 필드별 오류를 클라이언트와 서버에서 맞춘다.
- 제작/구현: 시스템 사진 선택과 원형 미리보기를 사용하며 별도 자르기 단계는 두지 않는다. 선택 파일은 업로드 실패 후에도 재시도할 수 있게 유지한다.
