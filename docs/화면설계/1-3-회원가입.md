# 1-3 회원가입

**목적** 이메일과 비밀번호를 받아 새 계정의 절반을 채우고, 닉네임(1-4)으로 넘긴다.
**원본** `../legacy/android-res/layout/fragment_signup.xml` · **변경** 배치·문구·검증은 그대로. 옛 앱은 이 화면에서 바로 가입 요청을 보냈지만, 새 계약 `POST /auth/signup` 이 `nickname` 을 필수로 받아 요청은 1-4 에서 한 번에 보낸다 — 이 화면은 서버를 부르지 않는다
**진입** 시작(1-1) "처음이신가요?" · 로그인(1-2) "회원가입" 링크 · 닉네임(1-4)에서 이메일 중복(409)으로 되돌아올 때 · **이탈** 닉네임(1-4) · "이미 계정이 있어요" → 로그인(1-2) · 뒤로 가기 → 온 화면

## 배치

옛 XML 의 세로 순서(헤더 → 워드마크·헤드라인·설명 → 이메일 라벨·입력·오류 → 비밀번호 라벨·입력(보기 토글)·오류 → 회원가입 버튼 → 로그인 링크)를 그대로 따른다. 헤더는 고정이고 그 아래가 통째로 스크롤이다. 세로가 넉넉하면 스크롤 없이 다 들어가고, 키보드가 올라오면 스크롤해서 버튼까지 닿는다.

```
┌──────────────────────────────────────┐
│ ① ←  회원가입                          │
│      새 계정                          │
├──────────────────────────────────────┤
│ ②          가치줍깅(워드마크)            │
│      가치줍깅에 오신 걸 환영해요           │
│      이메일과 비밀번호만 있으면            │
│      바로 줍깅을 시작할 수 있어요.          │
│                                      │
│ ③ 이메일                               │
│   ┌──────────────────────────────┐    │
│   │ you@example.com              │    │
│   └──────────────────────────────┘    │
│   이메일 형식이 올바르지 않아요. @와…      │  ← 평소 숨김
│                                      │
│ ④ 비밀번호                              │
│   ┌──────────────────────────┬───┐    │
│   │ 8자 이상                  │보기│    │
│   └──────────────────────────┴───┘    │

│                                      │
│ ⑤ [          회원가입          ]        │
│                                      │
│ ⑥          이미 계정이 있어요            │
└──────────────────────────────────────┘
```

| 칸 | 규칙 | 언제 검사 | 오류 문구 |
|---|---|---|---|
| ③ 이메일 | 비어 있지 않고 `@` 와 그 뒤에 `.` 이 있는 도메인 (`email` format) | 포커스가 떠날 때, 그리고 ⑤ 를 누를 때 | "이메일 형식이 올바르지 않아요. @와 도메인을 확인해 주세요." |
| ④ 비밀번호 | 8자 이상 (`password` minLength 8) | 포커스가 떠날 때, 그리고 ⑤ 를 누를 때 | "비밀번호는 8자 이상이어야 해요." |

⑤ 는 두 칸이 모두 채워지고 규칙을 통과한 순간 활성화된다. 오류 문구가 떠 있는 칸은 값이 바뀌기 시작하면 문구를 숨긴다.

## 인터랙션

- 스크롤: ① 헤더는 고정, ②~⑥ 이 세로 스크롤. 세로가 넉넉하면 스크롤이 생기지 않는다. 스크롤바는 그리지 않는다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음(입력창의 기본 붙여넣기 메뉴만)
- 시트: 없음
- 뒤로 가기: 온 화면(1-1 또는 1-2)으로 돌아간다. 입력한 값은 버린다 — 확인 대화 상자 없음
- 키보드: ③ 은 이메일 키보드, 자동 대문자·자동 수정 없음, 자동 완성 힌트는 이메일 주소. ④ 는 가림 처리 키보드, 자동 완성 힌트는 새 비밀번호(로그인의 저장된 비밀번호를 제안하지 않는다). ③ 의 완료 키는 "다음" 으로 ④ 에 포커스를 옮기고, ④ 의 완료 키는 "완료" 로 ⑤ 와 같다(검증 통과면 1-4 로). 키보드가 올라오면 내용이 밀려 올라가 ⑤ 가 가려지지 않는다. 입력창 밖을 탭하면 키보드가 내려간다
- 보기 토글: 탭마다 ④ 의 가림을 켜고 끄고 라벨을 "보기" ↔ "숨기기" 로 바꾼다. 커서 위치는 유지된다
- 전환: 1-4 는 푸시(뒤로 가기로 이 화면에 돌아온다). ⑥ → 1-2 는 이 화면을 1-2 로 **바꿔 넣는다**(1-1 → 1-3 → 1-2 → 1-3 … 이 쌓이지 않게). 1-2 의 "회원가입" 도 같은 규칙이다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - ① 뒤로: "뒤로"
  - ② 워드마크: "가치줍깅". 헤드라인·설명은 본문 그대로
  - ③: 라벨 "이메일" 이 입력창에 묶인다. 오류가 뜨면 입력창의 오류로 함께 읽힌다("이메일, 오류, 이메일 형식이 올바르지 않아요…")
  - ④: 라벨 "비밀번호", 가림 입력으로 읽힌다. 보기 토글은 "비밀번호 보기" / "비밀번호 숨기기" 와 켜짐·꺼짐 상태
  - 오류 문구: 나타나는 순간 읽어 준다(live region)
  - ⑤: "회원가입". 비활성이면 비활성으로 읽히고, 이유는 칸의 오류로 안다
  - ⑥: "이미 계정이 있어요, 로그인으로 이동" — 화면 문구는 상태만이라 힌트를 붙인다
- 최소 터치 크기 예외: 없음. 보기 토글은 보이는 알약이 작아도 터치 높이 48dp 를 채운다(옛 XML 과 같다). ⑥ 은 글자가 작아 위아래 여백까지 터치 영역에 넣어 44dp 를 채운다

## 옛 화면과의 차이

- 이 화면에서 가입 요청을 보내지 않는다. 옛 앱은 여기서 계정을 만들고 이메일 중복 오류(`err_email_taken`)를 이 화면에서 받았다 → 새 계약은 `nickname` 을 함께 받으므로 요청은 1-4 가 보내고, 409 면 1-4 가 이 화면으로 되돌려 같은 문구를 이메일 칸에 띄운다
- 헤더·워드마크·헤드라인·설명·라벨·플레이스홀더·오류 문구·버튼·링크 문구는 전부 그대로
- ⑥ → 1-2 전환 규칙(바꿔 넣기)은 새로 정했다 — 옛 XML 에는 없다
- 약관 동의는 옛 화면에 없었고 새 화면에도 없다(미결 참고)

## 미결

- **요청 위치.** 계약 `POST /auth/signup` 이 `email`·`password`·`nickname` 을 한 번에 필수로 받는데 화면 순서(화면.md)는 회원가입 → 닉네임이다. 계약을 따라 이 화면은 값만 들고 1-4 로 넘기고 요청은 1-4 가 보내는 것으로 썼다. 대안은 (a) 이메일 사용 가능 여부만 미리 묻는 경로를 계약에 추가해 409 를 이 화면에서 바로 받거나, (b) 닉네임 칸을 이 화면에 넣고 1-4 는 소셜 첫 가입과 프로필 사진 전용으로 두는 것. 1-4 설계와 함께 정해야 한다
- 이메일 중복 409 를 1-4 에서 받은 뒤 1-3 으로 되돌리는 방식(팝 + 오류 전달)은 내가 정한 안이다. 1-4 설계서가 같은 규칙을 써야 한다
- 약관·개인정보 동의: 지시에는 "약관" 이 있으나 기능범위·계약·옛 화면 어디에도 약관 문구·동의 필드·경로가 없다. 넣지 않았다. 필요하면 문구 출처와 동의 저장 방식(계약 필드)이 먼저 있어야 한다
- 비밀번호 규칙은 계약의 8자 이상만 있다. 최대 길이·문자 종류 제한이 서버에 있는지(422 VALIDATION 가능성) — 있으면 1-4 에서 받는 422 를 어느 칸으로 돌릴지 정해야 한다
- ⑥ 의 라벨 "이미 계정이 있어요" 는 상태 서술이고 행동 단어가 없다. 1-1 "처음이신가요?" 와 같은 문제라 함께 정한다
