# 5-6 게시물 작성

**목적** 사진과 글로 새 게시물을 만들어 크루 전체 또는 나만 보기로 올린다.
**원본** `../legacy/android-res/layout/fragment_publish.xml` (사진 타일 `item_photo_pick.xml`, `item_photo_thumb.xml`) · **변경** 활동 기록 카드·기록 범위 선택(내 기록만/모임 전체)이 빠졌다(활동은 요약 이미지로만 붙는다 — 기능범위·4-7). 공개 범위가 크루 전체/나만 보기 두 가지로 정리됐다. 사진 최대 4장 → 10장(계약)
**진입** 피드(5-1) "+ 글쓰기" · 활동 종료 요약(4-7) "공유하기"(요약 이미지가 사진 첫 칸에 미리 붙어서) · **이탈** 게시 완료 → 피드(5-1), 스택에서 이 화면과 4-7 을 함께 지운다 · 뒤로 가기 → 나가기 확인

이 화면은 항상 새 게시물만 만든다. 계약에 `PATCH /posts/{postId}` 가 없어 게시물 수정은 지원하지 않는다(5-2 미결과 같다) — 5-2 의 더보기 시트에도 [수정] 이 없다.

## 배치

옛 XML 의 세로 순서(글 라벨·입력·글자수 → 사진 라벨·선택 → 활동 기록 카드 → 공개 범위 → 버튼 줄)를 그대로 따르되, 활동 기록 카드와 기록 범위 선택을 통째로 뺀다. 헤더는 고정, 그 아래가 세로 스크롤이며 버튼 줄은 옛 화면처럼 스크롤 맨 아래에 있다(화면 밖에 고정하지 않는다). 사진은 옛 세로 4슬롯 리스트 대신 가로로 스크롤하는 정사각 썸네일 줄로 바꿨다 — 10장까지 늘어난 목록엔 슬롯형 리스트보다 어울린다.

## 인터랙션

- 스크롤: ① 헤더만 고정, ②③④⑤ 가 세로로 스크롤. ③ 사진 줄은 그 안에서 가로로 스크롤한다
- 당겨서 새로고침: 없음
- 길게 누르기: 사진 썸네일을 길게 눌러 끌면 다른 자리로 옮겨진다. 맨 앞자리 사진에 "대표" 배지가 옮겨 붙는다
- 시트: 없음. 사진 추가는 시스템 선택기를 바로 연다
- 뒤로 가기: 글·사진이 하나라도 있으면 나가기 확인 대화상자, 없으면 바로 닫는다(4-7 이면 4-7 로, 5-1 이면 5-1 로). 게시 중에는 요청을 끊지 않고 뒤에서 이어간다 — 성공하면 이미 화면을 나갔어도 피드 맨 위에 반영된다
- 키보드: 글 입력에 포커스하면 키보드가 올라오고 그만큼 스크롤 영역이 줄어든다. 엔터는 줄바꿈, 게시는 버튼으로만 한다
- 전환: 진입한 화면(5-1 · 4-7)으로 pop, 또는 게시 성공 시 5-1 로 교체. 나가기 확인은 대화상자(모달)

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로 가기"
  - 글 입력: "게시물 본문 입력". 남은 글자는 1000자에 닿기 전까진 읽지 않고, 닿으면 "1000자, 더 입력할 수 없어요"
  - 사진 추가 타일: "사진 추가, N장 중 M장 골랐어요"
  - 사진 썸네일: "N번째 사진, 삭제하려면 두 번 탭". 맨 앞 사진은 "대표 사진, N번째"
  - 업로드 실패 아이콘: "업로드 실패, 다시 시도하려면 두 번 탭"
  - 공개 범위 행: "크루 전체, 크루원 모두에게 보여요, 선택됨" / "나만 보기, 나에게만 보여요"
  - 진행바: 나타나는 순간과 값이 바뀔 때 "게시하는 중, N장 중 M장 올림" (live region)
  - [취소]: "취소, 게시물 작성 그만두기"
  - [게시하기]: "게시하기". 비활성이면 "게시하기, 비활성" + 힌트 "글이나 사진을 먼저 넣어 주세요"
  - 배너·대화상자: 뜨는 순간 문구를 읽어 준다(live region)
- 최소 터치 크기 예외: 없음. 사진 추가 타일·썸네일은 64dp 라 삭제 버튼만 48dp 로 터치 영역을 넓힌다(옛 `item_photo_thumb` 과 같다). 공개 범위 행·취소·게시하기는 44dp 이상

## 옛 화면과의 차이

- 활동 기록 카드(`recordCard`, 지표 3분할·지도 스냅샷·"수거 기록 없음"/"수정됨" 배지·[기록 카드 제거]·"첨부된 활동 기록이 없어요")와 기록 범위 선택(`scopeGroup`, "내 기록만"/"모임 전체 포함") → 모두 없음. `Post` 에 활동 참조 필드가 없어 활동은 요약 이미지 한 장으로만 붙는다(4-7 미결과 같은 제약)
- 공개 범위 선택(`visibilityRow`, FlexboxLayout — 옛 값 불명, 아마 전체공개/친구공개/비공개 계열) → "크루 전체"/"나만 보기" 두 행(계약 `visibility` enum CREW/PRIVATE)
- 사진 세로 4슬롯 리스트(`item_photo_pick`, "사진 선택 (최대 4장)") → 가로 스크롤 정사각 썸네일 줄(`item_photo_thumb` 스타일: 삭제 ×·대표 배지), 최대 10장(계약 `mediaIds` maxItems)으로 늘었다
- 글자 수 상한 300자(`hint_post_body`, EditText maxLength) → 1000자(계약 `text` maxLength)
- 헤더 부제 "게시글 작성"/"게시글 수정"(`pub_title_new`/`pub_title_edit`) → "게시물 작성" 하나만. 수정 모드는 없다(계약에 `PATCH /posts/{postId}` 가 없다 — 5-2 미결과 같다)
- 하단 왼쪽 버튼 "건너뛰기"(`pub_skip`) → "취소". 건너뛰기는 활동 공유 흐름 전용 어휘라 피드에서 바로 들어오는 일반 작성에는 맞지 않는다
- "게시하기"(`pub_cta_new`)는 그대로 두고 "수정 완료"(`pub_cta_edit`)는 없다
- "배출 인증 사진 포함" 토글(`pub_disposal_toggle`/`pub_disposal_desc`) → 없음. 배출 인증이라는 기능 자체가 이 기능범위에 없다
- "내용을 한 글자라도 써 주세요."(`pub_need_note`, 글 필수) → 글 또는 사진 중 하나만 있으면 게시 가능(아래 미결)
- 사진 업로드 진행바·부분 실패 재시도·나가기 확인 대화상자는 새로 정했다. 옛 XML 흔적으로는 확인 없이 바로 나갔다

## 미결

- **게시 버튼 활성화 기준.** 계약은 `text`·`mediaIds` 모두 `required` 지만 `text` 에 minLength 가 없어 빈 문자열도 형식상 유효하다. 이 문서는 "글 또는 사진 중 하나"를 기준으로 삼아 4-7 의 "글 없이 사진만 공유" 흐름을 살렸다. 옛 화면은 글을 필수로 했다(`pub_need_note`) — 정책 확정이 필요하다
- **사진 업로드 방식.** 계약은 순서·동시 업로드 개수·재시도 규칙을 말하지 않는다. 이 문서는 "순서대로, 실패한 사진만 재시도"로 정했다. 병렬로 여러 장을 한꺼번에 올릴지는 성능·서버 부하와 함께 정해야 한다
- **`purpose`=POST 일 때 `inference` 값.** 계약 설명은 "ACTIVITY 만 추론"이라고만 해 POST 업로드 응답의 `inference` 가 null 로 오는지 빈 객체로 오는지 명시하지 않는다. 이 화면은 어느 쪽이든 쓰지 않는다
- **사진 순서 변경(드래그) 의 실제 모양.** 길게 눌러 끄는 상호작용을 정했지만 디자인(끄는 동안의 시각 효과, 빈자리 표시)은 확정이 필요하다
- **최대 10장이 실제로 맞는지.** 계약 `mediaIds` maxItems 10 을 그대로 따랐다. 옛 화면 4장보다 크게 늘어 UI·업로드 시간에 부담이 될 수 있다
- **나가기 확인 문구·배너 문구("게시하지 못했어요. 다시 시도해 주세요." · "인터넷 연결을 확인해 주세요.")는 내가 정한 안이다.** 확정이 필요하다
- 5-2 의 미결("게시물 수정이 없다")과 짝을 이룬다 — `PATCH /posts/{postId}` 가 생기면 이 화면에 수정 모드(제목 "게시물 수정", 버튼 "수정 완료", 기존 `text`·`visibility`·사진으로 미리 채움)를 추가해야 한다
