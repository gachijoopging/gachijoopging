# 3-8 가입 신청 관리

**목적** 크루장이 대기 중인 가입 신청을 확인하고 한 사람씩 승인하거나 거절한다.
**원본** `../legacy/android-res/layout/fragment_friends.xml` · **변경** 친구·받은 요청 탭을 없애고, 초대 코드로 들어온 가입 신청 한 목록과 승인·거절 행동으로 바꿨다. 크루장만 접근한다.
**진입** 3-2 크루 정보의 "가입 신청 N건" · 2-3 JOIN_REQUEST 알림 · **이탈** 3-2 크루 정보 · 5-4 타인 프로필 · 뒤로 가기 → 진입 화면

## 배치

옛 XML의 순서(헤더 → 탭 자리 → 로딩·빈 상태·목록 → 아래 안내)를 따른다. 두 탭 자리에는 "대기 중인 가입 신청" 제목과 건수만 두고, 각 행에 신청자·신청 시각·승인·거절 버튼을 놓는다.

```
┌──────────────────────────────────────┐
│ ① ‹  가입 신청 관리                    │
├──────────────────────────────────────┤
│ ② 대기 중인 가입 신청 2건              │
├──────────────────────────────────────┤
│ ③ ┌────────────────────────────────┐ │
│    │ (◉) 지수                         │ │
│    │     9월 2일 가입 신청             │ │
│    │        [거절]  [승인]             │ │
│    └────────────────────────────────┘ │
│ ③ ┌────────────────────────────────┐ │
│    │ (◉) 민수                         │ │
│    │     9월 1일 가입 신청             │ │
│    │        [거절]  [승인]             │ │
│    └────────────────────────────────┘ │
│ ④ 승인된 사람은 바로 크루원이 돼요.     │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로 버튼 | "뒤로" | `Icon`(arrow-left) | 진입 화면 |
| ① | 헤더 제목 | "가입 신청 관리" | `Txt` title | — |
| ② | 대기 수 | `GET /crew/join-requests` 배열 길이. "대기 중인 가입 신청 2건" | `Txt` section | — |
| ③ | 신청 행 | `id`·`user.photoUrl`·`user.nickname`·`createdAt`·`status` (`GET /crew/join-requests`) | `Card` + `Avatar` md + `Txt` | 신청자 → 5-4 |
| ③ | 신청자 아바타·닉네임 | `user.photoUrl` null이면 `user.nickname` 첫 글자 | `Avatar` md + `Txt` body strong | 5-4 |
| ③ | 신청 시각 | `createdAt`을 "9월 2일 가입 신청"으로 표시 | `Txt` caption muted | — |
| ③ | 거절 버튼 | "거절" | `Button` ghost sm | 거절 확인 → `POST /crew/join-requests/{requestId}` (`decision` REJECT) |
| ③ | 승인 버튼 | "승인" | `Button` primary sm | 승인 확인 → `POST /crew/join-requests/{requestId}` (`decision` APPROVE) |
| ④ | 안내 문구 | "승인된 사람은 바로 크루원이 돼요." | `Banner` neutral | — |

목록은 PENDING 신청만 돌려주는 계약이다. 승인·거절 성공 뒤 해당 행은 목록에서 바로 사라지고 3-2의 `pendingJoinRequests`도 다음 진입·새로고침 때 줄어든다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | ①은 보이고 ②·③ 자리에 `Loading` "가입 신청을 불러오고 있어요" | ① 뒤로 |
| 새로고침 | 당겨서 새로고침. 기존 행은 남기고 상단 스피너 | 행·뒤로 |
| 빈 | 배열이 비어 있음. `EmptyState` "대기 중인 가입 신청이 없어요" / "새 신청이 들어오면 여기에서 승인하거나 거절할 수 있어요." | 뒤로 |
| 오류 | `GET /crew/join-requests` 4xx·5xx면 `ErrorState` "가입 신청을 불러오지 못했어요" / [다시 시도] | 다시 시도 |
| 오프라인 | 이전 행이 있으면 그대로, ② 아래 `Banner` "인터넷 연결을 확인해 주세요.". 없으면 오류 상태 | 이전 행·뒤로 |
| 권한 거부 | 크루원이 직접 진입하거나 403 FORBIDDEN이면 `ErrorState` "크루장만 가입 신청을 관리할 수 있어요." / [크루 정보로] | 크루 정보로 → 3-2 |
| 부분 실패 | **해당 없음.** 목록 요청 하나다. 개별 승인·거절 실패는 아래 처리 상태가 다룬다 | — |
| 승인·거절 처리 중 | 선택한 행의 두 버튼 자리에 스피너, 그 행만 비활성. 다른 행은 계속 처리 가능 | 다른 행·뒤로 |
| 이미 처리됨 | 같은 신청을 다른 크루장이 처리했거나 재시도 중 404·409이면 행을 목록에서 지우고 `Snackbar` "이미 처리된 가입 신청이에요." | 나머지 행 |

승인 확인 대화상자: 제목 "지수 님의 가입을 승인할까요?" · 본문 "승인하면 바로 크루원이 돼요." · [취소] / [승인].

거절 확인 대화상자: 제목 "지수 님의 가입을 거절할까요?" · 본문 "거절한 뒤에도 새 초대 코드로 다시 가입 신청할 수 있어요." · [취소] / [거절].

`POST /crew/join-requests/{requestId}` 204면 행을 제거하고 승인 때 "지수 님을 크루원으로 맞이했어요.", 거절 때 "가입 신청을 거절했어요." `Snackbar`를 보인다. 4xx·5xx·오프라인이면 행을 유지하고 "가입 신청을 처리하지 못했어요. 다시 시도해 주세요." `Snackbar`.

## 인터랙션

- 스크롤: 신청 행이 화면보다 많으면 세로 스크롤
- 당겨서 새로고침: 있음. `GET /crew/join-requests` 재조회
- 길게 누르기: 없음
- 시트: 없음. 승인·거절 확인은 대화상자
- 뒤로 가기: 진입 화면으로 팝한다. 대화상자가 떠 있으면 먼저 닫는다
- 키보드: 없음
- 행 탭: 신청자 아바타·닉네임 영역은 5-4 타인 프로필로 푸시한다. 승인·거절 버튼 영역은 프로필로 이동하지 않는다
- 전환: 5-4는 푸시. 처리 성공은 목록 안에서 행만 바꾼다

## 접근성

- ②: "대기 중인 가입 신청 2건"을 읽는다
- ③: "지수, 9월 2일 가입 신청, 승인, 거절"로 행을 읽는다. 아바타는 닉네임이 대신한다
- 승인·거절 확인 대화상자는 제목·본문을 live region으로 읽는다
- 버튼은 역할을 포함해 "지수 님 가입 승인", "지수 님 가입 거절"로 읽고 모두 44dp 이상이다

## 옛 화면과의 차이

- 옛 친구/받은 요청 두 탭과 친구 수락·거절을 없앴다. 크루원 사이에는 친구 관계가 없다
- 옛 받은 친구 요청 행을 초대 코드 기반 가입 신청 행으로 바꾸고, 승인하면 크루원이 되는 효과를 명시했다
- 옛 아래 친구 안내를 크루 가입 신청 안내로 바꿨다

## 미결

- 거절 뒤 같은 사람이 다시 신청할 수 있는지, 횟수 제한이 있는지 계약에 없다. 현재는 다시 신청할 수 있다고 안내한다
- 가입 신청을 처리할 때 거절 사유를 남길지 계약에 없다
- 신청이 매우 많을 때 페이지네이션이 없다. 현재 계약은 배열 전체를 받는다
