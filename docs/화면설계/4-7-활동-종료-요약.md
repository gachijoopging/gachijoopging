# 4-7 활동 종료 요약

**목적** 방금 끝낸 활동을 서버에 저장하고, 거리·시간·줍기 개수·경로를 한눈에 보인 뒤 게시물로 공유할지 고른다.
**원본** `../legacy/android-res/layout/fragment_activity_end.xml` (지표 줄 `view_metric_row.xml`, 지도 `view_map_frame.xml`) · **변경** 모임 관련 세 덩이(내 개인 기록 칩·모임 전체 기록 안내·함께한 멤버 카드)와 미분류 정리 배너를 뺐다. 제목·지도·지표 3분할·카테고리 칩·0개 배너·동기화 대기 칩·공유 카드는 그대로. 종료 요청(`POST /activities/{id}/end`)을 이 화면이 보내며 저장 중·실패·오프라인 상태를 새로 정했다
**진입** 활동 중(4-3)의 종료 확인 다이얼로그에서 [종료하기] · **이탈** 공유하기 → 게시물 작성(5-6, 요약 이미지가 첨부된 채) · 공유 안 함·뒤로 가기 → 줍깅 대기(4-1)

4-3 에서 [종료하기]를 누르는 순간 배경 추적(포그라운드 서비스)을 끄고 이 화면을 연다. 화면은 기기에 쌓여 있던 값(거리·시간·일시정지 시간·걸음수·경로·줍기 개수)으로 바로 그려지고, 동시에 `POST /activities/{id}/end` 를 보낸다. 응답이 오면 서버 값으로 바꾼다. 다른 요청은 없다 — `GET /activities/{id}` 는 나중에 5-3 기록 상세가 부른다.

## 배치

옛 XML 의 세로 순서(제목·메타 → 지도 → 지표 3분할 → 카테고리 칩 → 0개 배너 → 동기화 칩 → 공유 카드)를 그대로 따른다. 사이에 있던 개인 기록 칩·모임 안내·멤버 카드가 빠져 지도 바로 아래 지표가 붙는다. 제목 줄은 고정이고 그 아래가 세로 스크롤이다. 헤더 뒤로 버튼은 없다(옛 화면과 같다) — 닫기는 공유 카드의 [공유 안 함] 과 Android 뒤로 가기가 한다.

## 인터랙션

- 스크롤: 세로. ① 제목 줄은 고정, ②~⑦ 이 스크롤. 카테고리가 많거나 배너·칩이 붙으면 ⑦ 이 밀리므로 스크롤한다. 지도 위에서 세로로 끌어도 지도가 아니라 화면이 스크롤된다(지도 조작 막음)
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: 없음
- 뒤로 가기: [공유 안 함] 과 같다 — 확인 없이 4-1 로. 저장 중이면 요청을 끊지 않고 뒤에서 이어간다(저장 중 행). 오류·오프라인 상태에서 나가도 기기 값은 남는다
- 키보드: 없음
- 지도: 정지 이미지처럼 다룬다. 탭·끌기·확대 없음. 전체화면 없음
- 공유하기: 누르는 순간 ②③④ 를 한 장으로 그려(캡처가 아니라 같은 값으로 다시 그린 이미지) 5-6 을 푸시한다. 5-6 에 첨부 사진 첫 칸으로 들어가고 글은 비어 있다. 5-6 에서 뒤로 오면 이 화면(저장 완료 상태)으로 돌아온다. 게시물을 올리고 나면 5-6 이 4-7 과 함께 스택에서 빠져 4-1 로 간다
- 전환: 4-3 → 4-7 은 4-3 을 스택에서 지우고 교체(뒤로 가기로 4-3 에 돌아가지 않는다). 4-7 → 5-6 푸시. 4-7 → 4-1 은 닫기(4-1 은 4-2 때부터 스택에 남아 있다). ⑤⑥ 배너·칩과 ⑦ 문구 교체는 짧게 페이드

  - 메타: 본문 그대로. "9월 7일 일요일 9시 2분부터 9시 48분까지, 일시정지 4분, 4,100걸음"
  - 지도: "걸은 경로 지도, 3.1km". 선·점은 읽지 않는다. 경로가 없으면 "경로가 기록되지 않았어요"
  - ③: 칸 하나를 한 요소로 "수거 개수 27개" · "활동 시간 42분" · "이동 거리 3.1km"
  - ④: 칩마다 "담배꽁초 14개". 아이콘은 읽지 않는다
  - ⑤ 배너·⑥ 칩: 나타나는 순간 문구를 읽어 준다(live region). 앞의 이모지(🚶 📴)는 읽지 않는다
  - ⑦ 제목: 상태가 바뀌는 순간 새 문구를 읽어 준다(live region). 체크 아이콘·스피너는 읽지 않는다
  - [공유하기]: "공유하기, 게시물 작성으로 이동". 비활성이면 비활성으로 읽히고 힌트 "기록 저장이 끝나면 쓸 수 있어요"
  - [공유 안 함]: "공유 안 함, 닫기"
- 최소 터치 크기 예외: 없음. ⑦ 두 버튼은 md 높이에 카드 안 너비를 반씩 나눈다. 그 밖에 눌리는 것이 없다

## 옛 화면과의 차이

- "🙋 내 개인 기록" 칩(`personalChip`) · "모임 전체 기록은 따로 정리돼요 / 모임장이 활동을 종료하면…" 안내(`groupNote`) · "함께한 멤버" 카드(`membersCard`) → 모두 없음. 활동은 항상 개인 단위다
- 경로 라벨 "걸은 경로 · 주운 위치 N" → "걸은 경로". 줍기 위치 마커를 그리지 않는다(미결 참고)
- 미분류 배너(`unclassBanner`, [미분류 정리]) → 없음. 4-5 에서 사용자가 카테고리를 확인한 뒤 담으므로 종료 시점에 미분류가 남지 않는다
- 제목 "오늘의 줍깅 정리 🌱" · 지표 3분할(수거 개수·활동 시간·이동 거리) · 카테고리 칩 · "🚶 수거 기록 없이 활동만 저장돼요…" · "📴 동기화 대기 중 · 연결되면 자동 업로드돼요" · "기록을 저장했어요. 피드에 공유할까요?" · "동기화가 끝나야 피드에 공유할 수 있어요." · [공유 안 함] · [공유하기] 는 그대로
- 메타 줄에 일시정지 시간·걸음수를 넣었다 — 일시정지와 걸음수 보정이 새로 생겼다
- "공유하기" 가 기록을 붙인 게시물이 아니라 요약 이미지를 첨부한 자유 게시물로 간다(기능범위 피드 절)
- 저장 중·오류·오프라인 세 상태의 카드 문구와 [다시 시도] · 409 처리는 새로 정했다 — 옛 XML 에는 동기화 칩과 공유 막힘 문구만 있었다

## 미결

- **4-3 초안과 종료 요청의 주인이 다르다.** 같이 쓰인 4-3 초안은 종료 확인 다이얼로그의 [종료하기] 가 `POST /activities/{id}/end` 를 보내고 성공했을 때만 4-7 을 열며, 오프라인이면 "오프라인이에요. 연결된 뒤 종료해 주세요" 로 종료를 막는다. 이 장은 4-7 이 기기 값으로 먼저 그려지고 요청을 보내며 실패·오프라인을 여기서 받는다(옛 화면의 동기화 대기 칩 흐름). 둘 중 하나로 정해 한쪽을 고쳐야 한다 — 4-3 쪽으로 가면 이 장의 저장 중·오류·오프라인 행과 ⑥ 동기화 칩·공유 막힘 안내가 빠지고 첫 진입이 응답 값으로 바로 그려진다
- **줍기 위치 마커를 그릴 수 없다.** `Activity` 의 `items` 에 좌표가 없고 `photos` 도 `takenAt` 만 있다(`POST /media` 는 `lat`·`lng` 를 받지만 돌려주지 않는다). 옛 라벨 "걸은 경로 · 주운 위치 N" 을 "걸은 경로" 로 줄였다. 마커가 필요하면 `photos` 나 `items` 에 좌표를 붙여야 한다 — 5-3 기록 상세도 같은 제약이다
- `POST /activities/{id}/end` 의 responses 에 200 만 있고 `Error` 응답이 없다. 이미 종료된 활동에 다시 보내면 409 CONFLICT 로 읽고 `GET /activities/{id}` 로 복구하기로 했다 — 서버가 200 으로 그냥 돌려줘도 같은 결과다. 계약에 명시해 주면 좋다
- 오프라인 대기열은 계약·기능범위에 없다(4-5 미결과 같은 문제). 종료는 경로 id 로 멱등이라 두 번 보내도 활동이 두 개 되지는 않지만, 두 번째 응답(409 또는 200)을 성공으로 다루는 규칙이 필요하다
- 종료 응답에 크루 합산(crew_daily_stats) 반영 여부나 크루 목표 진행값이 없다. 이 화면은 크루 목표·캐릭터 반응을 보이지 않는다(기능범위 줍깅 절에 없다). "이번 활동으로 크루 목표까지 M개" 를 보이려면 응답에 `character` 같은 값을 붙이거나 `GET /crew/home` 을 한 번 더 불러야 한다
- 이탈 "닫기" 를 4-1 줍깅 대기로 정했다(4-2 승인본의 "4-3 을 끝내면 4-7 을 거쳐 4-1 로 돌아온다" 를 따름). 상위 지시는 2-1 홈이었다 — 홈으로 보내려면 4-2 도 함께 고쳐야 한다
- 매우 짧은 활동(0개 · 1분 미만 · 50m 미만)을 따로 다루지 않았다. "이 기록 지우기"(`DELETE /activities/{id}`) 를 이 화면에 둘지, 서버가 최소 길이 미만을 거를지
- 요약 이미지의 모양(②③④ 를 어떻게 한 장에 담는지)은 5-6 설계와 디자인에서 정한다. 이 화면은 5-6 에 첨부 사진으로 넘길 뿐이다
- "기록을 저장하고 있어요…" · "기록을 기기에 저장했어요" · "기록을 저장하지 못했어요" · "다시 시도하면 지금 보이는 기록을 그대로 올려요." · 404·422 문구 · "경로가 기록되지 않았어요" · 4-1 스낵바 두 문구는 내가 정한 안이다. 확정이 필요하다
- 시간 표기(1분 미만 · N분 · N시간 N분)와 거리 표기(m/km, 소수 첫째 자리)는 3-4 크루 기록·5-3 기록 상세와 같은 규칙을 써야 한다. 여기서 먼저 정했다
- 카테고리 아이콘은 4-5 와 같은 MDI 글리프를 썼다. 4-6 빠른 줍기 시트와도 맞춘다
