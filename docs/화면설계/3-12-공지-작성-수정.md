# 3-12 공지 작성·수정

**목적** 크루장이 제목·본문·고정 여부를 정해 공지를 작성하거나 기존 공지를 수정한다.
**원본** `../legacy/android-res/layout/fragment_publish.xml` · **변경** 사진·활동 요약·공개 범위·게시물 임시 저장을 없애고 제목·본문·고정 토글만 남겼다. 크루장만 접근한다.
**진입** 3-5 공지 목록의 "작성" · 3-6 공지 상세의 "수정" · **이탈** 작성 성공 → 3-6 공지 상세 · 수정 성공 → 3-6 공지 상세 · 뒤로 가기 → 진입 화면

## 배치

옛 작성 화면의 순서(헤더 → 본문 입력 → 글자 수 → 추가 설정 → 아래 주 버튼)를 따른다. 사진·활동·공개 범위 영역은 제거하고 제목, 본문, 공지 고정 토글을 세로로 둔다. 저장 버튼은 화면 아래에 고정한다.

```
┌──────────────────────────────────────┐
│ ① ‹  공지 작성                        │
├──────────────────────────────────────┤
│ ② 제목                                 │
│    ┌ 9월 정기 활동 안내 ─────────────┐ │
│                         14 / 100      │
│ ③ 내용                                 │
│    ┌ 9월 첫째 주 토요일... ─────────┐ │
│    │                                  │ │
│    └────────────────────────────────┘ │
│                         42 / 3000     │
│ ④ [●] 이 공지를 목록 맨 위에 고정       │
├──────────────────────────────────────┤
│ ⑤ [          공지 올리기          ]    │
└──────────────────────────────────────┘
```

수정 모드에서는 ① 제목이 "공지 수정", ⑤가 "변경사항 저장"으로 바뀌고 현재 `title`·`body`·`pinned`를 채운다.

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로 버튼 | "뒤로" | `Icon`(arrow-left) | 진입 화면 |
| ① | 헤더 제목 | 작성은 "공지 작성", 수정은 "공지 수정" | `Txt` title | — |
| ② | 제목 입력창 | `title` (`POST /crew/notices`, `PATCH /notices/{noticeId}`) · 최대 100자 · 플레이스홀더 "공지 제목을 입력해 주세요." | `Field` | 키보드 |
| ② | 제목 글자 수 | "14 / 100" | `Txt` micro | — |
| ③ | 본문 입력창 | `body` (`POST /crew/notices`, `PATCH /notices/{noticeId}`) · 최대 3000자 · 플레이스홀더 "크루원에게 알릴 내용을 입력해 주세요." | `Field` | 키보드 |
| ③ | 본문 글자 수 | "42 / 3000" | `Txt` micro | — |
| ④ | 고정 토글 | `pinned` (`POST /crew/notices`, `PATCH /notices/{noticeId}`) · "이 공지를 목록 맨 위에 고정" | `Tile` + `신규` 스위치 | on/off |

입력 앞뒤 공백을 지운다. 제목·본문은 각각 100자·3000자를 넘으면 입력을 막고 "제목은 100자까지 입력할 수 있어요." / "내용은 3000자까지 입력할 수 있어요."를 보인다. 빈 제목은 "공지 제목을 입력해 주세요.", 빈 본문은 "공지 내용을 입력해 주세요."를 각 입력창 아래에 보인다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | 작성은 즉시 빈 입력 화면. 수정은 ①은 보이고 ②~⑤에 `Loading` "공지를 불러오고 있어요" | 뒤로 |
| 작성·수정 전 | 입력값이 유효하지 않거나 수정 모드에서 변경이 없으면 ⑤ 비활성 | ①~④ |
| 저장 중 | ⑤ 라벨 자리에 스피너. ①~④ 비활성 | 없음 |
| 새로고침 | **해당 없음.** 입력 중 값을 잃을 수 있어 제공하지 않는다 | — |
| 빈 | **해당 없음.** 빈 입력은 초기 상태이지 목록의 빈 상태가 아니다 | ①~④ |
| 오류 | POST·PATCH 4xx·5xx면 입력값·토글을 보존하고 "공지를 저장하지 못했어요. 다시 시도해 주세요." `Snackbar` | ⑤ 다시 시도 |
| 오프라인 | 값은 그대로. ⑤을 누르면 같은 저장 실패 `Snackbar` | ①~④ |
| 권한 거부 | 크루원이 진입하거나 403 FORBIDDEN이면 `ErrorState` "크루장만 공지를 작성할 수 있어요." / [공지 목록으로] | 공지 목록으로 → 3-5 |
| 부분 실패 | **해당 없음.** 공지 텍스트·고정 여부는 하나의 요청으로 저장한다 | — |
| 삭제됨 | 수정 중 404 NOT_FOUND면 "삭제된 공지예요." `Snackbar` 뒤 3-5로 팝한다 | — |

작성 성공: `POST /crew/notices` 201의 `data.id`로 3-6으로 대체 전환하고 `Snackbar` "공지를 올렸어요.".
수정 성공: `PATCH /notices/{noticeId}` 204 뒤 3-6을 새로 받아 `Snackbar` "공지 변경사항을 저장했어요.".

## 인터랙션

- 스크롤: ②~④가 키보드·작은 화면에서 세로 스크롤. ①·⑤는 고정
- 당겨서 새로고침: 없음
- 길게 누르기: 입력창 OS 기본 붙여넣기
- 시트: 없음
- 뒤로 가기: 변경이 없으면 진입 화면으로 팝. 변경이 있으면 "변경사항을 버릴까요?" / "저장하지 않은 내용은 사라져요." / [계속 작성] [버리기] 대화상자
- 키보드: 제목 완료 키는 본문으로, 본문 완료 키는 유효하면 ⑤와 같은 저장을 한다
- 고정 토글: 켜면 "목록 맨 위에 고정돼요." 보조 문구, 끄면 보조 문구를 숨긴다
- 전환: 성공 뒤 3-6. 3-6에서 뒤로 가면 3-5 목록이 새로고침된다

## 접근성

- ②: "공지 제목, 100자까지, 14자 입력됨"
- ③: "공지 내용, 3000자까지, 42자 입력됨"
- ④: "이 공지를 목록 맨 위에 고정, 켜짐/꺼짐"
- ⑤: "공지 올리기" 또는 "변경사항 저장", 활성·비활성을 읽는다
- 모든 입력·토글·버튼은 44dp 이상이다

## 옛 화면과의 차이

- 옛 게시물 작성의 사진·활동 요약·공개 범위·게시물 임시 저장을 모두 없앴다
- 공지는 사진 없는 텍스트와 고정 여부만 가지며 크루장만 작성한다
- 옛 본문 300자 제한은 공지 본문 3000자로, 새 제목 입력과 100자 제한을 추가했다

## 미결

- 공지 제목·본문 최소 길이는 계약에 없다. 현재는 공백 제거 뒤 각각 1자로 정했다
- 고정 공지가 여러 개일 때 새 공지를 고정하면 기존 고정이 유지되는지 계약에 없다
- 공지 작성 중 임시 저장을 제공할지 정해지지 않았다
