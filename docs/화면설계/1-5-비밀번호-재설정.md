# 1-5 비밀번호 재설정·확인

**목적** 비밀번호를 잊은 사람이 가입한 이메일로 코드를 받아 새 비밀번호를 정한다.
**원본** `../legacy/android-res/layout/fragment_password_reset.xml` (A 요청) · `../legacy/android-res/layout/fragment_password_reset_confirm.xml` (B 확인) · **변경** 배치·문구는 그대로. 메일의 **링크**로 열리던 B 가 메일로 받은 **코드를 입력**하는 화면이 됐다(계약 `POST /auth/password-reset/confirm` 이 `email`·`code` 를 받는다). A 의 발송 후 패널에서 B 로 넘어가는 버튼이 생겼다
**진입** A: 1-2 로그인 "비밀번호를 잊으셨나요?" · 5-7 설정 "비밀번호 재설정". B: A 의 발송 후 패널 "코드 입력하기" 에서만 · **이탈** B 성공 → 1-2 로그인(5-7 에서 왔으면 5-7). 뒤로 가기 → 온 곳

## 배치

두 장 모두 옛 XML 의 세로 순서를 그대로 따른다. A 는 헤더 → 헤드라인 → 설명 → 이메일 라벨·입력·오류 → [재설정 메일 보내기] 이고, 발송이 끝나면 같은 자리가 ✉️ 원 → 제목 → 설명 → 버튼 2개로 바뀐다(옛 `formState`/`sentState` 전환). B 는 헤더 → 헤드라인 → 비밀번호 → 보기 토글 → 비밀번호 확인 → 오류 → [비밀번호 변경] 이며, 헤드라인 아래에 인증 코드 입력이 하나 늘었다. 둘 다 한 화면에 들어가고, 키보드가 올라오면 A 만 스크롤한다(옛 A 는 ScrollView, B 는 아니었다).

A 요청 — 발송 전

```
┌──────────────────────────────────────┐
│ ① ‹  비밀번호 재설정                    │
│      계정 복구                         │
├──────────────────────────────────────┤
│ ② 가입한 이메일을 알려 주세요             │
│    입력한 주소로 비밀번호 재설정 코드를     │
│    보내 드려요.                         │
│                                      │
│ ③ 이메일                               │
│   [ you@example.com              ]   │
│   이메일 형식이 올바르지 않아요.           │  ← 평소 숨김
│                                      │
│ ④ [     재설정 메일 보내기      ] 비활성  │
└──────────────────────────────────────┘
```

A 요청 — 발송 후 (②③④ 자리가 통째로 ⑤ 로 바뀐다)

```
┌──────────────────────────────────────┐
│ ① ‹  비밀번호 재설정                    │
│      계정 복구                         │
├──────────────────────────────────────┤
│ ⑤               (✉️)                 │
│        재설정 요청을 접수했어요            │
│   요청을 접수했어요. kwan@example.com     │
│   계정이 있으면 메일을 확인해 주세요.       │
│                                      │
│          [   코드 입력하기   ]           │
│            메일 다시 보내기              │
└──────────────────────────────────────┘
```

B 확인

```
┌──────────────────────────────────────┐
│ ⑥ ‹  새 비밀번호 설정                   │
├──────────────────────────────────────┤
│ ⑦ 새로 사용할 비밀번호를 입력해 주세요      │
│                                      │
│ ⑧ 인증 코드                            │
│   [ 메일로 받은 코드               ]   │
│                                      │
│ ⑨ 비밀번호                             │
│   [ 8자 이상                 ●●●● ]   │
│   보기                                │
│                                      │
│ ⑩ 비밀번호 확인                         │
│   [ 비밀번호를 한 번 더 입력          ]   │
│   비밀번호가 서로 달라요.                 │  ← 평소 숨김
│                                      │
│ ⑪ [        비밀번호 변경        ] 비활성 │
```

## 인터랙션

- 스크롤: A 는 키보드가 올라와 ④ 가 가리면 폼 영역만 스크롤(옛 ScrollView). 발송 후 패널과 B 는 스크롤하지 않는다 — B 는 키보드가 ⑪ 을 가리면 화면을 밀어 올린다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음. 입력칸은 OS 기본(붙여넣기)만 — ⑧ 코드는 메일에서 복사해 붙이는 것이 주 경로다
- 시트: 없음
- 뒤로 가기: A 발송 전 → 온 곳(1-2 또는 5-7). A 발송 후 패널 → 발송 전 폼이 아니라 온 곳으로 간다(패널은 되돌릴 화면이 아니다). B → A 발송 후 패널. 전송 중 뒤로 가기는 요청을 버리고 그대로 나간다
- 키보드: A ③ 이메일 키보드, 완료 키 = ④ 와 같다(활성일 때만). B ⑧ 기본 키보드, 다음 → ⑨ · ⑨ 다음 → ⑩ · ⑩ 완료 = ⑪ 과 같다(활성일 때만). 빈 곳을 탭하면 키보드가 내려간다
- 발송 전 → 발송 후: 같은 화면 안에서 ②③④ 가 사라지고 ⑤ 가 페이드 인. 헤더는 그대로
- 전환: 1-2·5-7 → A 는 푸시. A → B 는 푸시. B 성공은 1-2(또는 5-7)까지 스택을 걷어 A·B 를 모두 지운다 — 뒤로 가기로 B 에 되돌아오지 않는다. `Snackbar` 는 도착한 화면 위에 뜬다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로"
  - A 헤더: "비밀번호 재설정, 계정 복구" · B 헤더: "새 비밀번호 설정"
  - ③⑧⑨⑩: 라벨을 입력칸 라벨로 묶어 "이메일, 편집 상자" 처럼 읽힌다. 오류가 뜨면 그 칸의 오류로 붙여 읽는다(live region)
  - 보기 토글: "비밀번호 보기" ↔ "비밀번호 숨기기"
  - ④⑪ 비활성: "비활성" 으로 읽히고, 스피너 중에는 "보내는 중" / "변경하는 중"
  - ⑤ 봉투 원: 장식이라 읽지 않는다(옛 XML 도 `importantForAccessibility=no`)
  - ⑤ 설명: 이메일을 포함한 본문 그대로 읽는다
  - `Snackbar`: 뜨는 순간 문구를 읽어 준다
- 최소 터치 크기 예외: 없음. 뒤로는 44dp. 보기 토글은 글자가 작아 위아래 여백까지 터치 영역에 넣어 44dp 를 채운다

## 옛 화면과의 차이

- B 진입: 메일의 **링크**(토큰) → 메일로 받은 **코드**를 직접 입력. 그래서 B 에 ⑧ 인증 코드 칸이 새로 들어갔고, B 는 A 를 거쳐서만 열린다(딥링크 없음)
- A ⑤ 버튼: "메일 다시 보내기"(ghost) · "로그인으로 돌아가기"(primary) → "코드 입력하기"(primary) · "메일 다시 보내기"(ghost). 로그인 복귀는 뒤로 가기가 맡는다
- A 설명 "재설정 링크를 보내 드려요." → "재설정 코드를 보내 드려요."
- B 오류 문구 "링크가 만료되었거나 이미 사용됐어요. 재설정 메일을 다시 요청해 주세요." → "코드가 만료되었거나 올바르지 않아요. 재설정 메일을 다시 요청해 주세요."
- 비밀번호 확인 불일치 문구는 옛 문자열에 없어 "비밀번호가 서로 달라요." 를 새로 정했다
- 5-7 설정에서 들어오는 경로에서 이메일 미리 채움은 새로 정했다
- 그 외 헤더·헤드라인·라벨·플레이스홀더·버튼 문구·발송 후 패널(✉️ 원·제목·설명)은 그대로

## 미결

- 계약 `POST /auth/password-reset/confirm` 은 `email`·`code`·`newPassword` 만 받는다 — 메일 링크용 토큰이 없어 딥링크 진입은 뺐다. 링크 방식으로 돌아가려면 계약에 토큰 경로가 먼저 필요하다
- `code` 의 자릿수·문자 종류·유효 시간이 계약에 없다. 정해지면 ⑧ 플레이스홀더("6자리 숫자" 등)·키보드 종류·길이 검증을 넣는다
- 422 외의 코드 오류 구분(만료 vs 불일치 vs 횟수 초과)이 계약에 없어 한 문구로 합쳤다. 429 RATE_LIMITED 가 B 에도 오는지
- A 다시 보내기의 연타 제한(초 단위 쿨다운)을 화면에서 둘지 — 서버 429 에만 맡기고 두지 않았다
- 5-7 에서 온 경우 `hasPassword` (`GET /users/me`) 가 false 인 소셜 전용 계정에도 이 화면을 여는지(비밀번호 "만들기" 가 된다). 5-7 에서 정한다
- 5-7 에서 온 경우 변경 성공 뒤 기존 토큰을 그대로 두는지, 서버가 다른 기기 세션을 끊는지 — 계약에 없다
