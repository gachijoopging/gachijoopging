# 4-3 활동 중

**목적** 걷는 동안 거리·시간·줍기 개수를 보며 줍기를 기록하고, 같은 시간에 뛰는 크루원을 지도에서 본다.
**원본** `../legacy/android-res/layout/fragment_active.xml` (+ `view_map_frame`, `view_metric_row`) · **변경** 모임 라벨→위치 공유 표시, 멤버 알약→활동 중인 크루원, 그룹 버튼→채팅, 음소거·마이크→일시정지/재개, 지표 3칸→4칸(걸음 추가), GPS 배너를 세 가지로 나눔, 오프라인 문구 변경, 배경 알림창 신설
**진입** 활동 시작 시트(4-2)에서 시작 성공 · 줍깅 대기(4-1)에 들어왔는데 진행 중 활동이 있을 때(`GET /activities/current`) · 배경 알림창 탭 · 활동 중에 하단 탭 줍깅 · AI 분류 확인(4-5)·빠른 줍기 시트(4-6)에서 돌아올 때 · **이탈** 사진 촬영(4-4) · 빠른 줍기 시트(4-6) · 크루 채팅(3-7) · 활동 중인 크루원 목록(2-2) · 활동 종료 요약(4-7). 뒤로 가기는 활동을 끝내지 않는다 — 화면만 접는다

## 배치

옛 XML 의 겹침 순서(전체 지도 → 상단 오버레이[라벨 줄·지표 카드·경고 칩] → 왼쪽 아래 수거 알약 → 하단 바[왼쪽·가운데 촬영·오른쪽])를 그대로 따른다. 지도가 화면 전체를 채우고 나머지는 그 위에 뜬다. 하단 탭은 이 화면에서 숨기고 자체 하단 바가 그 자리를 쓴다(옛 화면과 같다). 지표 카드가 3칸에서 4칸이 됐고, 경고 칩 자리는 상황에 따라 다른 배너 하나가 들어오는 슬롯이다. 스크롤하지 않는다.

위치 점 하나가 들어올 때 하는 일(기능범위 "위치 품질"). 여기서 떨어진 점은 지도·거리·소켓 어디에도 쓰지 않는다.

| 순서 | 검사 | 떨어지면 |
|---|---|---|
| 1 | 오차 반경 30m 초과 | 버림. 15초 넘게 이어지면 ④ "GPS 불안정" |
| 2 | 직전 통과 점 대비 초속 5m 초과 이동 | 버림 |
| 3 | 최근 3~5점 평균으로 평활화 | (항상 통과) 평활화된 점을 경로·거리에 쓴다 |
| 4 | GPS 누적 거리가 걸음×0.7m 보다 30% 넘게 큼 | 표시·전송 거리는 걸음수 거리. 경로 선은 그대로 |

통과한 점은 5초마다 소켓 `/app/crew/live` 로 보낸다(`activityId`·`location`·`distanceM`·`itemCount`·`elapsedSec`·`paused`). 위치 공유를 끈 활동은 `location` 을 null 로, 나머지는 그대로 보낸다. 앱이 배경에서 소켓을 잃으면 같은 몸을 `POST /activities/{id}/live` 로 보낸다.

## 인터랙션

- 스크롤: 없음. 지도만 드래그·확대·축소된다. 지도를 옮기면 내 위치 따라가기가 풀리고 ⑤ 가 나타난다
- 당겨서 새로고침: 없음(지도 드래그와 겹친다). 크루원은 복귀 때마다 조용히 다시 받는다
- 길게 누르기: 없음
- 시트: 4-6 빠른 줍기 시트가 이 화면 위에 뜬다. 시트 뒤로 지도·지표가 보이고 시간은 계속 흐른다
- 뒤로 가기: 활동을 끝내지 않는다. 화면을 접고 직전에 있던 하단 탭 화면(없으면 2-1 홈)으로 돌아간다. 하단 탭 줍깅에 배지가 켜지고 누르면 4-3 으로 돌아온다. ⑧ 이 떠 있으면 대화상자만 닫는다(계속 줍기와 같다). 말풍선이 떠 있으면 말풍선만 닫는다. 종료 전송 중엔 무시
- 키보드: 없음
- 화면 꺼짐: 4-3 이 앞에 있는 동안은 화면이 자동으로 꺼지지 않는다. 다른 화면으로 가면 OS 기본으로 돌아간다. 꺼져도 추적은 이어진다(배경 상태)
- 일시정지/재개: 누르는 즉시 바뀐다(응답 대기 없음). 재개하면 "위치를 찾고 있어요" 부터 다시 시작하고, 재개 지점부터 새 경로 선을 그린다
- 종료: [활동 종료] → ⑧ → [종료하기] → `POST /activities/{id}/end` → 성공하면 추적·소켓·⑨ 를 즉시 끄고 4-7 로 간다. 4-3 은 스택에서 지운다 — 4-7 에서 뒤로 가기로 활동 중 화면에 돌아오지 않는다. 줍기 0개여도 그대로 종료된다(빈 기록 안내는 4-7 이 한다)
- 크루원 마커 탭: 말풍선 3초. 다른 마커를 탭하면 바로 옮겨 간다
- 전환: 4-4 · 3-7 · 2-2 푸시(뒤로 가기로 4-3 복귀, 시간은 그동안 흐른다). 4-6 시트. 4-7 은 4-3 을 대체. 배너·칩은 나타나고 사라질 때만 짧게 페이드

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 지도: "지도, 내 경로와 활동 중인 크루원". 경로 선·내 위치 점은 읽지 않는다
  - 크루원 마커: "상혁, 1.2km, 9개" · 일시정지면 "상혁, 일시정지 중, 1.2km, 9개". 탭 힌트 "자세히 들으려면 두 번 탭"
  - ② 위치 공유 칩: "위치 공유 중" / "위치 공유 꺼짐" 그대로
  - ② 크루원 알약: "활동 중인 크루원 2명, 목록 보기"
  - ② 활동 종료: "활동 종료"
  - ③ 지표 카드: 한 요소로 묶어 "줍기 17개, 활동 시간 42분 10초, 이동 거리 2.1킬로미터, 3200걸음". 초 단위 갱신은 읽지 않는다(live region 아님) — 걸음 "—" 는 "걸음수 없음"
  - ④ 배너: 나타나는 순간 문구를 읽어 준다(live region). 위치 꺼짐 배너의 버튼은 "위치 설정 열기"
  - ⑤: "내 위치로 이동"
  - ⑥: "줍기 17개, 빠른 줍기 열기"
  - ⑦ 채팅: "크루 채팅, 읽지 않은 메시지 있음" / 점이 없으면 "크루 채팅" · 촬영: "쓰레기 촬영" · 일시정지: "일시정지" / "재개"
  - ⑧: 뜨는 순간 제목과 본문을 읽어 준다. 초점은 [계속 줍기] 에 먼저
  - ⑨: 제목·본문이 알림 그대로 읽힌다
- 최소 터치 크기 예외: ② 칩 세 개는 sm 알약이라 보이는 높이가 44dp 보다 작다 — 위아래 여백까지 터치 영역에 넣는다. ⑦ 채팅·일시정지 원은 44dp, 촬영은 그보다 크다. 크루원 마커는 `Avatar` sm 이라 작다 — 마커 주변 44dp 를 터치 영역으로 잡고, 겹치면 위에 그려진 것이 받는다

## 옛 화면과의 차이

- 모임 라벨(`activityLabel`, "1인 모임"/모임 이름) → 위치 공유 칩. 활동은 항상 개인 단위라 모임 이름이 없다
- 멤버 알약(`memberPill`, "멤버 N") → 활동 중인 크루원 알약("크루원 N"). 수의 출처가 방 인원에서 `GET /crew/live` 로 바뀌고 항상 보인다(옛 화면은 1인이면 숨김)
- 지표(`view_metric_row`) 3칸 "수거 개수 · 활동 시간 · 이동 거리" → 4칸 "줍기 개수 · 활동 시간 · 이동 거리 · 걸음". 용어 수거→줍기
- GPS 칩(`gpsChip`) 하나 → 검색 중 · 불안정 · 위치 꺼짐 세 가지. 불안정 문구는 그대로
- 오프라인 칩 "📴 오프라인 · 촬영과 직접 분류만 가능해요" → "📴 오프라인 · 기록은 계속돼요. 연결되면 보내요". 빠른 줍기가 오프라인에도 기록되기 때문
- 수거 알약(`pickupChip`, "수거 N개" + 미분류 배지) → 줍기 알약 "줍기 N개". 미분류 배지(`unclassBadge`)는 없음 — 4-5 에서 분류를 확인한 뒤 저장하므로 미분류가 생기지 않는다. 누르면 수거 목록 시트(`sheet_pickup`)가 아니라 4-6 빠른 줍기 시트
- 하단 바 왼쪽 그룹(`groupButton`, 참여 요청 점) → 채팅(읽지 않음 점). 오른쪽 마이크·음소거(`voiceButton`) → 일시정지/재개. 가운데 촬영은 그대로
- 참여 요청·멤버 관리(신고·차단) 시트, 음성 통화 안내 문구는 모두 없음(함께줍깅·무전 끔)
- 종료 확인 문구는 1인용 본문(`act_end_body_solo`)만 남기고 모임용(`act_end_body_group`)은 뺐다. 버튼 "계속 줍기"·"종료하기" 그대로
- 내 위치로 버튼(`mapMyLocation`)은 옛 레이아웃에 있었으나 이 화면에서 켰는지 확실치 않다. 새 화면은 따라가기가 풀렸을 때만 보인다
- 배경 알림창·화면 꺼짐 방지·위치 필터 4개·걸음수 보정은 새로 정했다

## 미결

- 걸음 칸을 지표 카드에 넣어 4칸으로 한 것은 내 결정이다. 3칸을 유지하고 걸음을 카드 아래 한 줄로 빼는 안도 있다
- 계약의 `Item` 에는 위치가 없어 옛 화면의 수거 지점 마커(`ic_map_marker`, `sheet_point_detail`)를 지도에 그릴 수 없다. 줍기 위치를 남기려면 `POST /activities/{id}/items` 에 위치 필드가 필요하다 — 1차에서 뺄지 계약에 넣을지
- 앱이 죽은 뒤 복구할 때 경로·거리·일시정지 여부는 서버가 모른다(`GET /activities/current` 의 `distanceM` 은 마지막 live 보고 값). 기기 저장에서 되살리는 것으로 썼는데, 기기 저장도 없으면 거리 0 · 경로 없음으로 이어 간다. 이 경우 안내 문구를 넣을지
- 오프라인에서 종료를 막았다. 옛 4-7 은 "동기화 대기 중" 으로 종료를 받았는데, 새 계약은 `POST /activities/{id}/end` 응답(`Activity`)이 있어야 4-7 을 그릴 수 있어 막는 쪽을 택했다. 오프라인 종료를 허용하려면 4-7 이 기기 값으로 그려지고 나중에 보내는 흐름이 필요하다
- 일시정지 시간에 상한이 없다. 몇 시간 일시정지 뒤 방치된 활동을 서버나 앱이 자동 종료할지
- ⑨ 배경 알림창에 일시정지·종료 버튼을 넣을지. 지금은 탭하면 4-3 으로 오는 것만
- 채팅 읽지 않음 점의 출처를 `unreadChat` (`GET /crew`) + 소켓 CHAT 으로 했다. 3-7 을 열고 돌아오면 `POST /crew/chat/read` 뒤 점을 끄는 것으로 가정했다
- 오프라인 상태에서 쌓아 둔 줍기를 보내기 전에 종료하려 하면 어떻게 할지 — 지금은 오프라인 종료 자체를 막아 겹치지 않지만, 연결이 돌아온 직후 순서(줍기 전송 → 종료)는 4-6 과 함께 정해야 한다
- 크루원 마커의 "일시정지 중" 배지 문구가 얼굴 옆에 들어가기엔 길다. 아이콘(⏸)만으로 줄일지
