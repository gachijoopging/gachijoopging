# 5-3 활동 기록 상세

**목적** 한 활동의 거리·시간·줍기 목록·경로를 상세히 본다. 내 활동은 수정하고 삭제할 수 있고, 피드로 공유할 수 있다. 다른 사람의 활동도 볼 수 있지만 경로는 위치 공유를 켠 경우에만 본다.
**원본** `../legacy/android-res/layout/fragment_record_detail.xml` · `sheet_record_items.xml` · **변경** 경로 지도가 정적 이미지로만 보이고 상호작용 없음 · 옛 "위치 공유됨" 표시 대신 `locationShared` 필드 확인 · "편집" 모드와 사진 순서 이동 버튼은 내 활동일 때만 활성
**진입** 5-5 내 정보 기록 카드 · 5-4 타인 프로필 기록 탭 · 4-7 활동 종료 요약 · 5-1·5-2 게시물에 첨부된 활동 chip (링크 버튼으로) · **이탈** 5-2 게시물 상세(링크돼 있으면) · 5-4 크루원 프로필(다른 사람 활동이면) · 뒤로 가기(내 활동)

## 배치

옛 XML 의 세로 순서(헤더 → 지도 → 지표 행 → 카테고리 칩 · "수정" 링크 → 사진 카드 · 썸네일 · 이동 버튼 → 위치 공유 칩 → 공유 버튼)를 그대로 따른다. 헤더와 공유 버튼은 고정이고 나머지는 세로 스크롤한다. 지도 높이 170dp 유지. 사진이 없으면 "사진이 없어요" 문구가 나타난다.

```
┌──────────────────────────────────────┐
│ ① [< 뒤로]  활동 기록 상세    [⋯ 메뉴] │
├──────────────────────────────────────┤
│ ②            (지도 이미지)           │
│              경로 없음 / 경로 ›       │
│                                      │
├──────────────────────────────────────┤
│ ③   27   1시간 8분   3.1km          │
│    개수     시간      거리           │
├──────────────────────────────────────┤
│ ④ [담배꽁초 14] [플라스틱 6] [캔 3]   │
│    ✏️ 줍기 목록 수정                   │  ← 내 활동만
├──────────────────────────────────────┤
│ ⑤ 활동 사진 모음                     │
│   ┌─────────────────────────────┐   │
│   │      (첫 번째 사진)           │ (1/3) │
│   │  [◀ 이전] [다음 ▶]           │   │  ← 내 활동만
│   └─────────────────────────────┘   │
│   ┌───┐┌───┐┌───┐                  │
│   │ 썸 ││ 썸 ││ 썸 │                  │
│   └───┘└───┘└───┘                  │
│   [◀ 앞] [대표] [뒤 ▶]              │  ← 내 활동만, 숨김
│   편의점 사진도 포함돼요.              │
├──────────────────────────────────────┤
│ ⑥ (!) 위치를 공유하지 않은 활동이에요 │  ← 타인·미공유일 때
│   또는 ✅ 피드에 공유된 기록           │
├──────────────────────────────────────┤
│ ⑦ [피드에 공유하기] 또는 [게시글 보기]│
└──────────────────────────────────────┘
```

## 줍기 목록 편집 시트

④ 의 "줍기 목록 수정" 를 누르면 시트가 떠난다. 현장에서 놓친 개수를 조정할 수 있다.

| 요소 | 내용 | 컴포넌트 |
|---|---|---|
| 시트 핸들 | 시트 맨 위 핸들 | `신규` 핸들 (옛 `Gachi.SheetHandle`) |
| 제목 | "줍기 항목 편집" | `Txt` section lg |
| 설명 | "항목을 고치거나 지우면 총 개수와 분류 요약이 자동으로 다시 계산돼요." | `Txt` body |
| 항목 리스트 | `items` (`GET /activities/{id}`) 각각 한 행. 형식: "[카테고리명] N [개] [AI/직접] [×]" | 리스트 아이템 |
| 항목 — 카테고리 | 카테고리 이름. 한국어로 표기. 탭 불가(이 시트에선 카테고리 변경 없음) | `Txt` body |

| 항목 — 출처 | "AI가 찾음" 또는 "직접 추가". 읽기 전용 | `Txt` micro |

## 인터랙션

- 스크롤: ①②⑥⑦ 헤더와 공유 버튼은 고정, ③④⑤ 만 세로 스크롤(옛 XML 의 `ScrollView`)
- 당겨서 새로고침: 없음. 이전 화면에서 진입할 때만 갱신한다
- 길게 누르기: 없음
- 시트: ④ "줍기 목록 수정" 누르면 줍기 편집 시트. ① ⋯ 메뉴도 시트(또는 메뉴 다이얼로그)
- 뒤로 가기: 진입 출처로 돌아간다 (5-5 · 5-4 · 4-7 · 5-1/5-2 링크 등). 대화상자 또는 시트가 떠 있으면 먼저 닫는다
- 키보드: 줍기 편집 시트에서 수량 입력 필드에만 숫자 키보드
- 사진 네비게이션: 이전·다음 버튼 또는 썸네일 탭으로 사진 이동(내 활동일 때만)
- 전환: 5-2 · 5-4 · 5-6 · 6-1 모두 푸시. 대화상자·시트는 모달

## 옛 화면과의 차이

- 옛 화면은 M25 "기록 상세". 개념은 그대로지만 기능이 줄었다
- 경로 지도: 옛 `view_map_frame` (카카오맵 SDK, 상호작용 지원) → 정적 이미지. 전체화면 지도·즐겨찾기 버튼·GPS 약함 배너는 없음(지도 기능이 축소됐다)
- 대표 사진 순서 이동: 옛 [◀ 앞] [대표] [뒤 ▶] 버튼과 주석은 그대로이지만 내 활동일 때만 보인다
- 줍기 목록 수정: 옛 화면에서 분리된 시트로 정식화됐다. 옛 화면의 "줍기 항목" 섹션과 수정 버튼이 시트로 대체되고 모달이 된다
- 위치 공유 칩: 옛 "✅ 위치 공유됨" (고정) → `locationShared` 값에 따라 "✅ 피드에 공유됨"(내 활동, 게시물 링크) · "경고 위치를 공유하지 않은 활동이에요"(미공유)로 조건부 표시
- 공유 버튼: 옛 "피드에 공유하기" 유지. 이미 공유된 경우 "게시글 보기 →"로 바뀐다
- 구분: 옛 화면에서 내 활동·타인 활동 구분이 없었다. 새 앱에서는 `GET /users/me` 와 비교해 권한에 따라 버튼·메뉴 활성화를 다르게 한다
- 삭제 확인 문구: 옛 "이 기록에 연결된 게시글의 기록 카드도 함께 사라져요" 제거. 게시물은 활동과 독립이고 활동 요약은 첨부된 이미지일 뿐이다
- 빈 상태 표시: 줍기가 0일 때도 화면을 띄운다. 옛 화면처럼 경고 칩 "수거 기록 없음"을 보인다

## 미결

- **내 활동 vs 타인 활동의 판정:** `GET /activities/{id}` 응답의 `user.id` 와 `GET /users/me` 의 `id` 를 비교해 권한을 정한다고 했지만, 파라미터 전달·화면 진입 경로에 따라 앱 로직이 달라질 수 있다. 구체적 판정 시점(URL 진입 시 vs API 응답 후) 확인 필요
- **사진 순서 이동의 API:** 옛 XML 에 [◀ 앞] [대표] [뒤 ▶] 버튼이 있으나 백엔드 API 가 정의돼 있지 않다. 사진 순서 저장 방식(PUT · PATCH · POST 등) 확인 필요
- **줍기 항목 편집 API:** 시트에서 수량을 수정해 [수정 저장]을 누르면 단일 항목 수정 PATCH · 다중 항목 배치 vs 어느 방식으로 보낼지(옛 화면의 주석 "총개수는 항목에서 파생") 확인 필요. 현재 `PATCH /activities/{id}/items/{itemId}` 가 있으나 시트 전체 저장 방식 명시 필요
- **게시물 링크 판정:** 활동이 피드에 공유되었는지 확인하려면 활동 ID 로 Post 를 역조회해야 하는데, 계약에 그 경로가 없다. `GET /activities/{id}` 응답에 `linkedPostId` 같은 필드를 추가할지, 아니면 앱이 POST 목록에서 찾을지 확인 필요
- **타인 활동의 신고:** 메뉴 [신고]를 누르면 6-1 신고 화면으로 간다고 했지만, 신고 대상이 사용자인지 활동인지 구분이 필요할 수 있다. 6-1 에서 명시 필요
- **정렬·커서:** 활동 목록에서 이 화면으로 진입할 때 데이터는 이미 목록에서 받아 뒀으므로 커서 필요 없지만, 5-5 내 정보에서 활동 목록이 커서 기반(20개씩)일 경우 상세 화면에서 이전 목록으로 돌아올 때 위치를 기억해야 할지 확인 필요
