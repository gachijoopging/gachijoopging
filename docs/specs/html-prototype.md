# HTML 프로토타입 명세

## 산출물

| 경로 | 내용 |
|---|---|
| `prototype/gachijoopging.html` | CSS·JavaScript를 모두 포함한 독립 실행 HTML |
| `docs/prd/html-prototype.md` | 목적·범위·성공 기준 |
| 이 문서 | 제작·검증 계약 |

HTML은 외부 스크립트·스타일·폰트·이미지·API를 요청하지 않는다. 브라우저에서 `file://`로 직접 연다.

## 정본과 우선순위

1. `docs/화면설계/<번호>-<이름>.md`: 화면별 배치·요소·상태·인터랙션·접근성.
2. `docs/화면.md`: 화면 색인·이동 지도·공통 규칙.
3. `CONTEXT.md`: 화면 문구의 용어.
4. `docs/기능범위.md`: 권한·제품 정책.
5. `design-system/tokens/`, `design-system/src/components/`: 색·타이포·간격·반경·부품 의도.

HTML과 정본이 충돌하면 정본을 고치거나 HTML을 맞춘다. 새 문서에 화면 정책을 중복 기록하지 않는다.

## 화면 레지스트리

HTML 안 한 레지스트리가 아래 필드를 가진다.

| 필드 | 의미 |
|---|---|
| `id` | 화면 번호. 예: `4-3` |
| `name` | 색인과 같은 화면 이름 |
| `spec` | 대응 `docs/화면설계/` 상대 경로 |
| `render` | 화면 본문을 그리는 함수 |

등록 화면은 아래 43개다.

| 영역 | 화면 |
|---|---|
| 온보딩 | 1-1 시작 · 1-2 로그인 · 1-3 회원가입 · 1-4 소셜 첫 가입 닉네임 · 1-5 비밀번호 재설정·확인 · 1-6 크루 만들기/가입하기 · 1-7 크루 만들기 · 1-8 초대 코드 입력 · 1-9 승인 대기 · 1-10 위치 권한 안내 |
| 홈 | 2-1 홈 · 2-2 활동 중인 크루원 목록 · 2-3 알림 목록 |
| 모이깅 | 3-1 모이깅 · 3-2 크루 정보 · 3-3 초대 코드 · 3-4 크루 기록 · 3-5 공지 목록 · 3-6 공지 상세 · 3-7 크루 채팅 · 3-8 가입 신청 관리 · 3-9 활동 달력 · 3-10 크루 정보 수정 · 3-11 크루원 목록·관리 · 3-12 공지 작성·수정 |
| 줍깅 | 4-1 줍깅 대기 · 4-2 활동 시작 시트 · 4-3 활동 중 · 4-4 사진 촬영 · 4-5 AI 분류 확인 · 4-6 빠른 줍기 시트 · 4-7 활동 종료 요약 |
| 피드·내 정보 | 5-1 피드 · 5-2 게시물 상세 · 5-3 활동 기록 상세 · 5-4 타인 프로필 · 5-5 내 정보 · 5-6 게시물 작성 · 5-7 설정 · 5-8 프로필 수정 · 5-9 차단 관리 |
| 안전 | 6-1 신고 · 6-2 신고 처리 |

각 화면은 헤더 또는 검토 패널에 `id`, `name`, `spec`을 표시한다.

## 화면 전환

- 하단 탭은 홈(2-1)·피드(5-1)·줍깅 대기(4-1)·모이깅(3-1)·내 정보(5-5)로 간다.
- 주요 CTA와 목록 항목은 각 대응 화면설계서의 `탭하면`·`이탈`을 따른다.
- 시트는 현재 화면 위에 열며, 닫으면 같은 화면으로 돌아간다.
- 뒤로가기는 직전 화면으로 돌아간다. 이력이 없으면 시작 화면(1-1)으로 간다.
- 신고는 대상 미리보기와 함께 6-1로 가며, 처리는 크루장 역할에서 6-2로 간다.
- URL 라우팅, 브라우저 저장소, 서버 상태는 사용하지 않는다.

## 역할·목 데이터

상단 검토 제어에서 역할을 `크루원`과 `크루장`으로 바꾼다.

- 역할 전환은 버튼 노출만 바꾼다.
- 크루원은 크루장 전용 관리·공지 작성·신고 처리·CSV 내보내기 버튼을 보지 않는다.
- 크루장은 해당 버튼을 보고 관련 화면으로 이동할 수 있다.
- 목 데이터는 크루, 크루원, 활동, 줍기, 게시물, 공지, 채팅, 알림, 신고에 필요한 고정 예시값만 둔다.
- 입력처럼 보이는 요소는 화면 모양을 확인하는 용도이며 저장하지 않는다.

## 상태

화면설계서가 정의한 상태만 상태 제어에서 전환한다.

| 상태 | 표현 |
|---|---|
| 기본 | 고정 목 데이터 |
| 로딩 | 본문 자리표시자 |
| 빈 | 해당 기능의 빈 상태 |
| 오류/재시도 | 오류 설명과 재시도 버튼 |
| 오프라인 | 보존된 목 데이터와 오프라인 안내 |
| 권한 거부 | 위치·알림 등 권한 안내 |
| 제출 중 | 버튼 비활성 및 진행 표시 |

상태 제어는 네트워크 요청·타이머·실제 권한을 사용하지 않는다.

## 시각 규칙

- 390×844 기준 앱 프레임에서 검토한다.
- `design-system`의 토큰과 부품 의도를 따른다. HTML 구현은 React Native 컴포넌트를 가져오지 않는다.
- `Screen`의 안전 영역·스크롤 의도를 재현한다.
- 누를 수 있는 제어는 48dp 이상으로 보인다.
- 지도·카메라·AI는 정적 플레이스홀더다.

## 화면별 수용 기준

모든 43개 화면은 다음을 만족한다.

1. 레지스트리에 번호·이름·설계서 경로로 등록된다.
2. 대응 화면설계서의 기본 배치와 핵심 요소를 표현한다.
3. 설계서에 적힌 주요 이탈 또는 시트를 최소 하나 이상 클릭으로 확인한다.
4. 관련 역할 제한과 필수 상태를 확인할 수 있다.
5. 화면 정책이 부족하거나 모순되면 임의로 보완하지 않고 해당 화면설계서 이슈로 남긴다.

## 검증

1. `prototype/gachijoopging.html`을 파일 탐색기에서 열고 화면을 확인한다.
2. 43개 레지스트리 항목을 각각 열어 번호·설계서 경로를 확인한다.
3. 크루원·크루장 역할을 전환해 관리 버튼 차이를 확인한다.
4. 하단 탭, 주요 CTA, 시트, 뒤로가기, 신고 흐름을 확인한다.
5. 브라우저 개발자 도구 Network 탭에 외부 요청이 없는지 확인한다.
