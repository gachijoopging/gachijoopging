# 디자인 시스템 보완 설계

## 결정과 근거

- `docs/screens/`의 43개 화면 명세가 제품·UX의 정본이다.
- `mobile/legacy-387996e3-20260813.apk`와 `docs/legacy/android-res/`는 기존 시각 언어의 근거다. 문서와 충돌하면 문서를 따른다.
- 화면 명세에 문서화되지 않은 시각 결정은 구현 전에 사용자에게 확인한다.
- 기존 토큰(라이트/다크 색, 간격, 반경, Pretendard, 그림자)은 APK와 일치하므로 유지한다.

## 화면 대조 방법

각 화면 요소를 아래 다섯 상태 중 하나로 기록한다.

| 상태 | 처리 |
|---|---|
| 동일 | 현재 디자인 시스템을 그대로 사용한다. |
| 변형 필요 | 기존 컴포넌트에 문서·APK 근거가 있는 변형을 추가한다. |
| 공통 신규 | 범용 API와 접근성 규칙이 여러 화면에 반복되면 디자인 시스템에 추가한다. |
| 기능 공용 | 도메인 데이터나 업무 규칙에 묶였지만 여러 화면에서 반복되면 기능 폴더에 둔다. |
| 화면 전용 | 한 화면에서만 쓰는 배치·업무 조합으로 남긴다. |

APK와 다른 신규 화면도 같은 방식으로 판정한다. 문서가 화면의 목적·배치·상태·접근성을 정하고, APK는 토큰과 재사용 가능한 시각 패턴만 제공한다.

## 디자인 시스템 경계

### Foundations

기존 `tokens/`와 `theme.tsx`를 유지한다. APK 리소스 대조와 현재 대비 검사가 이미 보장하는 색상·간격·반경·타이포·그림자 계약은 바꾸지 않는다.

### Components

다음은 화면 명세와 APK에서 반복되는 범용 부품이므로 공개 API로 제공한다.

| 부품 | 근거와 책임 |
|---|---|
| `IconButton` | 48dp 이상 터치 영역, 접근 가능한 라벨, plain/surface/tint/lime/translucent 배경. 헤더, 사진, 지도, 채팅의 원형 액션을 통일한다. |
| `AppHeader` | 뒤로가기, 제목, 선택 부제, 선택 액션의 고정 헤더. 기존 `view_screen_header`의 구조를 따른다. |
| `BottomNav` 보완 | 홈·피드·모이깅·내 정보의 네 목적지와 가운데 돌출 `줍깅` 액션을 분리한다. 현재 균등 탭 구현을 그대로 확장하지 않는다. |
| `Switch` | 제어형 checked/disabled/onChange와 스크린리더 상태를 제공한다. 행 전체가 토글하는 경우에는 부모가 상호작용을 소유한다. |
| `Checkbox` | 필수·선택 동의에 쓰는 제어형 체크 상태와 48dp 터치 영역을 제공한다. |
| `Field` 보완 | `endAdornment`를 위한 별도 영역을 두어 비밀번호 보기 칩이 입력 글자를 가리지 않게 한다. |
| `Button` 보완 | 문서·APK에 있는 translucent, deep, danger, ghost-danger 변형을 추가한다. 기존 primary/soft/kakao/ghost 계약은 유지한다. |
| `Chip` 보완 | 정적 deep 톤을 추가한다. 선택 상태와 별개로 쓸 수 있어야 한다. |
| `Avatar` 보완 | 대표 사진용 `xl`을 96dp로 추가한다. 기존 sm/md/lg 값은 유지한다. |
| `NumberStepper` | 3-10, 4-5, 4-6에서 반복되는 직접 수량 입력과 증감 조작을 제어형 API로 제공한다. min/max, disabled, 접근성 라벨을 받는다. |

`Card`, `Tile`, `Tabs`, `ListRow`, `Banner`, `Progress`, `BottomSheet`, `Dialog`, `Snackbar`, 상태 UI는 유지한다. 설정 행의 원형 아이콘과 Switch는 `ListRow`의 left/right 슬롯으로 조합하며, 설정 전용 컴포넌트를 추가하지 않는다.

### Layout recipes

디자인 시스템은 화면 전체를 대신 렌더링하지 않는다. 대신 README와 카탈로그에 다음 조립 규칙을 제공한다.

1. **Root tab**: `Screen` 본문과 보이는 `BottomNav`의 안전 영역·하단 여백을 분리한다.
2. **Sub-screen**: `AppHeader`는 고정하고 본문만 스크롤한다. 작은 화면·큰 글씨에서는 장식과 미리보기부터 줄이며 글자와 터치 영역은 줄이지 않는다.
3. **Form**: 한 열 `Field` 묶음, 인라인 오류, 키보드 회피, 제출 중 중복 조작 잠금을 쓴다.
4. **List/detail**: 목록은 `List`, 빈/오류는 `EmptyState`/`ErrorState`, 새로고침 실패는 기존 값을 남기고 `Snackbar`로 알린다.
5. **Overlay**: 선택·보조 행동은 `BottomSheet`, 되돌릴 수 없는 행동은 `Dialog`, 완료·실패 피드백은 `Snackbar`를 쓴다.
6. **Metrics**: 3~4개 지표는 `Tile`과 텍스트를 조합한다. 세로 점선·열 수는 화면 요구에 따라 레시피로만 제공한다.

### UX contracts

- 모든 조작은 48dp 이상이며 아이콘 단독 버튼에는 읽을 라벨을 준다.
- 로딩·빈·오류·오프라인은 화면 명세의 상태 표를 따른다. 기존 데이터가 있으면 오류나 오프라인에서 흐리거나 지우지 않는다.
- 폼 오류는 해당 `Field` 아래에, 요청 실패는 `Banner` 또는 `Snackbar`에 표시한다.
- 저장·전송 중에는 같은 요청을 중복 실행하지 않으며, 필요한 경우 값과 준비된 미디어를 보존한다.
- 대화상자는 파괴적이거나 진행을 중단해야 하는 결정에만 쓴다.

## 디자인 시스템 밖의 재사용

다음은 범용 시각 부품이 아니므로 디자인 시스템에 넣지 않는다.

| 위치 | 대상 |
|---|---|
| 활동 기능 공용 | 활동 달력, ActivityCard, 활동 지표 조합, 카테고리 카드, 지도 표시 |
| 미디어 기능 공용 | 사진 프레임, 썸네일 정렬, 사진 페이저, 선택기 연결 |
| 채팅 기능 공용 | 말풍선, 날짜 구분, 전송 대기·재시도 행 |
| 화면 전용 | 홈 스파크라인·캐릭터, 신고 대상 미리보기 등 |

이들은 `Card`, `Tile`, `IconButton`, `NumberStepper` 등 디자인 시스템의 공개 부품을 조합한다.

## 문서와 카탈로그

- `docs/screens/`의 `신규` 표기는 구현 후 실제 공통 컴포넌트 이름 또는 기능 공용 조합으로 바꾼다.
- `design-system/README.md`에는 foundations, components, layout recipes, UX contracts와 경계를 기록한다.
- `Catalog.tsx`에는 신규·변경 컴포넌트의 기본, 선택, 비활성, 오류 상태를 추가한다.

## 검증과 완료 조건

1. `python docs/screens/check.py`가 모든 화면 명세에서 통과한다.
2. `npm test`의 대비 불변식과 `npm run typecheck`가 통과한다.
3. 카탈로그에서 신규 변형과 상태를 수동 확인한다.
4. APK와 대조할 대표 장면은 시작, 입력 폼, 하단 내비, 설정 토글, 활동 수량 입력, 채팅 입력, 프로필 지표다.
5. 화면 대조표에서 모든 항목이 동일·변형 필요·공통 신규·기능 공용·화면 전용 중 하나로 분류되고, 문서 미결은 사용자 결정으로 해소된다.

## 구현 순서

1. 화면 대조표를 완성하고 미결을 해소한다.
2. foundations를 재검증하고 공통 컴포넌트·변형을 추가한다.
3. layout recipes와 UX contracts를 README·Catalog에 반영한다.
4. 화면 명세의 컴포넌트 참조를 갱신한다.
5. 자동 검사와 대표 장면 시각 검증을 수행한다.
