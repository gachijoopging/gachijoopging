# 3-7 크루 채팅

**목적** 크루원 모두가 한 방에서 대화한다. 크루가 있는 동안 이어지는 하나의 방이다.
**원본** `../legacy/android-res/layout/fragment_chat.xml` (`item_chat_message.xml` · `item_chat_notice.xml`) · **변경** 모임 채팅방 → 크루 채팅. 폴링 → 소켓. 옛 앱에 없던 전송 중·실패, 끊김 배너, 새 메시지 알약, 신고를 넣었다
**진입** 모이깅(3-1)의 채팅 카드 · 활동 중(4-3)의 채팅 버튼 · 알림 목록(2-3)의 CHAT 알림 · **이탈** 얼굴·이름을 탭하면 타인 프로필(5-4) · 길게 눌러 신고(6-1) · 뒤로 가기

## 배치

옛 XML 의 세로 순서(헤더 → 메시지 목록 → 입력 줄)를 그대로 따른다. 헤더는 고정, 목록이 남는 높이를 모두 쓰고 아래에 입력 줄이 붙는다. 목록은 아래가 최신이며 처음 열면 맨 아래에 있다. 위로 올리면 이전 메시지를 더 받는다. 끊김 배너 ② 와 새 메시지 알약 ④ 는 평소 숨김이다.

메시지 이력과 실시간은 이렇게 잇는다.

| 순서 | 하는 것 | 결과 |
|---|---|---|
| 1 | 화면이 뜨면 `GET /crew/chat/messages` (`limit` 50, `beforeSeq` 없음) | 최신 50개. `seq` 오름차순으로 위→아래. 맨 아래로 스크롤 |
| 2 | 소켓 구독 `/user/queue/crew` 의 CHAT · CHAT_DELETED 만 쓴다(LIVE_*·NOTIFICATION 은 이 화면과 무관) | 새 메시지는 아래에 붙는다. 같은 `id` 가 이미 있으면(내가 보낸 echo) 전송 중 표시를 시각으로 바꾼다 |
| 3 | 위로 올려 첫 메시지가 보이면 `GET /crew/chat/messages` (`beforeSeq` = 가장 작은 `seq`, `limit` 50) | 위에 붙인다. 스크롤 위치는 보던 메시지에 고정. `hasMore` false 면 더 부르지 않는다 |
| 4 | 재연결 뒤 `GET /crew/chat/messages` (`afterSeq` = 가장 큰 `seq`, `limit` 50) | 빈 구간을 아래에 붙인다. `hasMore` true 면 마지막 `seq` 로 반복 |
| 5 | 읽음 표시 `PUT /crew/chat/read` (`lastSeq` = 화면에 보인 가장 큰 `seq`) | 1 이 끝난 직후 · 목록이 맨 아래에 있는 채로 새 메시지가 왔을 때 · 화면을 떠날 때. 1초 안에 여러 번이면 마지막 한 번만. 실패해도 아무것도 띄우지 않는다(다음 기회에 다시 보낸다) |

읽음 표시는 3-1 의 `unreadChat` (`GET /crew`) 와 홈 배지를 줄이기 위한 것이다. 이 화면 안에는 읽음 위치 구분선을 추가하지 않는다.

차단한 사람의 개인 메시지는 차단한 사람의 화면에서만 숨긴다. 서버는 이력·소켓을 필터링하고 앱도 차단 즉시 기존 목록·캐시에서 숨겨 화면 복귀나 재조회까지 기다리지 않는다. 반대 방향의 숨김은 만들지 않는다. 공식 공지와 크루장에게 필요한 신고 관리 정보는 유지한다.

## 인터랙션

- 스크롤: 세로. 아래가 최신이며 처음엔 맨 아래. 위로 올려 첫 메시지가 보이면 `beforeSeq` 로 50개를 더 받아 위에 붙이고, 보던 메시지의 화면 위치는 그대로 둔다. 목록이 맨 아래에 있으면 새 메시지가 올 때 자동으로 따라 내려간다. 떨어져 있으면 따라가지 않고 ④ 알약을 띄운다. 내가 보낸 메시지는 어디에 있었든 맨 아래로 간다
- 당겨서 새로고침: 없음. 소켓이 대신한다
- 길게 누르기: 상대 말풍선 — 크루원이면 시트 [신고하기] → 6-1 신고(`targetType` CHAT_MESSAGE, `targetId` = 메시지 `id`). 내 말풍선 — 실패 상태는 같은 id 재시도만 제공한다. 정상 전송된 내 메시지는 길게 눌러도 아무 일 없다. 지워진 메시지·탈퇴한 크루원의 메시지는 길게 눌러도 아무 일 없다
- 시트: 상대 메시지 신고 시트만. 배경을 탭하거나 뒤로 가기로 닫는다
- 뒤로 가기: 진입한 화면(3-1 · 4-3 · 2-3)으로 돌아간다. 시트가 떠 있으면 시트만 닫는다. 키보드가 떠 있으면 키보드만 내린다. 입력에 글이 남아 있으면 계정·크루별 초안을 보존하고, 다시 열 때 복원한다. 전송 중·실패 메시지는 화면을 떠나도 큐에 남아 다시 들어오면 그 상태로 보인다
- 키보드: 입력을 탭하면 키보드가 올라오고 목록·입력 줄이 함께 밀려 올라간다(마지막 메시지가 가려지지 않는다). 엔터는 줄바꿈이고 보내기는 버튼으로만 한다. 보내기 뒤에도 키보드는 내려가지 않는다. 목록을 드래그하면 키보드가 내려간다. 500자에 닿으면 더 입력되지 않는다
- 배경 전환: OS 정책에 따라 소켓이 끊길 수 있다. 끊겼으면 돌아올 때 "연결 중…" 을 잠깐 보이고 재연결 순서를 탄다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로"
  - 부제: "크루원 18명"
  - ② 배너: 나타나는 순간 "연결 중" 을 읽어 준다(live region). 복구 스낵바도 읽어 준다
  - 메시지 한 건은 한 요소로 묶는다. 상대: "상혁, 내일 여의도 9시 어때요?, 오후 3시 24분". 나: "나, 좋아요 갈게요, 오후 3시 25분". 전송 중: "…, 전송 중". 실패: "…, 전송 실패, 다시 보내려면 두 번 탭". 지워진 것: "상혁, 삭제된 메시지"
  - 얼굴: "상혁, 프로필 보기". 이름과 얼굴은 한 요소로 묶는다
  - 날짜 구분선: 본문 그대로 읽는다
  - ④ 알약: "새 메시지, 맨 아래로 이동". 나타나는 순간 "새 메시지가 도착했어요" 를 읽어 준다(live region). 새 메시지 본문을 자동으로 읽지는 않는다
  - ⑤ 입력: "메시지 입력". 남은 글자는 400자를 넘은 뒤부터 "487자, 500자 중" 으로 읽는다
  - 보내기: "보내기". 비활성일 때 "보내기, 비활성" 
  - 말풍선 모양·종이비행기·"!" 아이콘: 장식이라 읽지 않는다
- 최소 터치 크기 예외: 상대 얼굴이 30dp 라 이름까지 한 터치 영역으로 묶어 48dp 를 채운다. 보내기는 48dp. 시각·전송 상태 글자는 눌리는 요소가 아니라 예외 없음. "다시 보내기" 는 말풍선 전체가 터치 영역이다

## 옛 화면과의 차이

- 제목 "단체 채팅방" · 부제 "멤버 N명" → "크루 채팅" · "크루원 N명"(`memberCount`). 방이 모임마다 있었는데 이제 크루에 하나다
- 옛 화면의 시작 안내 "모임 멤버만 참여하는 채팅방이에요" 를 없앴다
- 폴링(`GET /meets/{id}/messages`) → 소켓. 그래서 생긴 것: 끊김 배너 ② · 전송 중·실패 표시 · 새 메시지 알약 ④ · 재연결 뒤 `afterSeq` 로 빈 구간 채우기
- 옛 `item_chat_message` 는 상대 말풍선 한 벌(`bg_bubble_other`)뿐이고 내 말풍선 drawable(`bg_bubble_me`)은 있었지만 레이아웃이 없었다. 내 말풍선 줄(오른쪽 정렬·얼굴 없음)을 새로 그렸다
- 같은 사람의 연속 메시지에서 얼굴·이름·같은 분의 시각을 생략하는 것은 새로 정했다. 옛 화면은 매 줄 다 보였다
- 날짜 구분선 · 지워진 메시지 자리 · 길게 눌러 신고 · 글자 수 제한(500)과 남은 글자 표시는 새로 생겼다
- 입력 줄 알약 배경 `bg_search_pill` 은 옛 XML 이 참조하지만 drawable 폴더에 파일이 없다. 모양은 `Field` 의 것을 따른다
- 얼굴을 탭하면 타인 프로필로 가는 것은 새로 생겼다(옛 화면은 눌리지 않았다)

- 채팅은 텍스트만 지원하며 이미지·검색·가입/추방 시스템 메시지는 추가하지 않는다.
- CHAT 푸시는 3-7로 직접 진입한다. 소속 변경 등으로 열 수 없으면 이유를 알리고 2-3으로 이동한다.
- 작은 화면·큰 글씨에서는 장식 여백·부제 높이를 먼저 줄인다. 메시지·입력 전체를 읽을 수 있도록 스크롤하며 글자와 48dp 터치 영역을 유지한다.

## 미결

- 전송 실패 타임아웃은 구현 전에 확정할 운영 파라미터다. 백오프는 소켓 계약의 1·2·4·8·최대 30초를 따른다. 큐와 같은 `id`를 보존하고 재연결·수동 재시도에서 중복을 방지한다
- 정상 전송된 내 메시지 직접 삭제는 현재 범위에 없다. 신고 처리 삭제만 지원한다.
- `GET /crew/chat/messages` 의 `hasMore` 가 `afterSeq` 방향에도 같은 뜻인지(더 새로운 것이 있는지) 계약이 말하지 않는다. 그렇게 가정했다
- 알림 CHAT 의 `target.id` 는 방 하나뿐이라 안 쓴다. 특정 메시지로 스크롤하는 요구가 생기면 `target.id` 를 메시지 `seq` 로 쓰기로 정해야 한다
