# 3-12 공지 작성·수정

**목적** 크루장이 제목·본문을 정해 공지를 작성하거나 기존 공지를 수정한다.
**원본** `../legacy/android-res/layout/fragment_publish.xml` · **변경** 사진·활동 요약·공개 범위·명시적 임시 저장 버튼을 없애고 제목·본문만 남겼다. 크루장만 접근한다.
**진입** 3-5 공지 목록의 "작성" · 3-6 공지 상세의 "수정" · **이탈** 작성 성공 → 3-6 공지 상세 · 수정 성공 → 3-6 공지 상세 · 뒤로 가기 → 진입 화면

## 배치

옛 작성 화면의 순서(헤더 → 본문 입력 → 글자 수 → 추가 설정 → 아래 주 버튼)를 따른다. 사진·활동·공개 범위 영역은 제거하고 제목과 본문을 세로로 둔다. 저장 버튼은 화면 아래에 두되 작은 화면에서는 본문과 함께 스크롤할 수 있다.

```
┌──────────────────────────────────────┐
│ ① ‹  공지 작성                        │
├──────────────────────────────────────┤
│ ② 제목                                 │
│    ┌ 9월 정기 활동 안내 ─────────────┐ │
│                         14 / 100      │
│ ③ 내용                                 │
│    ┌ 9월 첫째 주 토요일... ─────────┐ │
│    │                                  │ │
│    └────────────────────────────────┘ │
│                         42 / 3000     │
├──────────────────────────────────────┤
│ ④ [          공지 올리기          ]    │
└──────────────────────────────────────┘
```

수정 모드에서는 ① 제목이 "공지 수정", ④가 "변경사항 저장"으로 바뀌고 현재 `title`·`body`를 채운다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | 작성은 즉시 빈 입력 화면. 수정은 ①은 보이고 ②~④에 `Loading` "공지를 불러오고 있어요" | 뒤로 |
| 작성·수정 전 | 입력값이 유효하지 않거나 수정 모드에서 변경이 없으면 ④ 비활성 | ①~③ |
| 저장 중 | ④ 라벨 자리에 스피너. ①~③ 비활성 | 없음 |
| 새로고침 | **해당 없음.** 입력 중 값을 잃을 수 있어 제공하지 않는다 | — |
| 빈 | **해당 없음.** 빈 입력은 초기 상태이지 목록의 빈 상태가 아니다 | ①~③ |
| 오류 | POST·PATCH 4xx·5xx면 입력값을 보존하고 "공지를 저장하지 못했어요. 다시 시도해 주세요." `Snackbar` | ④ 다시 시도 |
| 오프라인 | 값은 그대로. 유효한 입력이면 ④로 재시도 가능 | ①~④ |
| 권한 거부 | 크루원이 진입하거나 403 FORBIDDEN이면 `ErrorState` "크루장만 공지를 작성할 수 있어요." / [공지 목록으로] | 공지 목록으로 → 3-5 |
| 부분 실패 | **해당 없음.** 공지 텍스트는 하나의 요청으로 저장한다 | — |
| 삭제됨 | 수정 중 404 NOT_FOUND면 "삭제된 공지예요." `Snackbar` 뒤 3-5로 팝한다 | — |

작성 성공: `POST /crew/notices` 201의 `data.id`로 3-6으로 대체 전환하고 `Snackbar` "공지를 올렸어요.".
수정 성공: `PATCH /notices/{noticeId}` 204 뒤 3-6을 새로 받아 `Snackbar` "공지 변경사항을 저장했어요.".

## 인터랙션

- 스크롤: ②~③이 키보드·작은 화면에서 세로 스크롤. 장식·여백부터 줄인 뒤 필요하면 주 버튼까지 스크롤한다. 글자·터치 영역은 줄이지 않는다
- 당겨서 새로고침: 없음
- 길게 누르기: 입력창 OS 기본 붙여넣기
- 시트: 없음
- 뒤로 가기: 계정·크루·공지별 초안을 보존하고 진입 화면으로 팝한다. 다시 진입하면 제목·본문을 복원한다. 별도 임시 저장 버튼은 없다
- 키보드: 제목 완료 키는 본문으로 옮긴다. 본문은 여러 줄이라 엔터가 줄바꿈이고, 저장은 ④로만 한다
- 전환: 성공 뒤 3-6. 3-6에서 뒤로 가면 3-5 목록이 새로고침된다

## 접근성

- ②: "공지 제목, 100자까지, 14자 입력됨"
- ③: "공지 내용, 3000자까지, 42자 입력됨"
- ④: "공지 올리기" 또는 "변경사항 저장", 활성·비활성을 읽는다
- 모든 입력·버튼은 48dp 이상이다

## 옛 화면과의 차이

- 옛 게시물 작성의 사진·활동 요약·공개 범위·게시물의 명시적 임시 저장 버튼을 없앴다. 화면 이동 중 공지 초안은 보존한다
- 공지는 사진 없는 텍스트만 가지며 크루장만 작성한다
- 옛 본문 300자 제한은 공지 본문 3000자로, 새 제목 입력과 100자 제한을 추가했다

- 최신 공지 한 건은 작성 시각 기준으로 자동 표시한다. 고정 입력·수동 고정 요청은 없다.
- 버튼·키보드 저장은 하나의 진행 중 요청을 공유한다. 저장 중 이탈을 취소로 안내하지 않으며, 실패하면 초안을 유지하고 같은 요청으로 재시도한다. 성공을 확인한 뒤에만 초안을 비운다.

## 미결

- 공지 제목·본문 최소 길이는 계약에 없다. 현재는 공백 제거 뒤 각각 1자로 정했다

- 공지 생성 재시도의 중복 방지 키·응답 확인 방식은 API 계약에 명시해야 한다.
