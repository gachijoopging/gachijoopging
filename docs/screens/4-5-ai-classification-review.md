# 4-5 AI 분류 확인

**목적** 방금 찍은 사진에서 AI 가 찾은 쓰레기를 카테고리별 수량으로 보여 주고, 사용자가 고친 뒤 한 번에 줍기로 저장한다.
**원본** `../legacy/android-res/layout/fragment_ai_classify.xml` (후보 줄 `item_ai_candidate.xml`) · **변경** "후보 하나 고르기(라디오) + 직접 분류 칩" → 카테고리 7종 수량 조절(−/+). 사진 한 장에서 찾은 물체를 전부 담는다. 다시 촬영·이대로 담기 두 버튼과 사진·배너 자리는 그대로
**진입** 4-4 사진 촬영에서 `POST /media` 가 200 으로 끝난 직후 — `inference.status` 가 OK 든 UNAVAILABLE 이든 온다 · **이탈** 로컬 대기열 보존 완료 → 4-3 활동 중 · 다시 촬영 → 4-4 · 뒤로 가기 → 버림 확인 뒤 4-3

## 배치

옛 XML 의 세로 순서(헤더 → 사진 카드 → 배너 → "맞게 분류됐나요?" → 후보 목록 → "직접 분류" 칩 → 버튼 줄)를 따른다. 후보 목록과 직접 분류 칩이 하나로 합쳐져 카테고리 7종 2열 격자(4행, 마지막 한 칸)가 됐고 칸마다 수량 조절이 붙었다. 헤더 아래가 세로 스크롤이고 버튼 줄은 스크롤 안 맨 아래에 있다(옛 화면과 같다). 사진이 세로로 길면 최대 520dp 까지만 차지한다.

| 권한 거부 | **해당 없음.** 카메라 권한은 4-4 에서 다룬다. 이 화면은 권한을 쓰지 않는다 | — |
| 부분 실패 | 사진 업로드는 성공했어도 로컬 줍기 보존이 실패할 수 있다. 사진·입력을 유지하고 로컬 저장을 재시도한다. 로컬 보존 후 서버 저장만 실패하면 4-3에서 미동기화 요청을 유지하며 재시도한다 | 실패 단계에 맞는 재시도 |

아래 서버 응답은 로컬 보존 후 이미 복귀한 4-3에서 처리한다(그사이 종료했다면 4-7의 대기 상태에서 처리). 4-5를 다시 열거나 서버 응답 동안 4-5를 막지 않는다. 오류 봉투(`code` · `message` · `requestId`)의 `code` 로 갈린다. `message` 는 화면에 쓰지 않는다.

| 응답 | 보이는 것 |
|---|---|
| 200 | 해당 작업을 동기화 완료로 바꾼다. 응답 `itemCount`·`byCategory`에 아직 미반영인 로컬 작업을 합산해 최신 개수를 유지한다. 이미 로컬 보존 때 더한 수량을 다시 더하거나 담기 알림을 중복 표시하지 않는다 |
| 404 NOT_FOUND | 활동이 이미 끝났거나 없다. `Dialog` "활동이 이미 끝났어요" / "활동 상태를 확인해 주세요. 입력과 미동기화 기록은 기기에 남아 있어요." / [확인] → 4-1 줍깅 대기 |
| 403 FORBIDDEN · 403 NO_CREW | 내 활동이 아니거나 크루가 없다. 같은 다이얼로그 → NO_CREW 면 1-6, FORBIDDEN 이면 4-1 |
| 422 VALIDATION | `Snackbar` "저장하지 못했어요. 수량을 확인해 주세요" |
| 401 TOKEN_EXPIRED | 앱 공통 토큰 갱신 뒤 같은 요청을 다시 보낸다(화면 변화 없음). 갱신도 실패하면 1-1. 입력과 대기열은 원래 계정으로 보존 |
| 429 RATE_LIMITED · 500 INTERNAL · 그 외 | `Snackbar` "저장하지 못했어요" [다시 시도] |

## 인터랙션

- 스크롤: 세로. 헤더 아래 전체(사진·배너·격자·버튼 줄). 사진이 길거나 배너가 있을 때 버튼 줄이 아래로 밀리므로 스크롤한다
- 당겨서 새로고침: 없음
- 길게 누르기: 수량 조절의 − / + 를 길게 누르면 0.3초마다 1씩 이어서 바뀐다. 다른 길게 누르기는 없다
- 시트: 없음
- 뒤로 가기: 헤더 뒤로와 Android 뒤로 모두 `Dialog` "촬영 결과를 버릴까요?" / "입력한 줍기 수량을 버릴까요? 업로드된 사진은 남을 수 있어요." / [계속 분류] · [버리고 돌아가기]. 버리고 돌아가기 → 4-3(이 화면과 4-4 를 스택에서 지운다). 7칸이 모두 0 이고 AI 도 아무것도 안 찾았으면 묻지 않고 바로 4-3 으로. 로컬 대기열 쓰기 중에만 뒤로 가기를 무시한다
- 키보드: 수량 숫자를 누르면 숫자 키패드. 완료로 입력 확정, 뒤로는 키보드부터 닫는다. 입력값과 필드 오류가 키보드 위에 보이도록 스크롤한다
- 수량 조절: 누를 때마다 숫자가 살짝 커졌다 돌아온다. 0 → 1 이 되면 칸 테두리가 진해지고, 1 → 0 이면 옅어진다. AI 가 채운 값을 0 으로 내려도 "AI" 알약은 남는다(그 카테고리는 AI 가 찾았다는 뜻이고, 0 이면 요청에 넣지 않는다)
- 전환: 4-4 → 4-5 는 푸시. 로컬 보존 완료·버리기로 4-3 에 돌아갈 때는 4-4 · 4-5 를 함께 스택에서 지운다. 다시 촬영은 4-5 를 지우고 4-4 로 되돌아간다. 다이얼로그는 모달

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로 버튼: "뒤로"
  - 사진: "방금 촬영한 수거물"(배지 문구를 사진의 설명으로 쓴다). 배지 자체는 따로 읽지 않는다
  - 배너: 나타나는 순간 문구를 읽어 준다(live region). 앞의 이모지(🛠️ 🔍 🤔)는 읽지 않는다
  - 찾은 개수: "AI 가 3개 찾았어요"
  - 카테고리 칸: 카드 이름·현재 수량·AI 상태를 "플라스틱, 2개, 확인 필요"로 안내하고 수량 입력·−·+는 각각 조작 가능한 요소로 노출 · AI 가 아니면 "담배꽁초, 0개". 아이콘은 읽지 않는다
  - − / +: "플라스틱 빼기" · "플라스틱 더하기". 비활성이면 비활성으로 읽힌다. 수량이 바뀌면 새 숫자를 읽어 준다(live region)
  - 이대로 담기: "이대로 담기, 3개". 로컬 쓰기 중엔 "기기에 저장 중" 으로 바뀌고 나머지가 비활성으로 읽힌다
  - 다이얼로그: 제목·본문을 읽고 두 버튼으로 포커스가 간다
- 최소 터치 크기 예외: 없음. − / + 는 각각 48dp. 직접 입력 필드도 최소 48dp이며 2열에서 각 조작 영역이 겹치지 않는다. 사진 높이를 먼저 줄이고 전체 내용 스크롤로 버튼을 노출한다

## 옛 화면과의 차이

- 후보 목록(`candidateList`, `item_ai_candidate` 라디오 줄) + "직접 분류" 칩(`etcRow`) → 카테고리 7종 격자 하나. 고르는 것이 아니라 수량을 맞춘다. 서버가 돌려준 박스 여러 개를 앱이 최고 신뢰도 하나만 남기던 것을 카테고리별 수량으로 전부 살린다
- 신뢰도 숫자("AI 신뢰도 N%")·막대(`bar`) → 없음. 카테고리별 확인 필요 판정에만 쓴다
- 오프라인 배너(`failedBanner`, "📴 오프라인이라 AI 분석을 할 수 없어요…") → 없음. 업로드가 4-4 에서 끝나야 이 화면에 오므로 여기서 오프라인은 저장 단계에서만 만난다
- "🛠️ 지금은 AI 분석을 쓸 수 없어요" 와 "🔍 사진에서 쓰레기를 찾지 못했어요" 는 뒷문장만 "직접 분류를 고르면" → "직접 골라 담으면" 으로 바꿨다(직접 분류 절이 없어졌다). "🤔 확실하지 않아요" 의 뒷문장도 "아래에서 직접 골라 주세요" → "수량을 한 번 확인해 주세요"
- "이대로 담기" 에 합계 "· N개" 를 붙였다. 옛 버튼은 후보를 고르기 전까지 비활성이었고, 새 버튼은 합이 0 이면 비활성이다
- "다시 촬영"·사진 카드·배지·버림 확인 다이얼로그 문구(`ai_back_*`)는 그대로
- 로컬 보존 완료 안내는 "플라스틱 2 · 캔 1 담았어요 · 기기에 저장됨"처럼 표시하고 서버 동기화 대기 여부를 별도로 알린다

## 미결

- `ItemInput.quantity`의 서버 상한은 미정이다. 확정된 하한과 정수 검증을 쓰고 임의의 99 제한은 두지 않는다.
- 카테고리별 여러 탐지를 한 수량으로 묶으므로 `bbox`는 보내지 않는다. `aiPredictedCategory`는 원래 탐지 카테고리와 같은 값이며 개별 재분류 정확도를 표현하지 못한다.
- 이미 업로드했지만 담지 않은 사진의 정리 정책·API는 미정이다.
- 내구성 대기열은 앱 재실행·활동 종료·오류 후에도 보존하며 동일 id로 재시도한다. 구현에서 줍기 저장을 종료 요청보다 먼저 완료해야 한다.
