# 5-2 게시물 상세

**목적** 게시물 하나를 사진 원본 비율로 끝까지 보고, 좋아요와 댓글을 남긴다. 내 글이면 지우고, 남의 글이면 신고한다.
**원본** `../legacy/android-res/layout/fragment_post_detail.xml` · `sheet_post_menu.xml` · `item_comment.xml` · **변경** 동네 피드 → 크루 피드. 활동 기록 카드(`recordCard`)가 빠졌다(활동 요약은 첨부 이미지일 뿐이다). 답글·숨김·차단이 빠지고, 시트가 역할(본인·크루원·크루장)별로 갈린다. 댓글 입력 줄이 화면 아래에 고정됐다
**진입** 피드(5-1) 카드 · 알림 목록(2-3)의 COMMENT 알림 · 타인 프로필(5-4) 게시물 탭 · 내 정보(5-5) 게시물 목록 · **이탈** 얼굴·이름을 탭하면 타인 프로필(5-4) · 시트 [신고] → 신고(6-1) · 삭제 뒤 진입한 화면으로 · 뒤로 가기

## 배치

옛 XML 의 세로 순서(헤더 → 삭제 안내 → 본문 카드 → 댓글 카드 → 입력 줄)를 그대로 따른다. 헤더는 고정, 그 아래 본문 카드와 댓글 카드가 한 덩어리로 세로 스크롤한다. 입력 줄 ④ 는 옛 화면에서 댓글 카드 안 맨 아래에 있었는데, 화면 아래에 고정해 키보드와 함께 올라오게 했다 — 스크롤을 끝까지 내리지 않아도 댓글을 남길 수 있다. 사진은 자르지 않고 원본 비율로 보이며(최소 220dp · 최대 520dp), 여러 장이면 좌우로 넘긴다. 삭제된 게시물 ⑤ 는 ②③④ 자리를 통째로 대신한다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | ① 헤더는 바로 보인다. ②③ 자리에 `Loading` ("불러오는 중") 하나. ④ 입력 줄은 보이지만 흐리다. 5-1 · 5-4 · 5-5 카드에서 왔으면 카드가 이미 가진 `Post` 값(얼굴·이름·메타·사진·본문·숫자)을 먼저 그리고 `comments` 자리만 `Loading` — 화면이 비지 않는다. 2-3 에서 왔으면 `target.id` 만 있어 전부 `Loading` | 뒤로. 카드 값이 먼저 그려졌으면 얼굴·이름·좋아요는 눌린다. 더보기·입력·등록은 응답 뒤부터 |
| 새로고침 | 당겨서 새로고침. 위에 스피너가 돌고 이전 값이 그대로 남아 있다가 새 값으로 바뀐다(전송 중인 댓글은 유지). 실패하면 값은 그대로, `Snackbar` "새로고침에 실패했어요". 화면으로 돌아올 때(5-4 · 6-1 에서 뒤로)는 다시 받지 않는다 | 전부 평소처럼 눌린다 |

| 오프라인 | 네트워크 없음. 이미 그려진 값이 있으면 그대로 보이고 ① 아래에 `Banner` "인터넷 연결을 확인해 주세요." 없으면 오류와 같은 `ErrorState`. 좋아요를 누르면 먹은 것처럼 바뀌었다가 실패 → 되돌리고 `Snackbar` "좋아요를 반영하지 못했어요". 등록을 누르면 전송 중으로 그려졌다가 실패 → 댓글 전송 실패와 같다 | 전부 |

| 부분 실패 | `GET /posts/{postId}` 는 됐는데 `GET /users/me` 가 실패(캐시도 없음): 내 글인지 크루장인지 몰라 더보기를 흐리게 두고 댓글 길게 누르기도 막는다. 좋아요·댓글 쓰기는 된다. 사진 한 장을 못 받으면 그 장만 사진 자리 아이콘, 나머지 장은 넘긴다 | 더보기 빼고 전부 |
| 좋아요 반영 중 | 누르는 순간 하트·숫자가 먼저 바뀐다. 204 가 오면 그대로. 실패하면 되돌리고 `Snackbar` "좋아요를 반영하지 못했어요". 응답까지 같은 알약의 중복 요청을 막는다 | 그 칩만 비활성 |
| 댓글 전송 중 | 등록을 누른 순간 입력 원문을 유지하고 ③ 맨 아래에 내 댓글이 스피너 + "전송 중" 으로 그려진다. `commentCount` 는 아직 올리지 않는다. 201 이 오면 응답 `Comment` 의 `seq`·`createdAt` 으로 바뀌고 라벨·칩의 숫자가 1 오른다 | 그 행과 입력·등록은 응답까지 비활성. 성공하면 입력을 비운다 |
| 댓글 전송 실패 | 4xx/5xx 또는 시간 초과. 전송 중 행이 사라지고 보냈던 글이 입력에 되돌아온다. `Snackbar` "댓글을 남기지 못했어요. 다시 시도해 주세요." 422 VALIDATION은 입력칸 아래 해당 오류를 표시한다 | 등록을 다시 누르면 같은 `id` 로 다시 보낸다(서버가 중복을 흡수한다) |
| 삭제 중 | 대화상자 [삭제] 를 누르면 버튼 라벨 자리에 스피너, 대화상자는 닫히지 않는다. 204 면 대화상자·시트를 닫고 진입한 화면으로 돌아가며 `Snackbar` "게시물을 삭제했어요". 실패하면 대화상자는 남고 `Snackbar` "삭제하지 못했어요. 다시 시도해 주세요." 댓글 삭제도 같다(성공 시 행만 사라지고 스낵바 없음) | 진행 중에는 [취소]·[삭제] 모두 눌리지 않는다 |
| 크루장 / 크루원 / 내 글 | 화면과 요소는 같다. 차이는 더보기 시트와 댓글 길게 누르기 시트의 버튼만 — 위 시트 표. **내 글**: [삭제]. **크루원이 남의 글**: [신고]. **크루장이 남의 글**: [삭제]. 크루장은 자기 크루의 신고를 받는 쪽이라 신고 버튼이 없다 | — |
| 차단한 작성자 | 내가 차단한 크루원의 글·댓글은 서버가 피드·댓글에서 빼고 준다(차단·공개 범위 필터링은 서버 책임). 그 사람의 글에 2-3 알림 등으로 직접 들어오면 403 → 볼 수 없는 게시물. 5-4 에서 차단 성공 즉시 캐시와 현재 화면에서도 해당 글·댓글을 제거한다. 내 차단이 상대 화면을 숨기지는 않으며 공식 공지와 필수 운영 정보는 유지한다 | — |

## 인터랙션

- 스크롤: 헤더·입력 줄 사이가 세로 스크롤. 댓글은 `comments` 배열이 한 번에 와서 다음 장이 없다(커서 없음). 사진은 틀 안에서 좌우 스와이프로 넘기며 세로 스크롤과 겹치지 않는다
- 당겨서 새로고침: 있음. `GET /posts/{postId}` 한 번
- 길게 누르기: 댓글 행 — 위 시트 표대로 한 항목짜리 시트. 내 댓글 [댓글 삭제] · 크루원이 남의 댓글 [신고] · 크루장이 남의 댓글 [댓글 삭제]. 전송 중인 댓글·"탈퇴한 크루원" 의 댓글(크루원일 때)은 길게 눌러도 아무 일 없다. 게시물 본문·사진은 길게 눌러도 아무 일 없다(더보기가 있다)
- 시트: 더보기 시트(제목 "게시물 관리" + 설명 한 줄 + 버튼)와 댓글 시트(버튼만). 배경을 탭하거나 뒤로 가기로 닫는다. 시트에서 [삭제] 를 누르면 시트 위에 대화상자가 뜨고, 대화상자 [취소] 는 시트까지 함께 닫는다
- 뒤로 가기: 진입한 화면(5-1 · 2-3 · 5-4 · 5-5)으로. 시트·대화상자가 떠 있으면 그것만 닫는다. 키보드가 떠 있으면 키보드만 내린다. 입력 초안은 계정·게시물별로 보존하고 돌아오면 복원한다. 전송 중에는 입력·등록과 뒤로 가기를 잠시 막고 처리 상태를 알린다. 실패하면 원문과 같은 요청 id를 보존해 재시도한다
- 키보드: 입력 또는 댓글 칩을 탭하면 키보드가 올라오고 입력 줄이 키보드 위에 붙는다. 스크롤 영역은 그만큼 줄어든다. 엔터는 줄바꿈이고 등록은 버튼으로만 한다. 등록 뒤에도 키보드는 내려가지 않는다. 목록을 드래그하면 키보드가 내려간다. 500자에 닿으면 더 입력되지 않는다
- 사진 넘기기: 스와이프 또는 좌우 화살표. 넘기면 "1/3" 이 바뀐다. 마지막 장에서 더 넘기려 해도 처음으로 돌아가지 않는다
- 좋아요: 탭 한 번에 토글. 두 번 탭으로 좋아요는 없다
- 알림에서 진입: 푸시는 대상 게시물로 직접 이동한다. 대상이 삭제·권한 없음이면 이유 안내 후 2-3으로 돌아간다. 2-3 COMMENT 알림의 `target.id` 는 게시물 id 라 맨 위로 열고 특정 댓글로 스크롤하지 않는다(2-3 미결과 같다). 옛 "🔔 알림에서 이동한 댓글 위치예요" 칩은 없다
- 삭제 뒤 돌아가기: 진입한 화면이 5-1 · 5-4 · 5-5 목록이면 그 목록에서 이 게시물 카드를 빼 준다(목록을 다시 받지 않는다). 2-3 이면 그냥 돌아간다
- 전환: 5-1 · 2-3 · 5-4 · 5-5 에서 푸시. 5-4 · 6-1 로 푸시. 시트는 아래에서, 대화상자는 가운데에서 페이드

## 접근성

- 모든 내용과 동작을 유지한다. 작은 화면·큰 글자에서는 장식과 미리보기 높이를 먼저 줄이고 본문을 스크롤하며, 글자와 48dp 터치 영역은 줄이지 않는다.

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로"
  - 얼굴과 이름은 한 요소로 묶어 "상혁, 프로필 보기". 내 글이면 "상혁(나)". 탈퇴했으면 "탈퇴한 크루원"
  - 메타: "10분 전, 나만 보기"
  - 더보기: "더보기"
  - 사진: "게시물 사진, 3장 중 1번째". 한 장이면 "게시물 사진". 넘기면 새 번호를 읽어 준다(live region). 이전·다음 화살표: "이전 사진" · "다음 사진"
  - 본문: 그대로 읽는다
  - 좋아요 칩: "좋아요 6, 선택됨" / "좋아요 6, 선택 안 됨". 탭 힌트 "좋아요를 누르려면 두 번 탭" / "좋아요를 취소하려면 두 번 탭"
  - 댓글 칩: "댓글 2, 댓글 쓰기"
  - 댓글 한 건은 한 요소로 묶어 "지수, 어제, 오늘 많이 주우셨네요!". 전송 중: "…, 전송 중". 길게 누르기 힌트 "관리하려면 길게 누르기" 는 시트가 뜨는 댓글에만 붙인다
  - 빈 댓글 문구: 그대로 읽는다
  - 입력: "댓글 입력". 남은 글자는 400자를 넘은 뒤부터 "487자, 500자 중" 으로 읽는다
  - 등록: "등록". 비활성일 때 "등록, 비활성". 전송 중 "등록 중"
  - 시트가 뜨면 제목·설명을 먼저 읽고 포커스는 첫 버튼으로. 대화상자도 제목·본문을 읽고 [취소] 에 포커스
  - 스낵바·배너: 나타나는 순간 문구를 읽어 준다(live region)
  - ⑤: "삭제된 게시물이에요, 작성자가 삭제했거나 더 이상 볼 수 없는 게시물이에요" · 버튼 "돌아가기". 캐릭터는 장식이라 읽지 않는다
  - 하트·말풍선·점 3개·사진 자리 아이콘: 장식이라 읽지 않는다
- 최소 터치 크기 예외: 댓글 얼굴이 28dp 라 이름까지 한 터치 영역으로 묶어 48dp 를 채운다. 더보기·이전·다음은 48dp. 좋아요·댓글 칩은 위아래 여백까지 터치 영역에 넣어 48dp 를 채운다. 사진 번호 알약은 눌리는 요소가 아니라 예외 없음

## 옛 화면과의 차이

- 제목 "게시글" → "게시물"(용어). 문구 속 "게시글" 도 모두 "게시물" 로
- 활동 기록 카드(`recordCard` · `view_record_metrics` · "줍기 기록 없음" 배지 · "전체 합산 기록, 멤버별 기여는 표시하지 않아요") → 없음. 활동 요약은 첨부 이미지일 뿐이라 `media` 에 섞여 온다. 따라서 5-3 활동 기록 상세로 가는 길도 없다
- "고마워요 N" → "좋아요 N"(기능범위 용어). 칩 모양·하트는 그대로
- 댓글 칩이 새로 생겼다(옛 상세엔 없고 `item_post` 피드 카드에만 있었다). 누르면 입력에 포커스
- 답글(`replyButton` · `replyList` · `replyingChip` "답글 취소") → 없음. `Comment` 에 부모 댓글이 없다. 댓글은 한 층이다
- 더보기 시트: 옛 내 글 [수정]·[삭제] → [삭제] 만. 옛 남의 글 [신고]·[숨김]·[차단] → 크루원 [신고] 만, 크루장 [삭제] 만. 숨김은 기능에서 빠졐고 차단은 5-4 타인 프로필에서 한다. 시트 설명 문구 "내가 쓴 글이에요. 수정하거나 삭제할 수 있어요." → "내가 쓴 게시물이에요. 삭제하면 되돌릴 수 없어요.", "신고하거나 숨기고, 작성자를 차단할 수 있어요." → "크루장에게 이 게시물을 알릴 수 있어요."
- 삭제 확인 본문 "피드에서 바로 사라지고, 링크로 들어와도 삭제된 게시글로 보여요. 연결된 활동 기록은 그대로 남아요." → "피드에서 바로 사라지고, 알림으로 들어와도 삭제된 게시물로 보여요." (링크 공유가 없고 활동 기록 연결도 없다)
- 댓글 길게 눌러 삭제·신고는 새로 생겼다. 옛 화면은 댓글에 아무 행동이 없었다
- 댓글 입력 줄이 댓글 카드 안 → 화면 아래 고정. 500자 상한과 남은 글자 표시가 새로 생겼다
- 전송 중·전송 실패·좋아요 되돌리기는 새로 정했다 — 옛 XML 에는 없다
- "🔔 알림에서 이동한 댓글 위치예요" 칩(`focusChip`) → 없음. 댓글 위치를 짚을 수 없다
- 삭제 안내 "삭제된 게시글입니다" / "작성자가 삭제했거나 더 이상 볼 수 없는 글이에요." → "삭제된 게시물이에요" / "작성자가 삭제했거나 더 이상 볼 수 없는 게시물이에요." + [돌아가기] 버튼(옛 `emptyCta` 자리). 아이콘(`ic_sprout`) 자리에 캐릭터
- 메타의 "· 역삼동" 같은 동네 표기 → "· 나만 보기"(PRIVATE 일 때만). 동네 개념이 빠졌다
- 사진 자르지 않기(원본 비율 · 최소 220dp · 최대 520dp) · 번호 알약 · 좌우 화살표는 그대로. 스와이프 넘김은 새로 생겼다
- 당겨서 새로고침은 새로 생겼다

## 미결

- **댓글이 한 번에 온다.** `GET /posts/{postId}` 응답의 `comments` 가 배열이고 `GET /posts/{postId}/comments` 목록 경로·커서가 없다. 댓글이 수백 개가 되면 응답이 커진다. 커서 페이지가 필요해지면 경로를 추가하고 이 화면의 ③ 에 "이전 댓글 더 보기" 를 넣는다
- **좋아요 알림이 없다.** 알림 `type` 에 LIKE 가 없어(2-3 표 참고) 좋아요는 알림을 만들지 않는다. 이 화면으로 오는 알림은 COMMENT 하나다. POST_REMOVED 는 2-3 에서 이동 없음으로 정했다
- **차단·비공개 글에 직접 들어왔을 때의 응답 코드**를 계약이 말하지 않는다. 403 FORBIDDEN 으로 가정하고 404 와 같은 ⑤ 화면을 보이기로 했다. 서버가 404 로 통일해도 화면은 같다
- **크루장이 지운 뒤의 응답**: 삭제된 글을 `GET` 하면 404 라고 가정했다. `deleted_by` 를 구분해 "크루장이 삭제한 게시물이에요" 로 다르게 보이려면 응답 본문이 필요하다 — 지금은 구분하지 않는다
- 크루장 [삭제] 를 신고 처리(6-2)와 별개로 이 화면에서 바로 하게 했다. 계약 `DELETE /posts/{postId}` 요약("작성자 또는 크루장")을 따른 것이다. 신고 없이 지워도 POST_REMOVED 알림이 가는지는 서버가 정한다
- 댓글 삭제 뒤 `commentCount` 를 앱이 1 줄인다. 서버 값과 어긋날 수 있으나 새로고침하면 맞는다
- 빈 상태 캐릭터: `design-system/assets/character/` 에 "게시물 없음" 그림이 아직 없다(기능범위 빈 상태 3장 중 하나). 삭제된 게시물에도 같은 그림을 쓴다
