# 1-1 시작

**목적** 처음 온 사람은 가입하고, 계정이 있는 사람은 로그인해 자기 크루로 들어간다.
**원본** `../legacy/android-res/layout/fragment_start.xml` · **변경** 배치·버튼은 그대로. 태그라인의 "동네" 를 뺐고, 로그인 뒤 갈 곳이 동네 선택이 아니라 소속 상태(`membership.status`)로 갈린다
**진입** 앱 실행 시 저장된 토큰이 없을 때 첫 화면 · 로그아웃(5-7) · 회원 탈퇴(5-7) 직후 · **이탈** 로그인(1-2) · 회원가입(1-3) · 소셜 첫 가입이면 닉네임(1-4) · 소셜 로그인 성공 뒤 소속 상태에 따라 크루 만들기/가입하기(1-6) · 승인 대기(1-9) · 홈(2-1)

## 배치

옛 XML 의 순서(배경 사진 → 스크림 → 워드마크·태그라인 → 소셜 오류 배너 → 카카오 → 구글 → 이메일 → 회원가입 링크)를 그대로 따른다. 배경 사진이 화면 전체를 채우고 그 위에 아래로 갈수록 어두워지는 스크림이 깔린다. 워드마크 묶음이 남는 높이를 모두 차지해 가운데에 뜨고, 버튼 4개는 아래에 붙는다. 공간이 부족하면 워드마크·장식 여백을 먼저 줄이고 전체를 스크롤한다. 문구·버튼은 보존한다.

```
┌──────────────────────────────────────┐
│ ① (배경 사진 · 아래로 어두워지는 스크림)    │
│                                      │
│ ②          ╭──────────────╮           │
│            │  가치줍깅(워드마크) │  ← 광원   │
│            ╰──────────────╯           │
│      크루와 함께 걸으며 줍는 사람들.        │
│      기록하고, 나누고, 응원해요.           │
│                                      │
├──────────────────────────────────────┤
│ ③ (!) 소셜 로그인에 실패했어요. 네트워크…   │  ← 평소 숨김
├──────────────────────────────────────┤
│ ④ [      카카오로 시작하기      ] 노랑   │
│ ⑤ [     G 구글로 시작하기      ] 테두리  │
│ ⑥ [     ✉️ 이메일로 로그인     ] 반투명  │
│ ⑦            처음이신가요?              │
└──────────────────────────────────────┘
```

소셜 로그인·자동 로그인 뒤에는 `GET /users/me`의 `profileComplete`를 먼저 확인한다. 미완료면 1-4에서 이어가며 `isNew` false만으로 건너뛰지 않는다. 닉네임과 필수 동의 완료를 모두 확인한 뒤 소속 상태를 따른다. `profileComplete` true만으로 필수 동의 완료를 추정하지 않는다. 저장된 토큰으로 재개하되 인증 갱신 불가 시 1-1을 표시한다.

| 순서 | 보는 것 | 값 | 가는 곳 |
|---|---|---|---|
| 1 | `POST /auth/kakao` · `POST /auth/google` 인증 응답 | 성공 (`isNew` true·false 모두) | 토큰 저장 후 `GET /users/me` 조회 → 2. 자동 로그인·재로그인도 동일 |
| 2 | `GET /users/me` 응답 `profileComplete` | false | 1-4 닉네임 설정 재개. 소속 분기는 아직 실행하지 않는다 |
| 2 | 같은 응답 `profileComplete` | true | 닉네임 완료만 확인됨 → 3. 필수 동의 완료로 추정하지 않는다 |
| 3 | 필수 동의 완료 여부(조회·저장 계약 미결) | 미완료 또는 확인 불가 | 동의 완료 확인 단계에 머문다. 계약·콘텐츠 보완 전 완료로 간주하거나 소속 분기로 넘기지 않는다 |
| 3 | 같은 확인 | 완료 확인 | 4로 |
| 4 | `GET /users/me` 응답 `membership.status` | NONE | 1-6 크루 만들기/가입하기 |
| 4 | 같은 응답 | PENDING | 1-9 승인 대기 |
| 4 | 같은 응답 | MEMBER | 2-1 홈 |

| 빈 | **해당 없음.** 고정 화면이다 | — |
| 오류 | 제공자에서 토큰을 못 받았거나 `POST /auth/kakao` · `/auth/google` 이 4xx/5xx 면 ③ 배너 "소셜 로그인에 실패했어요. 네트워크 상태를 확인하고 다시 시도해 주세요." 가 ④ 위에 나타나고 스피너가 꺼진다. 사용자가 제공자 화면을 스스로 닫은 **취소**는 오류가 아니다 — 배너 없이 원래 화면으로 돌아온다. 배너는 다음 소셜 버튼 탭 때 숨긴다 | 전부. 다시 시도는 ④ 또는 ⑤ 를 다시 누르는 것이다 |

## 인터랙션

- 스크롤: 평소 한 화면. 작은 화면·큰 글씨에서는 장식부터 줄이고 전체를 스크롤한다. 글씨·터치는 줄이지 않는다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: 없음. 카카오·구글 로그인 화면은 앱 안 시트가 아니라 제공자(카카오 앱·구글 계정 선택)가 띄운다
- 뒤로 가기: 앱의 첫 화면이라 앱을 벗어난다(Android 기본). 제공자 인증 단계의 취소는 이 화면에 남는다. 서버 요청 중에는 결과 확인까지 이탈을 잠근다
- 키보드: 없음
- 전환: 1-2 · 1-3 은 푸시(뒤로 가기로 1-1 에 돌아온다). 소셜 로그인 성공 뒤 1-4 · 1-6 · 1-9 · 2-1 으로 갈 때는 1-1 을 스택에서 지운다 — 뒤로 가기로 시작 화면에 되돌아오지 않는다. 배너는 나타날 때만 짧게 페이드

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 워드마크: "가치줍깅"
  - 태그라인: 본문 그대로 읽는다
  - ④: "카카오로 시작하기" · ⑤: "구글로 시작하기"("G" 는 읽지 않는다) · ⑥: "이메일로 로그인"(✉️ 는 읽지 않는다)
  - 진행 중인 버튼: "로그인 중" 으로 바뀌고 나머지 버튼은 비활성으로 읽힌다
  - ③ 배너: 나타나는 순간 문구를 읽어 준다(live region)
  - ⑦: "처음이신가요? 회원가입으로 이동" — 화면 문구는 질문만이라 힌트를 붙인다
  - 배경 사진·스크림·광원: 장식이라 읽지 않는다
- 최소 터치 크기 예외: 없음. ④⑤⑥ 은 lg 버튼. ⑦ 은 글자가 작아 위아래 여백까지 터치 영역에 넣어 48dp 를 채운다

## 옛 화면과의 차이

- 태그라인 "동네를 걸으며 함께 줍는 사람들.\n기록하고, 만나고, 공유해요." → "크루와 함께 걸으며 줍는 사람들.\n기록하고, 나누고, 응원해요." 동네 개념을 끄고, 낯선 사람을 "만나는" 서비스가 아니라는 방향에 맞췄다
- 소셜 로그인 뒤: 옛 앱은 동네 선택으로 갔다 → `membership.status` 로 1-6 · 1-9 · 2-1 이 갈린다. 소셜 첫 가입(`isNew`)이면 1-4 닉네임을 먼저 거친다
- 소셜 오류 배너 문구는 그대로. 앞의 "⚠️" 는 `Banner` 의 danger 아이콘이 대신한다
- 카카오·구글·이메일·회원가입 네 버튼의 순서·문구·모양은 그대로
- 진행 중 표시(버튼 스피너·나머지 버튼 비활성)는 새로 정했다 — 옛 XML 에는 없다

## 미결

- `profileComplete`는 닉네임 설정 완료만 뜻한다. 실제 약관·개인정보 내용과 동의 저장·완료 판별은 1-3·1-4의 미결이다.
- 인증 갱신·상태 조회 실패 시 계정별 활동 대기 데이터를 삭제하지 않는 복구 구현이 필요하다.
