# 4-4 사진 촬영

**목적** 활동 중에 주운 쓰레기를 찍어 올리고, AI 가 찾은 결과를 4-5 에서 확인하도록 넘긴다.
**원본** `../legacy/android-res/layout/fragment_capture.xml` · **변경** 어두운 배경·둥근 프리뷰 틀·모서리 가이드·팁 타일·큰 셔터는 그대로. "1개씩" 안내를 뺐고(사진 한 장에서 찾은 것을 전부 기록한다), 셔터 뒤에 **미리보기(다시 찍기/사용)** 단계와 **업로드 진행**을 이 화면에서 처리한다. 옛 앱의 "다시 촬영" 은 4-5 에서만 했다
**진입** 4-3 활동 중의 카메라 버튼 · **이탈** 업로드 성공 → 4-5 AI 분류 확인 · 뒤로 가기 → 4-3

화면은 두 단계다. **① 촬영** — 카메라가 프리뷰 틀을 채우고 아래 셔터를 누른다. **② 미리보기** — 찍은 사진이 같은 틀에 멈춰 뜨고 아래 버튼이 "다시 찍기" · "사용" 둘로 바뀐다. "사용" 을 누르면 `POST /media` 가 올라가는 동안 사진 위에 진행 막대가 겹치고, 끝나면 4-5 로 넘어간다. 같은 화면 안에서 바뀌며 화면 이동은 없다.

## 배치

옛 XML 의 세로 순서(헤더 → 프리뷰 틀 → 팁 타일 → 셔터)를 그대로 따른다. 배경은 어두운 카메라색이고 글자는 밝은 계열이다. 프리뷰 틀이 남는 높이를 모두 쓰며, 틀 안에 어두운 스크림·가운데 안내 문구·네 모서리 가이드가 겹친다. 작은 화면·큰 글자에서는 프리뷰를 먼저 줄이고 내용이 넘치면 세로 스크롤한다. 글자·48dp 터치 영역은 유지한다. 세로 고정이다.

```
┌──────────────────────────────────────┐  어두운 배경
│ ① (‹)  쓰레기 촬영                     │
│        찍으면 AI 가 종류를 찾아요           │
├──────────────────────────────────────┤
│ ② ┌ ╭─────────────────────────────╮ ┐ │  점선 둥근 틀
│   │ (카메라 프리뷰 · 어두운 스크림)      │  │
│   │                               │  │
│   │    쓰레기를 화면 중앙에 놓아 주세요    │  │  ← ①단계만
│   │                               │  │
│   │      ▒▒▒▒▒▒▒▒▒▒▒░░░░ 올리는 중  │  │  ← 업로드 중만
│   └ ╰─────────────────────────────╯ ┘ │
├──────────────────────────────────────┤
│ ③ (✦) 쓰레기가 겹치지 않게 펼쳐 찍으면     │  어두운 타일
│       AI 가 더 잘 찾아요.                │
├──────────────────────────────────────┤
│ ④-a            ( ◎ )                  │  ①단계: 셔터 78dp
│ ④-b   [ 다시 찍기 ]   [   사용   ]     │  ②단계: 버튼 둘
└──────────────────────────────────────┘
```

권한이 없을 때는 ② 틀 안이 카메라 대신 권한 카드로 채워진다(상태 표 참고).

업로드 성공 뒤 4-5 로 넘길 것은 `POST /media` 응답 `data` 전체다.

| 응답 | 값 | 4-5 에 넘기는 것 |
|---|---|---|
| `data.inference.status` | OK | `data.photoId` · `data.url` · `data.inference.items`(각 `category`·`aiConfidence`·`bbox`). 4-5 가 카테고리별 수량으로 묶어 보여 준다. `items` 가 비어 있어도 4-5 로 간다(4-5 가 "찾지 못했어요" 를 띄운다) |
| `data.inference.status` | UNAVAILABLE | `data.photoId` · `data.url` 만. 예측 없이 4-5 로 가고, 4-5 가 직접 분류를 고르게 한다 |
| `data.inference` | null | UNAVAILABLE 과 같게 다룬다 |

이 화면은 예측 결과를 해석하거나 보여 주지 않는다. 판단·수정·저장(`POST /activities/{id}/items`)은 모두 4-5 의 일이다.

| 셔터 누른 직후 | 프리뷰가 한 번 짧게 어두워지고(셔터 효과) 사진이 굳는다. 사진이 나오기까지 셔터는 눌리지 않는다 | 뒤로 |

## 인터랙션

- 스크롤: ② 프리뷰 높이를 먼저 줄이고 내용이 넘치면 스크롤한다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: 없음. 시스템 권한 창과 OS 설정은 앱 밖이다
- 뒤로 가기: ①단계 → 4-3. ②단계 → 사진을 버리고 ①단계(확인 없음 — 다시 찍기와 같다). 업로드 중 → 결과가 확정될 때까지 이탈 차단. 연결 실패면 사진과 같은 mediaId를 보존해 재시도. 헤더의 뒤로 버튼도 같다
- 키보드: 없음
- 셔터: 한 번만 눌린다. 사진이 굳을 때까지 다시 눌리지 않는다. 촬영 순간 짧은 진동 한 번
- 프리뷰 탭: 아무 일도 없다(초점·확대 제스처는 두지 않는다)
- 화면 이탈: 4-5 로 넘어가면 카메라를 끈다. 4-5 의 "다시 촬영" 으로 되돌아오면 ①단계부터 새로 시작하며 이전 미리보기만 비운다. 이미 업로드된 사진의 보존·정리는 서버 계약을 따른다
- 앱이 배경으로 가면 카메라를 끄고, 돌아오면 같은 단계에서 다시 켠다(②단계면 사진은 남는다)
- 전환: 4-5 는 푸시. 4-5 에서 "이대로 담기" 로 저장하면 4-4·4-5 를 함께 스택에서 지우고 4-3 으로 돌아간다. ①↔② 단계 전환은 자리 바꿈만, 애니메이션 없음

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로"
  - 카메라 프리뷰: "카메라 미리보기" · ②단계 사진: "방금 찍은 사진"
  - 안내 문구·팁: 본문 그대로 읽는다
  - 셔터: "촬영" (`CaptureButton` 의 고정 라벨). 비활성이면 비활성으로 읽힌다
  - 다시 찍기 · 사용: 라벨 그대로
  - 진행 막대: "올리는 중, 40%" 처럼 값이 함께 읽힌다(`Progress` 의 value). 시작할 때 "사진을 올리고 있어요" 를 한 번 읽어 준다(live region)
  - 권한 카드: 제목·설명·버튼을 순서대로 읽는다. 나타나는 순간 제목을 읽어 준다(live region)
  - `Snackbar`: 나타나는 순간 문구를 읽어 준다
  - 모서리 가이드·스크림·점선 틀·반짝 아이콘: 장식이라 읽지 않는다
- 최소 터치 크기 예외: 없음. 셔터 78dp, 뒤로 48dp 이상, ④-b 는 lg 버튼
- 어두운 배경 위 글자는 밝은 계열만 쓴다. 안내 문구는 프리뷰가 밝아도 읽히도록 그림자를 둔다

## 옛 화면과의 차이

- 부제 "1개씩 촬영" → "찍으면 AI 가 종류를 찾아요". 팁 "한 번에 한 개를 촬영하면 AI 정확도가 높아져요." → "쓰레기가 겹치지 않게 펼쳐 찍으면 AI 가 더 잘 찾아요." 사진 한 장에서 찾은 것을 전부 기록하기로 해서(기능범위 AI 줍기) 한 개씩 찍으라는 안내가 맞지 않게 됐다
- 미리보기 단계(다시 찍기/사용)는 새로 생겼다. 옛 앱은 셔터를 누르면 바로 올리고 4-5 에서만 "다시 촬영" 할 수 있었다
- 업로드 진행 표시는 새로 생겼다. 옛 XML 에는 없다
- 권한 상태 3종(안 물음·거부·영구 거부)의 카드는 옛 문구(`cap_perm_title`·`cap_perm_desc`·`cap_perm_cta`)를 살렸다. 거부(다시 물을 수 있음) 단계의 짧은 설명과 [카메라 권한 허용] 버튼은 새로 정했다. 데모용 링크(`permDemo` "데모: 카메라 권한 없음 상태 보기")는 없다
- 헤더·프리뷰 틀·모서리 가이드·팁 타일·셔터의 모양과 자리는 그대로
- 갤러리에서 고르기·플래시·전면 전환은 옛 XML 에도 없었고 이번에도 없다

## 미결


- `POST /media` 파일 형식·용량·리사이즈 제한과 같은 `mediaId` 재시도의 멱등 처리를 계약·구현에서 확정해야 한다.
- 이미 업로드했지만 담지 않은 사진의 정리 정책·API는 미정이다. 업로드 후 AI만 실패하면 사진은 보존하고 4-5 수동 수량 입력으로 이어진다.
