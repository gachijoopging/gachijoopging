# 1-7 크루 만들기

**목적** 아직 크루가 없는 사람이 크루 이름 하나를 정해 크루장이 되고, 자동 생성된 초대 코드로 다른 사람을 초대할 준비를 한다.
**원본** `../legacy/android-res/layout/fragment_meet_create.xml` · **변경** 장소·시간·정원·공개 범위 입력을 없애고 이름 하나만 남겼다. 소개·대표 사진·크루 목표는 생성 뒤 3-10 크루 정보 수정에서 크루장이 정한다.
**진입** 1-6 크루 만들기/가입하기의 "새 크루 만들기" · **이탈** 생성 성공 → 2-1 홈 · 뒤로 가기 → 1-6

## 배치

옛 XML의 순서(헤더 → 세로 입력 영역 → 아래 주 버튼)를 따른다. 이름 입력칸은 그대로 두고, 장소 검색·시간·정원 스테퍼·공개 범위 목록을 모두 없앤다. 빈 영역에는 생성 뒤 할 수 있는 일을 설명하는 안내 카드를 둔다. 버튼은 화면 아래에 고정한다.

```
┌──────────────────────────────────────┐
│ ① ‹  새 크루 만들기                   │
├──────────────────────────────────────┤
│ ② 크루 이름                            │
│    ┌────────────────────────────────┐ │
│    │ 예: 한강줍깅크루                 │ │
│    └────────────────────────────────┘ │
│                                      │
│ ③ ┌────────────────────────────────┐ │
│    └────────────────────────────────┘ │
│                                      │
├──────────────────────────────────────┤
│ ④ [          크루 만들기          ]    │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로 버튼 | "뒤로" | `AppHeader` | 1-6 |
| ① | 헤더 제목 | "새 크루 만들기" | `AppHeader` | — |
| ② | 라벨 | "크루 이름" | `Txt` label | — |
| ② | 이름 입력창 | 플레이스홀더 "예: 한강줍깅크루". `name` (`POST /crews`), 줄바꿈 제거·앞뒤 공백 제거 뒤 2~20자, 추가 문자 제한 없음 | `Field` | 키보드 |
| ② | 오류 문구 | 검증 실패 시 아래 표의 빨간 문구 | `Field` error | — |
| ④ | 주 버튼 | "크루 만들기". 유효한 `name`일 때만 활성 | `Button` primary lg | `POST /crews` → 201이면 2-1 |

이름 검증은 계약의 `name` `minLength: 2`, `maxLength: 20`을 따른다.

| 조건 | 보이는 것 | 크루 만들기 버튼 |
|---|---|---|
| 비어 있음 | "크루 이름을 입력해 주세요."는 포커스를 떠났을 때만 | 비활성 |
| 1자 | "크루 이름은 2자 이상이어야 해요." | 비활성 |
| 2~20자 | 오류 없음 | 활성 |
| 21자 이상 | "크루 이름은 20자까지 입력할 수 있어요." | 비활성 |

서버 응답은 공통 오류 봉투의 `code`를 쓴다. `message`는 화면에 쓰지 않는다.

| 응답 | 보이는 것 |
|---|---|
| `POST /crews` 201 | 생성된 `data.name`으로 "한강줍깅크루를 만들었어요." `Snackbar`. `data.isLeader`가 true인 크루장 상태가 된 뒤 2-1으로 간다 |
| 409 ALREADY_IN_CREW | "이미 크루에 소속돼 있어요." `Snackbar` 뒤 `GET /users/me`의 `membership.status`를 다시 확인해 MEMBER면 2-1, PENDING이면 1-9로 간다 |
| 409 CREW_NAME_TAKEN | 이름 필드 아래 “이미 사용 중인 크루 이름이에요.”. 입력값 유지 |
| 422 VALIDATION | 입력창 아래 "크루 이름을 다시 확인해 주세요.". 입력값은 남긴다 |
| 401 TOKEN_EXPIRED | 토큰 갱신 뒤 같은 요청을 한 번 다시 보낸다. 갱신할 수 없으면 1-1 |
| 그 외 4xx·5xx·네트워크 실패 | `Snackbar` "크루를 만들지 못했어요. 네트워크 상태를 확인하고 다시 시도해 주세요.". 입력값은 남긴다 |

## 인터랙션

- 스크롤: 키보드가 없으면 한 화면에 다 들어간다. 작은 화면·키보드가 올라오면 ②·③만 세로 스크롤하고 ④는 키보드 위에 보인다
- 당겨서 새로고침: 없음
- 길게 누르기: 이름 입력창에서 OS 기본 붙여넣기만 가능하다
- 시트: 없음
- 뒤로 가기: 헤더와 시스템 뒤로 가기 모두 1-6으로 팝한다. 아직 서버에 생성된 것은 없고 입력한 이름은 버린다. 생성 중에는 무시한다
- 키보드: 진입 때 ②에 포커스. 완료(Done)는 유효한 이름이면 ④와 같은 생성 요청, 아니면 검증 문구를 보인다. 입력창 밖을 누르면 키보드를 내린다
- 전환: 1-7→2-1은 온보딩 스택에서 1-6·1-7을 지우고 전환한다. 위치 권한은 활동 시작 때만 묻는다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - ①: "뒤로, 크루 선택으로"
  - ②: "크루 이름, 2자에서 20자". 오류는 나타나는 순간 읽고 입력창과 연결한다
  - ④: "크루 만들기", 비활성·생성 중 상태를 함께 읽는다
  - 장식용 🌱·화살표는 읽지 않는다
- 최소 터치 크기 예외: 없음. ①·②·④는 모두 48dp 이상이다

## 옛 화면과의 차이

- 옛 화면의 이름 입력(`titleInput`)만 남겼다. 장소 검색(`placeInput`·`placeSuggestions`)·시간(`timeInput`)·정원 스테퍼(`capacityMinus`·`capacityPlus`)·공개 범위 목록(`visibilityList`)은 크루에 맞지 않아 없앴다
- 옛 "모임 만들기"는 활동 일정을 만들었다. 새 "크루 만들기"는 지속되는 크루를 만들고 호출자가 크루장이 된다
- 정원·장소·시간을 고르는 대신, 초대 코드가 자동 생성되고 소개·사진·목표는 3-10에서 나중에 정한다
- 옛 주 버튼은 모든 입력이 채워져야 활성화됐다. 새 주 버튼은 이름 하나만 유효하면 활성화된다
