# 4-7 활동 종료 요약

**목적** 방금 끝낸 활동을 서버에 저장하고, 거리·시간·줍기 개수·경로를 한눈에 보인 뒤 게시물로 공유할지 고른다.
**원본** `../legacy/android-res/layout/fragment_activity_end.xml` (지표 줄 `view_metric_row.xml`, 지도 `view_map_frame.xml`) · **변경** 모임 관련 세 덩이(내 개인 기록 칩·모임 전체 기록 안내·함께한 멤버 카드)와 미분류 정리 배너를 뺐다. 제목·지도·지표 3분할·카테고리 칩·0개 배너·동기화 대기 칩·공유 카드는 그대로. 종료 요청(`POST /activities/{id}/end`)을 이 화면이 보내며 저장 중·실패·오프라인 상태를 새로 정했다
**진입** 활동 중(4-3)의 종료 확인 다이얼로그에서 [종료하기] · **이탈** 공유하기 → 게시물 작성(5-6, 요약 이미지가 첨부된 채) · 공유 안 함·뒤로 가기 → 줍깅 대기(4-1)

4-3에서 [종료하기]를 눌러 로컬 기록과 종료 스냅샷을 보존한 뒤 배경 추적(포그라운드 서비스)을 끄고 이 화면을 연다. 화면은 기기에 쌓여 있던 값(거리·시간·일시정지 시간·걸음수·경로·줍기 개수)으로 바로 그려지고, 줍기 생성·되돌리기 대기열을 서버에 반영한 다음 `POST /activities/{id}/end` 를 보낸다. 응답이 오면 서버 값으로 바꾼다. 줍기 동기화 실패 시 종료 요청도 보류하고 로컬 요약을 유지한다. `GET /activities/{id}`는 이미 종료된 응답 복구에도 쓰고 5-3 기록 상세에서도 사용한다.

## 배치

옛 XML 의 세로 순서(제목·메타 → 지도 → 지표 3분할 → 카테고리 칩 → 0개 배너 → 동기화 칩 → 공유 카드)를 그대로 따른다. 사이에 있던 개인 기록 칩·모임 안내·멤버 카드가 빠져 지도 바로 아래 지표가 붙는다. 제목만 고정하고 메타를 포함한 나머지는 세로 스크롤이다. 작은 화면에서는 지도 높이·장식 여백부터 줄이며 글자·터치 영역을 줄이지 않는다. 헤더 뒤로 버튼은 없다(옛 화면과 같다) — 닫기는 공유 카드의 [공유 안 함] 과 Android 뒤로 가기가 한다.

| 3 | 같은 요청 | 4xx/5xx | 오류 행. 기기 값은 지우지 않는다 |
| 3 | 같은 요청 | 네트워크 없음·시간 안에 닿지 않음 | 대기열에 넣고 오프라인 행. 연결되면 같은 요청을 다시 보낸다 |

대기열은 앱 재실행·화면 이탈·오류에도 계정별로 보존하고 연결 복구·앱 재실행 시 재시도한다. 종료 스냅샷의 시각과 값은 재시도 때 새로 계산하지 않는다. 4-1에서 이전 종료 동기화 완료 전 새 활동만 막으며, 다른 탭은 계속 이용한다. 로그아웃·크루 나가기·회원 탈퇴는 진행 중 또는 미동기화 활동이 있으면 막는다.

| 409 CONFLICT | 이미 종료된 활동(다른 기기 또는 대기열 중복). 실패로 보이지 않는다 — `GET /activities/{id}` 로 받아 저장 완료 상태로 그린다 |
| 403 FORBIDDEN · 403 NO_CREW | 내 활동이 아니거나 크루가 없다. 404 와 같은 카드. NO_CREW 는 [닫기] → 1-6 |
| 422 VALIDATION | 보낸 값이 어긋남(`distanceM` 음수 등). 오류 상태 그대로, 아래 문구만 "기록 값에 문제가 있어요. 다시 시도해도 같으면 기기에만 남겨요." |
| 401 TOKEN_EXPIRED | 앱 공통 토큰 갱신 뒤 같은 요청을 다시 보낸다(화면 변화 없음). 갱신도 실패하면 1-1 — 원래 계정의 기기 값은 남긴다 |
| 429 RATE_LIMITED · 500 INTERNAL · 그 외 | 오류 상태 |

크루장·크루원 차이: **없음.** 활동 종료·게시물 작성은 권한표에서 둘 다 ○ 이고 요소도 같다.

## 인터랙션

- 스크롤: 세로. ① 제목 줄은 고정, ②~⑦ 이 스크롤. 카테고리가 많거나 배너·칩이 붙으면 ⑦ 이 밀리므로 스크롤한다. 지도 위에서 세로로 끌어도 지도가 아니라 화면이 스크롤된다(지도 조작 막음)
- 당겨서 새로고침: 없음
- 길게 누르기: 없음
- 시트: 없음. 기록 삭제는 확인 대화상자로 처리한다
- 뒤로 가기: [공유 안 함] 과 같다 — 확인 없이 4-1 로. 저장 중이면 요청을 끊지 않고 뒤에서 이어간다(저장 중 행). 오류·오프라인 상태에서 나가도 기기 값은 남는다
- 기록 삭제: [이 기록 지우기] → 확인. 요청 중 중복 삭제·공유 차단, 성공하면 4-1, 실패하면 원본 기록을 유지하고 재시도. 미동기화 상태에서는 삭제하지 않는다.
- 키보드: 없음
- 지도: 정지 이미지처럼 다룬다. 탭·끌기·확대 없음. 전체화면 없음
- 공유하기: 누르는 순간 날짜·시작/종료 시각·활동 시간·거리·측정된 걸음수·줍기 개수를 한 장으로 그려(캡처가 아니라 같은 값으로 다시 그린 이미지) 경로는 사용자가 포함을 켰을 때만 추가한다. 걸음 미측정이면 걸음 칸은 생략한다. `linkedPostId`나 기록 상세로 연결되는 게시물 링크를 만들지 않는다. 5-6 을 푸시한다. 5-6 에 첨부 사진 첫 칸으로 들어가고 글은 비어 있다. 5-6 에서 뒤로 오면 이 화면(저장 완료 상태)으로 돌아온다. 게시물을 올리고 나면 5-6이 4-7과 함께 스택에서 빠져 5-1 피드로 간다
- 전환: 4-3 → 4-7 은 4-3 을 스택에서 지우고 교체(뒤로 가기로 4-3 에 돌아가지 않는다). 4-7 → 5-6 푸시. 4-7 → 4-1 은 닫기(4-1 은 4-2 때부터 스택에 남아 있다). ⑤⑥ 배너·칩과 ⑦ 문구 교체는 짧게 페이드

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 화면이 열리는 순간 ① 제목에 포커스. "오늘의 줍깅 정리"(🌱 는 읽지 않는다)
  - 메타: 본문 그대로. "9월 7일 일요일 9시 2분부터 9시 48분까지, 일시정지 4분, 4,100걸음"
  - 지도: "이동 경로 지도, 3.1km". 선·점은 읽지 않는다. 경로가 없으면 "경로가 기록되지 않았어요"
  - ③: 칸 하나를 한 요소로 "줍기 개수 27개" · "활동 시간 42분" · "이동 거리 3.1km"
  - ④: 칩마다 "담배꽁초 14개". 아이콘은 읽지 않는다
  - ⑤ 배너·⑥ 칩: 나타나는 순간 문구를 읽어 준다(live region). 앞의 이모지(🚶 📴)는 읽지 않는다
  - ⑦ 제목: 상태가 바뀌는 순간 새 문구를 읽어 준다(live region). 체크 아이콘·스피너는 읽지 않는다
  - [공유하기]: "공유하기, 게시물 작성으로 이동". 비활성이면 비활성으로 읽히고 힌트 "기록 저장이 끝나면 쓸 수 있어요"
  - [공유 안 함]: "공유 안 함, 닫기"
- 경로 포함 스위치는 켬/끔을 읽고, 삭제 확인은 취소에 먼저 포커스한다.
- 최소 터치 크기 예외: 없음. ⑦ 두 버튼은 md 높이에 카드 안 너비를 반씩 나눈다. 경로 포함·기록 삭제도 최소 48dp 터치 영역을 확보한다

## 옛 화면과의 차이

- "🙋 내 개인 기록" 칩(`personalChip`) · "모임 전체 기록은 따로 정리돼요 / 모임장이 활동을 종료하면…" 안내(`groupNote`) · "함께한 멤버" 카드(`membersCard`) → 모두 없음. 활동은 항상 개인 단위다
- 경로 라벨 "이동 경로 · 주운 위치 N" → "이동 경로". 줍기 위치 좌표가 계약에 없으므로 해당 마커를 그리지 않는다
- 미분류 배너(`unclassBanner`, [미분류 정리]) → 없음. 4-5 에서 사용자가 카테고리를 확인한 뒤 담으므로 종료 시점에 미분류가 남지 않는다
- 제목 "오늘의 줍깅 정리 🌱" · 지표 3분할(줍기 개수·활동 시간·이동 거리) · 카테고리 칩 · "🚶 줍기 기록 없이 활동만 저장돼요…" · "📴 동기화 대기 중 · 연결되면 자동 업로드돼요" · "기록을 저장했어요. 피드에 공유할까요?" · "동기화가 끝나야 피드에 공유할 수 있어요." · [공유 안 함] · [공유하기] 는 그대로
- 메타 줄에 일시정지 시간·걸음수를 넣었다 — 일시정지와 걸음수 보정이 새로 생겼다
- "공유하기" 가 기록을 붙인 게시물이 아니라 요약 이미지를 첨부한 자유 게시물로 간다(기능범위 피드 절)
- 저장 중·오류·오프라인 세 상태의 카드 문구와 [다시 시도] · 409 처리는 새로 정했다 — 옛 XML 에는 동기화 칩과 공유 막힘 문구만 있었다

## 미결

- `POST /activities/{id}/end` 재전송의 성공·이미 종료 응답을 API 구현에서 멱등하게 처리해야 한다. 409이면 상세 재조회로 같은 종료 결과와 모든 줍기 반영 여부를 확인한 뒤 완료한다.
- 줍기 생성·되돌리기 → 종료 순서, 계정별 내구성 대기열·재실행 복구는 구현 검증이 필요하다. 오류만으로 대기열을 지우지 않는다.
- 요약 이미지의 최종 시각 디자인은 제작해야 한다. 포함 정보는 날짜·시각·활동 시간·거리·측정된 걸음수·줍기 개수로 확정했고 경로는 별도 opt-in이다.
