# 3-8 가입 신청 관리

**목적** 크루장이 대기 중인 가입 신청을 확인하고 한 사람씩 승인하거나 거절한다.
**원본** `../legacy/android-res/layout/fragment_friends.xml` · **변경** 친구·받은 요청 탭을 없애고, 비공개 크루에 들어온 가입 신청 한 목록과 승인·거절 행동으로 바꿨다. 크루장만 접근한다. 공개 크루는 승인 없이 바로 가입하므로 신청이 생기지 않는다.
**진입** 3-11 크루원 관리의 "가입 신청" · 2-3 JOIN_REQUEST 알림 · **이탈** 3-11 크루원 관리 · 5-4 타인 프로필 · 뒤로 가기 → 진입 화면

## 배치

옛 XML의 순서(헤더 → 탭 자리 → 로딩·빈 상태·목록)를 따른다. 두 탭 자리에는 "대기 중인 가입 신청" 제목과 건수만 두고, 각 행에 신청자·신청 시각·승인·거절 버튼을 놓는다.

```
┌──────────────────────────────────────┐
│ ① ‹  가입 신청 관리                    │
├──────────────────────────────────────┤
│ ② 대기 중인 가입 신청 2건              │
├──────────────────────────────────────┤
│ ③ ┌────────────────────────────────┐ │
│    │ (◉) 지수                         │ │
│    │     9월 2일 가입 신청             │ │
│    │        [거절]  [승인]             │ │
│    └────────────────────────────────┘ │
│ ③ ┌────────────────────────────────┐ │
│    │ (◉) 민수                         │ │
│    │     9월 1일 가입 신청             │ │
│    │        [거절]  [승인]             │ │
│    └────────────────────────────────┘ │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로 버튼 | "뒤로" | `AppHeader` | 진입 화면 |
| ① | 헤더 제목 | "가입 신청 관리" | `AppHeader` | — |
| ② | 대기 수 | `pendingJoinRequests` (`GET /crew`). "대기 중인 가입 신청 2건". 승인·거절 성공마다 1 줄인다. 대기 신청자는 정원에 세지 않는다 | `Txt` section | — |
| ③ | 신청 행 | `id`·`user.photoUrl`·`user.nickname`·`createdAt`·`status` (`GET /crew/join-requests`, 먼저 신청한 순) | `Card` + `Avatar` md + `Txt` | 신청자 → 5-4 |
| ③ | 신청자 아바타·닉네임 | `user.photoUrl` null이면 `user.nickname` 첫 글자 | `Avatar` md + `Txt` body strong | 5-4 |
| ③ | 신청 시각 | `createdAt`을 "9월 2일 가입 신청"으로 표시 | `Txt` caption muted | — |
| ③ | 거절 버튼 | "거절" | `Button` ghost sm | 거절 확인 → `POST /crew/join-requests/{requestId}` (`decision` REJECT) |
| ③ | 승인 버튼 | "승인" | `Button` primary sm | 승인 확인 → `POST /crew/join-requests/{requestId}` (`decision` APPROVE) |

목록은 PENDING 신청만 돌려주는 계약이다. 승인·거절 성공 뒤 해당 행은 목록에서 바로 사라지고 3-2의 `pendingJoinRequests`도 다음 진입·새로고침 때 줄어든다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | ①은 보이고 ②·③ 자리에 `Loading` "가입 신청을 불러오고 있어요" | ① 뒤로 |
| 새로고침 | 당겨서 새로고침. 기존 행은 남기고 상단 스피너 | 행·뒤로 |
| 빈 | 첫 페이지 `items` 가 비어 있음. `EmptyState` "대기 중인 가입 신청이 없어요" | 뒤로 |
| 오류 | `GET /crew/join-requests` 4xx·5xx면 `ErrorState` "가입 신청을 불러오지 못했어요" / [다시 시도] | 다시 시도 |
| 오프라인 | 이전 행이 있으면 그대로, ② 아래 `Banner` "인터넷 연결을 확인해 주세요.". 없으면 오류 상태 | 이전 행·뒤로 |
| 권한 거부 | 크루원이 직접 진입하거나 403 FORBIDDEN이면 `ErrorState` "크루장만 가입 신청을 관리할 수 있어요." / [크루 정보로] | 크루 정보로 → 3-11 |
| 부분 실패 | **해당 없음.** 목록 요청 하나다. 개별 승인·거절 실패는 아래 처리 상태가 다룬다 | — |
| 승인·거절 처리 중 | 선택한 행의 두 버튼 자리에 스피너, 그 행만 비활성. 다른 행은 계속 처리 가능 | 다른 행·뒤로 |
| 이미 처리됨 | 같은 신청을 다른 기기에서 처리했거나 재시도 중 404·409 CONFLICT 이면 행을 목록에서 지우고 `Snackbar` "이미 처리된 가입 신청이에요." | 나머지 행 |
| 정원 참 | 승인이 409 CREW_FULL 이면 행을 그대로 두고(신청은 대기 그대로) `Snackbar` "크루 정원(50명)이 차서 승인할 수 없어요." 거절은 할 수 있다. ② 위에 `Banner` "크루원이 50명이라 승인할 수 없어요." 를 `memberCount` 가 50 일 때 미리 보인다 | 거절·뒤로 |

승인 확인 대화상자: 제목 "지수 님의 가입을 승인할까요?" · [그대로 두기] / [승인].

거절 확인 대화상자: 제목 "지수 님의 가입을 거절할까요?" · [그대로 두기] / [거절].

`POST /crew/join-requests/{requestId}` 204면 행을 제거하고 승인 때 "지수 님을 크루원으로 맞이했어요.", 거절 때 "가입 신청을 거절했어요." `Snackbar`를 보인다. 4xx·5xx·오프라인이면 행을 유지하고 "가입 신청을 처리하지 못했어요. 다시 시도해 주세요." `Snackbar`.

## 인터랙션

- 스크롤: 신청 행이 화면보다 많으면 세로 스크롤. 끝에 닿으면 `nextCursor` 로 다음 페이지를 붙인다(null 이면 멈춤)
- 당겨서 새로고침: 있음. `GET /crew` 와 `GET /crew/join-requests` 첫 페이지 재조회
- 길게 누르기: 없음
- 시트: 없음. 승인·거절 확인은 대화상자
- 뒤로 가기: 진입 화면으로 팝한다. 대화상자가 떠 있으면 먼저 닫는다
- 키보드: 없음
- 행 탭: 신청자 아바타·닉네임 영역은 5-4 타인 프로필로 푸시한다. 승인·거절 버튼 영역은 프로필로 이동하지 않는다
- 전환: 5-4는 푸시. 처리 성공은 목록 안에서 행만 바꾼다
- 가입 신청 거절 사유는 남기지 않는다(1-9 와 같다)

## 접근성

- ②: "대기 중인 가입 신청 2건"을 읽는다
- ③: "지수, 9월 2일 가입 신청, 승인, 거절"로 행을 읽는다. 아바타는 닉네임이 대신한다
- 승인·거절 확인 대화상자는 제목을 읽는다
- 버튼은 역할을 포함해 "지수 님 가입 승인", "지수 님 가입 거절"로 읽고 모두 48dp 이상이다

## 옛 화면과의 차이

- 옛 친구/받은 요청 두 탭과 친구 수락·거절을 없앴다. 크루원 사이에는 친구 관계가 없다
- 옛 받은 친구 요청 행을 비공개 크루 가입 신청 행으로 바꾸고, 승인하면 크루원이 되는 효과를 명시했다
- 옛 아래 친구 안내를 없앴다

- 같은 행은 요청 중 중복 처리하지 않고 실패 시 행을 보존해 재시도한다.
- 승인·거절 결과는 신청자가 푸시·앱 복귀·수동 새로고침으로 확인한다. 거절된 신청자는 다음 로그인 때도 거절 안내를 한 번 보고 크루 선택으로 이동하며, 같은 크루에 바로 다시 신청할 수 있다.
- 차단 여부와 무관하게 크루장에게 필요한 신청자 관리 정보는 보인다. 알림에서 직접 진입한 대상이 사라지거나 권한이 없으면 이유를 안내하고 2-3으로 돌아간다.

- 크루장이 3-10 에서 공개로 바꾸면 이 목록의 대기 신청은 바로 가입되고 목록에서 빠진다. 추방 이력이 있는 신청은 남는다. 크루원 + 대기 신청이 50명을 넘으면 전환이 막히고, 3-10 이 이 화면으로 보내 신청을 정리하게 한다.
- 신청자가 탈퇴하면 그 신청은 취소돼 목록에서 사라진다.
