# 3-5 공지 목록

**목적** 크루 공지를 최신순으로 보고, 크루장은 새 공지를 작성하거나 기존 공지를 관리한다.
**원본** `../legacy/android-res/layout/fragment_feed.xml` · **변경** 일반 게시물 피드의 검색·전체/친구 탭을 없애고, 최신 공지 한 건을 자동 강조하는 공지 목록으로 바꿨다. 작성 버튼은 크루장에게만 보인다.
**진입** 3-1 모이깅의 "공지" · **이탈** 3-6 공지 상세 · 3-12 공지 작성·수정 · 뒤로 가기 → 3-1

## 배치

옛 피드의 순서(제목 → 우측 행동 버튼 → 목록 → 로딩·빈 상태)를 따른다. 검색·두 탭을 없애고 제목 아래에 "크루 공지" 설명만 둔다. 최신 작성 공지 한 건이 맨 위에 자동 표시되고 나머지도 최신순이다.

```
┌──────────────────────────────────────┐
│ ① ‹  공지                        ＋작성│ ← 크루장만
├──────────────────────────────────────┤
│ ② 크루원 모두에게 알릴 내용을 확인해요. │
├──────────────────────────────────────┤
│ ③ 📌 9월 정기 활동 안내              › │
│    9월 첫째 주 토요일, 여의도에서...    │
│    댓글 3개 · 9월 1일                 │
│ ④    새 크루원 환영합니다            › │
│      소개를 확인해 주세요.             │
│      댓글 0개 · 8월 28일               │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로 버튼 | "뒤로" | `AppHeader` | 3-1 |
| ① | 헤더 제목 | "공지" | `AppHeader` | — |
| ① | 작성 버튼 | 크루장만 "작성" | `Button` primary sm + `Icon`(plus) | 3-12 |
| ② | 안내 문구 | "크루원 모두에게 알릴 내용을 확인해요." | `Txt` caption muted | — |
| ③ | 최신 공지 행 | 최신 작성 공지를 뜻하는 읽기 전용 `pinned` true인 `title`·`preview`·`commentCount`·`createdAt` (`GET /crew/notices`) | `Card` + `Icon`(pin) + `Txt` + `Badge` | 3-6 |
| ④ | 일반 공지 행 | `pinned` false인 `title`·`preview`·`commentCount`·`createdAt` (`GET /crew/notices`) | `ListRow` + `Txt` + `Icon`(comment-outline) | 3-6 |
| ③·④ | 댓글 수 | "댓글 `commentCount`개" | `Txt` micro | 3-6 |
| ③·④ | 날짜 | `createdAt`을 "9월 1일"로 표시 | `Txt` micro muted | — |

목록은 `GET /crew/notices`의 `items`를 최신 `createdAt` 순으로 보인다. `pinned`는 최신 공지 한 건만 true인 파생 값이며 수동 고정은 없다. 마지막 `nextCursor`가 null이 아니면 목록 아래에서 다음 페이지를 받는다.

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | ①은 보이고 ③·④ 자리에 `Loading` "공지를 불러오고 있어요" | ① 뒤로·작성(크루장) |
| 새로고침 | 당겨서 새로고침. 기존 공지는 남기고 상단 스피너 | 행·작성·뒤로 |
| 빈 | `items`가 빈 배열. `EmptyState` "아직 공지가 없어요" / "크루장이 첫 공지를 작성하면 여기에 보여요." | 크루장은 작성 → 3-12 · 크루원은 뒤로 |
| 오류 | `GET /crew/notices` 4xx·5xx면 `ErrorState` "공지를 불러오지 못했어요" / [다시 시도] | 다시 시도 → 첫 페이지 재조회 |
| 오프라인 | 이전 공지가 있으면 그대로, ② 아래 `Banner` "인터넷 연결을 확인해 주세요.". 없으면 오류 상태 | 이전 행·뒤로 |
| 권한 거부 | **해당 없음.** MEMBER면 공지 읽기가 가능하다 | — |
| 부분 실패 | 첫 페이지는 성공했으나 다음 `nextCursor` 페이지가 실패하면 기존 목록 아래 "더 불러오지 못했어요." / [다시 시도] | 다시 시도 → 같은 cursor |
| 크루원 | ① 작성 버튼이 숨겨진다 | 공지 행·뒤로 |
| 크루장 | ① 작성 버튼이 보인다 | 전부 |

## 인터랙션

- 스크롤: 공지 목록을 세로 스크롤. 끝에 닿고 `nextCursor`가 있으면 다음 페이지를 받는다
- 당겨서 새로고침: 있음. 첫 cursor부터 다시 받고 최신 공지·댓글 수를 갱신한다
- 길게 누르기: 없음. 크루장의 수정·삭제은 3-6 상세의 메뉴에서 한다
- 시트: 없음
- 뒤로 가기: 3-1로 팝한다
- 키보드: 없음
- 공지 행 탭: 3-6으로 푸시한다. 해당 `id`를 넘긴다
- 전환: 작성·상세 모두 푸시. 작성 완료 뒤 돌아오면 첫 페이지를 새로고침한다

## 접근성

- 최신 행은 "최신 공지, 9월 정기 활동 안내, 댓글 3개, 9월 1일"로 읽는다
- 일반 행은 제목·본문 첫 줄·댓글 수·날짜·"공지 상세 보기"를 한 묶음으로 읽는다
- ① 작성 버튼은 "공지 작성, 크루장만 가능"으로 읽는다
- 행·작성 버튼·뒤로 버튼은 모두 48dp 이상이다

## 옛 화면과의 차이

- 옛 피드의 검색·전체/친구 탭·일반 게시물 카드·게시물 작성 버튼을 없앴다
- 새 목록은 공지만 보이며, 최신 공지 한 건이 자동으로 맨 위에 온다
- 작성은 모든 사람이 아니라 크루장만 할 수 있다
- 옛 피드의 사진 미리보기·좋아요 수 대신 공지 본문 첫 줄·댓글 수를 보인다

## 미결

- `preview`의 최대 길이·말줄임 줄 수는 계약에 없다. 현재는 2줄 말줄임으로 본다
