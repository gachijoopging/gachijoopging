# 3-3 초대 코드

**목적** 크루원 모두가 현재 초대 코드를 확인·복사·공유하고, 크루장은 필요하면 새 코드로 재발급해 새 크루원을 가입 신청으로 초대한다.
**원본** `../legacy/android-res/layout/fragment_meet_manage.xml`의 초대하기 버튼 · **변경** 초대 링크를 없애고 사람이 전달할 문자열 초대 코드만 남겼다. 코드 재발급은 옛 코드를 새 가입 신청에 대해 즉시 무효로 하고 기존 대기 신청은 유지한다.
**진입** 3-2 크루 정보의 "초대 코드" · **이탈** 3-2 크루 정보 · 1-8 초대 코드 입력(초대받은 사람의 별도 흐름)

## 배치

옛 관리 화면의 채팅 아래 초대 버튼 자리를 독립 화면으로 확장한다. 가운데에 큰 코드 카드, 복사·공유 버튼, 재발급 링크와 주의 안내를 세로로 둔다.

```
┌──────────────────────────────────────┐
│ ① ‹  초대 코드                        │
├──────────────────────────────────────┤
│ ② 크루원에게 이 코드를 보내세요         │
│                                      │
│ ③ ┌────────────────────────────────┐ │
│    │          HG-7K2P                │ │
│    │     [ 코드 복사 ] [ 공유 ]       │ │
│    └────────────────────────────────┘ │
│                                      │
│    [        새 코드 만들기        ]     │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로 버튼 | "뒤로" | `AppHeader` | 3-2 |
| ① | 헤더 제목 | "초대 코드" | `AppHeader` | — |
| ② | 제목 | "크루원에게 이 코드를 보내세요" | `Txt` display | — |
| ③ | 코드 카드 | `inviteCode` (`GET /crew`) 예: "HG-7K2P". 문자 간 넓은 간격 | `Card` + `Txt` counter | — |
| ③ | 코드 복사 버튼 | "코드 복사" | `Button` primary lg | 시스템 클립보드에 `inviteCode` 복사 |
| ③ | 공유 버튼 | "공유" | `Button` soft lg | 초대 코드를 OS 기본 공유 시트로 전달. 사용자가 앱·수신자를 선택 |
| ④ | 새 코드 만들기 버튼 | 크루장(`isLeader` true)만 "새 코드 만들기" | `Button` ghost md | 확인 대화상자 → `POST /crew/invite-code` |

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | ①은 보이고 ②~④는 `Loading` "초대 코드를 불러오고 있어요" | ① 뒤로 |
| 새로고침 | 당겨서 새로고침. 기존 코드가 남고 상단 스피너 | 복사·공유·뒤로 |
| 빈 | **해당 없음.** MEMBER 크루에는 서버가 만든 초대 코드가 항상 있다 | 코드 복사·공유 |
| 오류 | `GET /crew` 실패면 `ErrorState` "초대 코드를 불러오지 못했어요" / [다시 시도] | 다시 시도 |
| 오프라인 | 이전 코드가 있으면 그대로 보이고 `Banner` "인터넷 연결을 확인해 주세요.". 복사·공유는 가능하지만 재발급은 실패한다 | 복사·공유·뒤로 |
| 권한 거부 | **해당 없음.** 권한을 쓰지 않는다 | — |
| 부분 실패 | **해당 없음.** 코드와 역할은 `GET /crew` 하나에서 받는다 | — |
| 크루원 | ④ 새 코드 만들기가 숨겨진다. 코드 복사·공유 가능 | ①·③ |
| 크루장 | ④ 재발급 버튼이 보인다 | 전부 |
| 재발급 중 | ④ 버튼 자리에 스피너, 복사·공유·뒤로도 비활성 | 없음 |

재발급 확인 대화상자: 제목 "새 초대 코드를 만들까요?" · 버튼 [취소] / [새 코드 만들기]. `POST /crew/invite-code` 200이면 `data.inviteCode`로 ③을 교체하고 `Snackbar` "새 초대 코드를 만들었어요.". 4xx·5xx·오프라인이면 코드 카드 원값을 유지하고 "새 코드를 만들지 못했어요. 다시 시도해 주세요." `Snackbar`.

## 인터랙션

- 스크롤: 없음. 작은 화면에서는 ②~④만 세로 스크롤
- 당겨서 새로고침: 있음. `GET /crew` 재조회
- 길게 누르기: 코드 카드 길게 누르기는 복사와 같다
- 시트: 공유 버튼은 OS 기본 공유 시트를 연다. 닫아도 초대 성공으로 표시하지 않는다
- 뒤로 가기: 3-2로 팝한다
- 키보드: 없음
- 코드 복사: 시스템 클립보드에 복사하고 `Snackbar` "초대 코드를 복사했어요.". 클립보드를 읽거나 공유 링크를 만들지 않는다
- 전환: 3-2에서 푸시. 재발급은 화면 안에서 코드만 바꾼다

## 접근성

- ③ 카드: "초대 코드 H G 7 K 2 P"처럼 글자마다 읽는다
- 코드 복사: "초대 코드 복사"
- ④ 경고·대화상자는 나타나는 즉시 읽는다(live region)
- 모든 버튼은 48dp 이상이다

## 옛 화면과의 차이

- 옛 "초대하기"는 초대 링크를 복사했다. 새 화면은 링크 없이 초대 코드를 복사하거나 OS 기본 공유 시트로 전달한다
- 옛 코드 재발급 규칙이 없었다. 새 재발급은 옛 코드를 새 가입 신청에 대해 즉시 무효로 하고 기존 대기 신청은 유지한다
- 옛 관리 화면 안 보조 버튼이 독립 화면의 큰 코드 카드가 됐다

- 거절·추방된 사람도 현재 유효한 코드로 다시 가입 신청할 수 있다. 재발급이나 개별 메시지 전송은 재신청의 필수 조건이 아니다.
- 공유 버튼은 "초대 코드 공유"로 읽고 최소 48dp 터치 영역을 제공한다.

## 미결

- 코드 형식·만료 여부는 1-8과 같이 계약에 없다
