# 1-8 초대 코드 입력

**목적** 크루장에게 받은 초대 코드로 크루를 확인하고 가입 신청을 낸다.
**원본** `../legacy/android-res/layout/fragment_invite_redeem.xml` · **변경** 옛 화면은 초대 링크를 타고 들어와 스피너·상태 문구·다시 시도·취소만 있는 처리 화면이었다. 새 화면은 코드를 손으로 넣는 입력 화면이고, 확인된 크루를 카드로 먼저 보여 준 뒤 가입 신청을 보낸다. 링크 딥링크는 없다(초대 코드만 쓴다)
**진입** 1-6 크루 만들기/가입하기의 "가입하기" · **이탈** 가입 신청 성공 → 1-9 승인 대기 · 뒤로 가기 → 1-6

화면은 두 단계다. **① 코드 입력** — 코드를 넣고 "크루 찾기" 를 누른다. **② 크루 미리보기** — 확인된 크루 카드가 입력창 자리에 뜨고 "가입 신청" 을 누른다. 같은 화면 안에서 바뀌며 화면 이동은 없다.

## 배치

옛 XML 은 가운데 정렬 세로 묶음(스피너 → 상태 문구 → 다시 시도 → 취소) 하나였다. 그 뼈대(가운데 묶음 + 아래 주 버튼 + 그 아래 보조 버튼)는 남기고, 위에 1-4 와 같은 헤더·배지·큰 제목·설명을 얹어 온보딩 형제 화면들과 모양을 맞췄다. 스피너는 버튼 안으로 들어갔다. 헤더 아래가 세로 스크롤 영역이고, 키보드가 올라오면 주 버튼까지 보이도록 밀려 올라간다.

```
 │ ① ‹  크루 가입하기                      │   │ ① ‹  크루 가입하기                      │
 ├──────────────────────────────────────┤   ├──────────────────────────────────────┤
 │ ② 초대 코드를 입력해 주세요              │   │ ② 이 크루가 맞나요?                     │
 │                                      │   │                                      │

 │    │ 예: HG-7K2P                   │   │   │    │       크루원 18명                │   │
 │    └──────────────────────────────┘   │   │    │  (◉) 크루장 관열                  │   │
 │    초대 코드를 찾을 수 없어요. 코드를 다시… │   │    │  매주 토요일 아침 여의도           │   │
 │                          ← 평소 숨김  │   │    │       초대 코드 HG-7K2P           │   │
 │                                      │   │    └──────────────────────────────┘   │

 │                                      │   │ ⑥           다른 코드 입력              │
 └──────────────────────────────────────┘   └──────────────────────────────────────┘
```

## 인터랙션

- 스크롤: 헤더 아래가 세로 스크롤. 키보드가 올라오면 ⑤ 가 키보드 위로 보이도록 밀린다. 키보드가 없으면 두 단계 모두 한 화면에 다 들어간다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음. 입력창의 붙여넣기는 OS 기본 동작(길게 눌러 붙여넣기)에 맡긴다
- 시트: 없음
- 뒤로 가기: 헤더 뒤로 버튼과 시스템 뒤로 가기 모두 같다. **1단계** — 1-6 으로 돌아간다(팝). 입력한 코드는 버린다. **2단계** — 1-6 으로 돌아간다. 카드는 서버에 아무것도 남기지 않았으므로 확인 없이 나간다(2단계에서 1단계로 되돌리는 것은 ⑥ 이 맡는다). 확인 중·신청 중에는 무시
- 키보드: 진입 즉시 ③ 에 포커스. 입력은 대문자로 들어가고 앞뒤 공백만 제거해 보낸다. 키보드의 완료(Done) 키는 1단계 ⑤ 와 같다 — 비어 있지 않으면 `GET /crews/preview`, 비어 있으면 검증 문구. 입력창 밖을 누르면 키보드가 내려간다. 2단계로 바뀔 때 키보드를 내린다
- 단계 전환: 1→2 는 ③ 이 사라지고 ④⑥ 이 나타나며 ②⑤ 의 문구가 바뀐다. 짧게 페이드. 2→1(⑥ 또는 2단계 404)은 반대로 되돌리고 ③ 에 포커스를 넣는다
- 전환: 1-6 → 1-8 은 푸시. 1-9 로 갈 때는 이 화면과 1-6 을 스택에서 지운다 — 1-9 에서 뒤로 가기로 코드 입력 화면에 돌아오지 않는다(신청 취소는 1-9 가 `DELETE /crews/join-requests/mine` 으로 맡는다). 409 로 2-1 에 갈 때도 같다. 오류 문구·`Snackbar` 는 나타날 때만 짧게 페이드

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - ① 뒤로 버튼: "뒤로" · 헤더 제목: "크루 가입하기"
  - ② 큰 제목: 본문 그대로. 2단계로 바뀔 때 새 큰 제목을 읽어 준다(live region)
  - ③ 입력창: 라벨 "초대 코드", 힌트 "크루장에게 받은 코드". 오류 문구는 나타나는 순간 읽어 주고(live region) 입력창과 연결한다
  - ④ 카드: 하나로 묶어 "한강줍깅크루, 크루원 18명, 크루장 관열, 매주 토요일 아침 여의도, 초대 코드 HG-7K2P". 소개가 비어 있으면 그 부분을 뺀다. 얼굴 두 개는 읽지 않는다(이름이 대신한다). 코드는 글자 하나씩 읽도록 표시한다
  - ⑤: 1단계 "크루 찾기" · 2단계 "가입 신청하기". 비활성이면 비활성으로 읽힌다. 확인 중이면 "확인 중", 신청 중이면 "신청 중"
  - ⑥: "다른 코드 입력"
  - `Snackbar`: 나타나는 순간 문구를 읽어 준다
- 최소 터치 크기 예외: 없음. ③ 입력창·⑤ 버튼은 48dp 이상. ⑥ 은 md 버튼이라 48dp 를 채운다

## 옛 화면과의 차이

- 옛 화면은 초대 **링크**(`toast_invite` "초대 링크를 복사했어요")를 타고 들어와 자동으로 처리하는 화면이었다(스피너 + "초대를 확인하고 있어요") → 초대 코드를 손으로 넣는 입력 화면. 기능범위가 초대 링크를 끄고 초대 코드만 남겼다
- 스피너(`progress`)·상태 문구(`statusText`) → 버튼 안 스피너. "초대를 확인하고 있어요" 문구는 쓰지 않는다
- "다시 시도"(`retryButton`) → 없음. 다시 시도는 주 버튼을 다시 누르는 것이다. "취소"(`cancelButton`) → "다른 코드 입력"(2단계) 과 헤더 뒤로 버튼이 나눠 맡는다
- 크루 미리보기 카드는 새로 생겼다. 옛 화면은 어느 모임인지 보여 주지 않고 바로 참여시켰다
- 옛 오류 문구 중 살린 것: "초대를 확인하지 못했어요. 네트워크 상태를 확인하고 다시 시도해 주세요."(`invite_error_retryable`) 는 `Snackbar` 로 그대로. "유효하지 않거나 만료된 초대 링크예요."(`invite_error_invalid`) → "초대 코드를 찾을 수 없어요. 코드를 다시 확인해 주세요." 링크가 코드로 바뀌었다. "이 모임에는 참여할 수 없어요."(`invite_error_blocked`) · "모임 정원이 모두 찼어요."(`invite_error_full`) · "이미 종료되었거나 참여할 수 없는 모임이에요."(`invite_error_closed`) → 쓰지 않는다. 크루 정원·가입 차단이 없어 해당 오류가 없다
- "모임 목록으로"(`invite_to_meets`) → 없음. 모임 목록이 사라졌다
- 옛 화면은 승인 없이 바로 멤버가 됐다(`toast_meet_joined` "모임에 참여했어요") → 가입 신청을 내고 1-9 승인 대기로 간다
- 헤더·배지·큰 제목·설명·입력창 라벨·플레이스홀더·"크루 찾기"·"가입 신청하기"·"다른 코드 입력"·"초대 코드를 입력해 주세요."·"초대 코드 형식이 올바르지 않아요."·"이미 크루에 소속돼 있어요." 는 새로 정했다
