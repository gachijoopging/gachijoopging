# 1-2 로그인

**목적** 이메일 계정이 있는 사람이 이메일·비밀번호로 로그인해 자기 크루로 들어간다.
**원본** `../legacy/android-res/layout/fragment_login.xml` · **변경** 배치·문구·검증 규칙은 그대로. 로그인 뒤 갈 곳이 동네 선택이 아니라 소속 상태(`membership.status`)로 갈리고, 서버 오류 배너 자리를 새로 잡았다
**진입** 시작(1-1)의 "✉️ 이메일로 로그인" · **이탈** 비밀번호 재설정(1-5) · 회원가입(1-3) · 로그인 성공 뒤 소속 상태에 따라 크루 선택(1-6) · 승인 대기(1-9) · 홈(2-1)

## 배치

옛 XML 의 세로 순서(헤더 → 워드마크·헤드라인·설명 → 이메일 라벨·입력·오류 → 비밀번호 라벨·입력(보기 칩)·오류 → 로그인 버튼 → 링크 두 개)를 그대로 따른다. 헤더만 고정이고 그 아래는 통째로 스크롤 영역이라 키보드가 올라와도 버튼까지 밀어 올릴 수 있다. 오류 배너 ⑥ 은 옛 XML 에 없던 자리로, 비밀번호 오류 문구와 로그인 버튼 사이에 넣었다.

│                                      │
│ ④ 비밀번호                              │

검증은 ⑤ 를 누르는 순간 한 번에 한다. 입력 중에는 오류를 띄우지 않고, 오류가 떠 있는 필드는 글자를 고치는 순간 오류를 지운다.

| 필드 | 규칙 | 걸리면 |
|---|---|---|
| 이메일 | 앞뒤 공백을 지운 뒤 `@` 가 하나 있고, `@` 뒤에 `.` 이 든 도메인이 있어야 한다. 빈 값도 걸린다 | ③ 오류 "이메일 형식이 올바르지 않아요. @와 도메인을 확인해 주세요." |
| 비밀번호 | 8자 이상. 빈 값도 걸린다. 비밀번호 원문은 공백 제거·줄바꿈 제거·대소문자 변환하지 않는다 | ④ 오류 "비밀번호는 8자 이상이어야 해요." |

둘 다 걸리면 둘 다 보여 주고 이메일에 포커스를 준다. 하나만 걸리면 그 필드에 포커스. 통과하면 서버를 부른다. ⑤ 는 항상 눌린다 — 빈 채로 눌러도 비활성 대신 오류 문구로 알려 준다(옛 앱과 같다).

로그인·자동 로그인 뒤 `profileComplete` false면 소셜 닉네임 설정(1-4)을 우선 재개하고, 닉네임과 필수 동의 완료가 확인된 계정은 다음 소속 분기를 따른다. `profileComplete`는 동의 완료를 뜻하지 않는다. 상태 조회 실패 시 인증·계정별 미동기화 활동을 보존한다.

| 순서 | 보는 것 | 값 | 가는 곳 |
|---|---|---|---|
| 1 | `POST /auth/login` 응답 `data.accessToken`·`data.refreshToken` | 200 | 토큰 저장 후 `GET /users/me` 조회 → 2. 자동 로그인·재로그인도 동일 |
| 2 | `GET /users/me` 응답 `profileComplete` | false | 1-4 닉네임 설정 재개. 소속 분기는 아직 실행하지 않는다 |
| 2 | 같은 응답 `profileComplete` | true | 닉네임 완료만 확인됨 → 3. 필수 동의 완료로 추정하지 않는다 |
| 3 | `GET /users/me/agreements` 응답 `complete` | false | 1-4 동의 단계(약관 버전이 올라 재동의가 필요한 경우 포함). 소속 분기로 넘기지 않는다 |
| 3 | 같은 조회 | 실패 | 이 단계에서 재시도한다. 완료로 간주하거나 소속 분기로 넘기지 않는다 |
| 3 | 같은 응답 `complete` | true | 4로 |
| 4 | `GET /users/me` 응답 `membership.status` | MEMBER | 2-1 홈 (승인 대기 중 승인된 경우 포함) |
| 4 | 같은 응답 | PENDING | 1-9 승인 대기 |
| 4 | 같은 응답 | NONE 이고 `membership.rejection` 있음 | 1-9 거절 안내 ([확인] 뒤 1-6) |
| 4 | 같은 응답 | NONE 이고 `membership.rejection` null | 1-6 크루 선택 |

## 인터랙션

- 스크롤: ① 헤더는 고정, 그 아래 ②~⑦ 이 세로 스크롤. 키보드가 없을 때는 보통 한 화면에 들어간다. 키보드가 올라오면 포커스된 입력이 가리지 않게 밀어 올린다. 스크롤바는 그리지 않는다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음(입력창의 기본 선택·붙여넣기만)
- 시트: 없음
- 뒤로 가기: 1-1 시작으로 돌아간다. 입력한 값은 버린다(확인 없음). 진행 중에는 결과 확인까지 이탈을 잠근다
- 키보드: 이메일 입력의 완료 키는 "다음"(→ 비밀번호로 포커스), 비밀번호 입력의 완료 키는 "완료"(→ ⑤ 와 같은 동작). 이메일 키보드는 이메일용(@ 노출), 자동 대문자·자동 교정 끔. 입력 바깥을 탭하면 키보드를 내린다
- 보기 칩: 가림 ↔ 보임을 바꿔도 포커스·커서 위치·값은 그대로. 진행 중에는 눌리지 않는다
- 자동 완성: 두 입력에 이메일·비밀번호 자동 완성 힌트를 준다. 채워지면 검증 오류를 지운다
- 전환: 1-3 · 1-5 는 푸시(뒤로 가기로 1-2 에 돌아온다). 로그인 성공 뒤 1-6 · 1-9 · 2-1 으로 갈 때는 1-1 과 1-2 를 스택에서 지운다 — 뒤로 가기로 로그인 화면에 되돌아오지 않는다. 오류 문구·배너는 나타날 때만 짧게 페이드

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - ① 뒤로: "뒤로"
  - 워드마크: "가치줍깅"
  - 헤드라인·설명: 본문 그대로 읽는다
  - ③: "이메일" · 오류가 있으면 오류 문구를 뒤에 붙여 읽는다 · ④: "비밀번호" (가림 상태는 시스템이 "비밀번호 입력" 으로 읽는다)
  - 보기 칩: "비밀번호 보기" / "비밀번호 숨기기" — 화면 글자 "보기"/"숨기기" 만으로는 무엇을 보이는지 모른다
  - ⑤: "로그인" · 진행 중엔 라벨 그대로 `busy` 상태로 읽히고(디자인 시스템 `Button` 결정) 나머지는 비활성으로 읽힌다
  - 검증 오류 문구·⑥ 배너: 나타나는 순간 읽어 준다(live region). 검증에 걸리면 포커스도 그 필드로 옮긴다
  - ⑦: "비밀번호를 잊으셨나요? 비밀번호 재설정으로 이동" · "회원가입으로 이동"
- 최소 터치 크기 예외: 없음. ⑤ 는 lg 버튼, 입력창은 48dp. 보기 칩은 보이는 높이가 28dp 라 위아래 10dp 를 터치 영역에 넣어 48dp 를 채운다(옛 `bg_chip_neutral_touch` 와 같다). ⑦ 두 링크는 글자가 작아 위아래 여백까지 터치 영역에 넣어 48dp 를 채우고, 둘 사이 간격을 두어 잘못 누르지 않게 한다

## 옛 화면과의 차이

- 로그인 뒤: 옛 앱은 동네 선택으로 갔다 → `membership.status` 로 1-6 · 1-9 · 2-1 이 갈린다
- 헤더 제목 "이메일 로그인" / 부제 "기존 계정", 워드마크, 헤드라인 "다시 만나서 반가워요", 설명 두 줄은 그대로. "줍깅" 은 우리 용어라 살렸다
- 라벨·자리 글·검증 문구·"로그인"·"비밀번호를 잊으셨나요?"·"회원가입"·"보기/숨기기" 전부 그대로
- 서버 오류 배너 ⑥ 은 새 자리다. 옛 XML 에는 `err_credentials` 문구만 있고 보여 줄 뷰가 없었다. 1-1 의 소셜 오류 배너와 같은 `Banner` danger 를 쓴다
- 진행 중 표시(버튼 스피너·나머지 비활성)와 429·기타 오류 문구는 새로 정했다 — 옛 XML·strings 에 없다
