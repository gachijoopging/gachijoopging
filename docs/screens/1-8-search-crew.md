# 1-8 크루 검색

**목적** 크루가 없는 사람이 크루 이름이나 활동 지역으로 기존 크루를 찾아 골라 가입한다. 공개 크루는 바로 크루원이 되고, 비공개 크루는 가입 신청을 보낸다.
**원본** 신규 — `../legacy/android-res/layout/fragment_hood.xml` 의 검색 입력·후보 목록 부품 · **변경** 옛 초대 코드 입력 화면(`fragment_invite_redeem`)을 대신한다. 초대 코드는 끔(2026-10 회의)
**진입** 1-6 의 "기존 크루에 들어가기" · **이탈** 공개 크루 가입 성공 → 2-1 홈 · 비공개 크루 가입 신청 성공 → 1-9 승인 대기 · 빈 결과의 [크루 만들기] → 1-7 · 뒤로 가기 → 1-6

미가입자만 온다. 소속이 있거나 승인 대기 중이면 서버가 409 로 막는다 — 승인 대기 중인 사람은 1-9 에서 [요청 취소]를 한 뒤에 이 화면을 쓴다. 검색은 `GET /crews`, 가입은 `POST /crews/join-requests` 하나로 한다. 가입 뒤 이동은 응답 `data.status` 로 정한다 — 응답이 기준이다(검색 뒤 크루장이 가입 방식을 바꿨을 수 있다).

## 배치

헤더 아래에 검색 입력창과 지역 선택을 고정하고, 그 아래를 결과 목록이 채운다. 들어오자마자 전체 크루가 이름순으로 보인다. 행을 누르면 가입 확인 시트가 올라온다.

```
┌──────────────────────────────────────┐
│ ① ‹  크루 찾기                         │
├──────────────────────────────────────┤
│ ② [🔍 크루 이름으로 찾기          ✕ ]   │
│ ③ [지역: 전체 ▾]                       │
├──────────────────────────────────────┤
│ ④ (◯) 한강망원줍깅        [공개]    › │
│        서울특별시 · 크루원 50/50명       │
│        정원이 찼어요                    │
│ ④ (◯) 한강줍깅크루        [비공개]  › │
│        서울특별시 · 크루원 18/50명       │
│        매주 토요일 아침 여의도           │
└──────────────────────────────────────┘
```

가입 확인 시트 (④ 행을 누르면 올라온다)

```
├──────────────────────────────────────┤
│ ⑤            ▬▬▬▬                    │
│    (◯) 한강줍깅크루         [비공개]     │
│        크루장 관열 · 크루원 18/50명       │
│        서울특별시                       │
│        매주 토요일 아침 여의도            │
│    크루장이 승인하면 크루원이 돼요.        │
│ ⑥ [          가입 신청하기          ]   │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로 버튼·제목 | "크루 찾기" | `AppHeader` | 1-6 |
| ② | 검색 입력창 | 플레이스홀더 "크루 이름으로 찾기". 앞뒤 공백을 지운 값이 `query`(이름 부분 일치). 키보드 검색 키로 `GET /crews` 를 다시 부른다. 비우면 `query` 없이 부른다. 지우기 버튼은 입력이 있을 때만 | `Field` | 키보드 |
| ③ | 지역 선택 | "지역: 전체" 또는 "지역: 서울특별시". 고르면 `region` 으로 바로 다시 부른다. 검색어와 함께 쓰면 둘 다 맞는 크루 | `Chip` | 지역 시트(맨 위 "전체" + 시·도 17개, `BottomSheet` + `ListRow`) |
| ④ | 결과 행 | `items` (`GET /crews`, 크루 이름 오름차순). `photoUrl`(null 이면 `name` 첫 글자) · `name` · `joinPolicy` 배지 · `region` 이름 · "크루원 `memberCount`/50명" · `intro` 1줄(빈 문자열이면 줄을 그리지 않는다) | `ListRow` + `Avatar` md + `Txt` + `Badge` | ⑤ 가입 확인 시트 |
| ④ | 가입 방식 배지 | `joinPolicy` OPEN → "공개", APPROVAL → "비공개". 승인 필요 여부일 뿐 두 유형 모두 결과에 나온다 | `Badge` | — |
| ④ | 정원 표시 | `memberCount` 가 50 이면 "정원이 찼어요" 를 `intro` 줄 대신 보인다. 공개·비공개 모두 가입·신청이 안 된다 | `Txt` caption muted | — |
| ⑤ | 가입 확인 시트 | 고른 행의 값을 그대로 보인다(다시 부르지 않는다). `leader.nickname` "크루장 관열" · "크루원 `memberCount`/50명" · `region` · `intro` 전문. 안내 문구는 OPEN "바로 크루원이 돼요." · APPROVAL "크루장이 승인하면 크루원이 돼요." · 정원이 찬 크루(공개·비공개 모두) "정원(50명)이 차서 지금은 가입할 수 없어요. 자리가 생기면 다시 신청할 수 있어요." | `BottomSheet` + `Avatar` lg + `Txt` + `Badge` | 스크림·뒤로·끌기 → 닫기(요청 중에는 닫히지 않는다) |
| ⑥ | 가입 버튼 | OPEN "가입하기" · APPROVAL "가입 신청하기". 50명이면 공개·비공개 모두 비활성 | `Button` primary lg | `POST /crews/join-requests` (`crewId` = 고른 행의 `id`) |

정원이 찬 비공개 크루에는 새 신청을 할 수 없다(자리가 생기면 다시 신청). 추방된 적이 있는 크루에는 공개·비공개 모두 가입·신청할 수 없다. 앱은 추방 이력을 미리 알 수 없으므로 서버 403 으로 안내한다.

서버 응답. 오류 봉투의 `code` 로 갈린다. `message` 는 화면에 쓰지 않는다.

| 요청 | 응답 | 보이는 것 |
|---|---|---|
| `GET /crews` | 200 | 결과 행. 비었으면 빈 상태 |
| `GET /crews` | 422 VALIDATION | ② 아래 "검색어를 다시 확인해 주세요." |
| 둘 다 | 409 ALREADY_IN_CREW | `Snackbar` "이미 크루에 소속돼 있어요." 뒤 `GET /users/me` 대로 2-1 |
| 둘 다 | 409 JOIN_REQUEST_PENDING | `Snackbar` "승인 대기 중인 가입 요청이 있어요." 뒤 1-9 (다른 기기에서 신청한 경우) |
| `POST /crews/join-requests` | 201 `status` APPROVED | 공개 크루 가입 완료. `Snackbar` "{crew.name}에 가입했어요." 뒤 온보딩 스택을 지우고 2-1 |
| `POST /crews/join-requests` | 201·200 `status` PENDING | 비공개 크루 신청 완료(200 은 같은 크루에 이미 대기 중이던 신청). 온보딩 스택을 지우고 1-9 |
| `POST /crews/join-requests` | 409 CREW_FULL | 시트 안 `Banner` "정원(50명)이 차서 가입할 수 없어요. 자리가 생기면 다시 신청할 수 있어요." ⑥ 비활성. 결과를 다시 부른다 |
| `POST /crews/join-requests` | 403 EXPELLED_FROM_CREW | 시트 안 `Banner` "이 크루에서 내보내져 다시 가입할 수 없어요." ⑥ 비활성 |
| `POST /crews/join-requests` | 404 NOT_FOUND | 시트를 닫고 `Snackbar` "크루를 찾을 수 없어요. 다시 검색해 주세요." 결과를 다시 부른다(크루가 해산됐다) |
| 둘 다 | 그 외 4xx·5xx·네트워크 실패 | 검색은 `ErrorState`, 가입은 시트 안 `Banner` "가입하지 못했어요. 네트워크 상태를 확인하고 다시 시도해 주세요." 시트와 고른 크루는 남긴다 |

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | `query`·`region` 없이 `GET /crews` 로 전체 크루를 부른다. ④ 자리에 `Loading` "크루를 불러오고 있어요" | ①·②·③ |
| 검색 중 | 이전 결과를 남기고 상단 스피너 | ①·②·③ |
| 새로고침 | 당겨서 새로고침은 지금 `query`·`region` 으로 첫 장을 다시 부른다 | ①·②·③·④ |
| 빈 | 결과 0건. 조건이 있으면 `EmptyState` "조건에 맞는 크루가 없어요" / "이름이나 지역을 바꿔 보거나 크루를 새로 만들어 보세요." [크루 만들기], 조건이 없으면(크루가 하나도 없음) "아직 크루가 없어요" / [크루 만들기] | ①·②·③ · 크루 만들기 → 1-7 |
| 오류 | 검색 실패면 `ErrorState` "크루를 불러오지 못했어요" / [다시 시도]. 가입 실패는 위 응답 표대로 시트 안에서 | 다시 시도 |
| 오프라인 | 첫 진입이면 오류 상태, 결과가 있으면 그대로 두고 검색·가입을 누를 때 네트워크 실패 문구 | ①·②·③ |
| 권한 거부 | **해당 없음.** 위치·카메라·사진·알림 권한을 쓰지 않는다 | — |
| 부분 실패 | **해당 없음.** 단계마다 요청이 하나다. 다음 장 이어 받기 실패는 목록 끝에 [다시 시도] 행 | 다시 시도 |
| 가입 중 | ⑥ 라벨 자리에 스피너. 시트·목록 모두 비활성 | 없음. 뒤로 가기도 무시 |
| 권한별 차이 | 미가입자만 쓴다(권한표 "크루 검색"). 크루원·크루장·승인 대기자는 409 로 막히고 각자 화면으로 간다 | — |

## 인터랙션

- 스크롤: ②·③ 은 고정, ④ 결과만 세로 스크롤. 끝에 닿으면 `nextCursor` 로 다음 장을 붙인다(null 이면 멈춤)
- 당겨서 새로고침: 있음
- 길게 누르기: 없음
- 시트: ③ 지역 시트, ⑤ 가입 확인 시트. 열려 있을 때 시스템 뒤로 가기는 시트를 닫는다
- 뒤로 가기: 1-6 으로 팝. 검색어·지역은 버린다. 가입 중에는 무시
- 키보드: 진입 때는 키보드를 올리지 않는다(전체 목록을 먼저 본다). ② 를 누르면 올라오고 검색 키 = 검색. 결과를 스크롤하면 내린다
- 중복 요청: 같은 조건으로 검색 중이면 다시 부르지 않는다. 조건이 바뀌면 앞 요청 결과를 버린다. ⑥ 은 첫 탭 뒤 잠근다
- 전환: 1-6 → 1-8 은 푸시. 2-1·1-9 로 갈 때는 1-6·1-8 을 스택에서 지운다 — 뒤로 가기로 검색에 돌아오지 않는다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - ②: 라벨 "크루 이름으로 찾기", 결과가 바뀌면 "크루 N개" 를 읽는다(live region)
  - ③: "지역, 전체" 또는 "지역, 서울특별시, 바꾸기"
  - ④: "한강줍깅크루, 비공개, 서울특별시, 크루원 18명, 정원 50명, 매주 토요일 아침 여의도". 정원이 찼으면 "정원이 찼어요" 를 붙인다. 얼굴은 읽지 않는다
  - ⑤: 시트가 열리면 크루 이름과 안내 문구를 먼저 읽는다
  - ⑥: "한강줍깅크루 가입 신청하기" 또는 "한강망원줍깅 가입하기". 가입 중이면 "가입 중"
- 최소 터치 크기 예외: 없음. ③·결과 행 전체·⑥ 는 48dp 이상

## 옛 화면과의 차이

- 초대 코드 입력·크루 미리보기 두 단계를 크루 검색 → 가입 확인 시트로 바꿨다. 초대 코드는 끔(2026-10 회의)
- 옛 초대 코드 화면은 모두 가입 신청이었다. 이제 공개 크루는 바로 크루원이 되고 비공개 크루만 1-9 승인 대기로 간다
- 옛 `fragment_hood` 의 검색 입력·후보 목록 모양을 가져왔지만 동네가 아니라 크루를 찾는다. 지역은 시·도 단위다
