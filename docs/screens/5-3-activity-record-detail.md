# 5-3 활동 기록 상세

**목적** 활동의 날짜·시간·거리·줍기 항목·사진·경로를 본다. 본인은 크루를 나간 뒤에도 자기 기록을 보고 항목을 수정·삭제한다.
**원본** `../legacy/android-res/layout/fragment_record_detail.xml` · `sheet_record_items.xml` · **변경** 사진은 조회만, 항목은 본인만 카테고리·수량 수정·삭제. 공유는 요약 이미지다.
**진입** 5-5 내 정보(소속 없는 기록 모드 포함) · 5-4 타인 프로필 · 4-7 저장 완료 요약 · **이탈** 뒤로 → 진입 화면 · 5-6 게시물 작성(본인·저장 완료·소속 있음)

## 배치

헤더만 고정하고 지도·지표·사진·공유 버튼까지 본문 전체를 스크롤한다. 그림 높이를 먼저 줄여도 지표와 기능은 남긴다. 사진 순서·대표 지정 기능은 없다.

```
┌──────────────────────────────────────┐
│ ① [‹ 뒤로] 활동 기록 상세      [⋯]  │
├──────────────────────────────────────┤
│ ② 2026년 9월 5일 오후 6:02          │
│             경로 지도                │
├──────────────────────────────────────┤
│ ③ 27개 · 1시간 8분 · 3.1km         │
│    5,200보 (미측정이면 이 줄 생략)    │
├──────────────────────────────────────┤
│ ④ 담배꽁초 14 · 플라스틱 6 · …      │
│     [줍기 목록 수정] ← 본인만        │
├──────────────────────────────────────┤
│ ⑤ 활동 사진 모음              1/3   │
│             (현재 사진)              │
│      [이전 사진] [다음 사진]          │
│       [썸네일] [썸네일] [썸네일]     │
├──────────────────────────────────────┤
│ ⑥ 경로를 크루원에게 공유하지 않음    │
│ ⑦ [피드에 공유하기] ← 본인·저장 완료│
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 뒤로·제목 | "활동 기록 상세" | `AppHeader` | 진입 화면, 목록 위치 유지 |
| ① | 메뉴 | 본인임이 확인된 저장 완료 활동만 [삭제하기]. 타인은 관리 메뉴 없음 | `Icon`(dots-horizontal) | 삭제 확인 |
| ② | 날짜 | `startedAt`, KST 날짜·시각 | `Txt` body | — |
| ② | 지도 | `route`가 있으면 본인은 `locationShared`와 무관하게 조회. 타인은 현재 같은 크루에서 이루어진 활동이며 `locationShared`가 true인 경우만 경로 조회. 공유 끈 타인의 경로 데이터는 서버도 제공하지 않음 | 정적 지도 이미지 | — |
| ③ | 지표 | `itemCount`·`durationSec`·`distanceM`·측정한 `steps`. 1분 미만은 초로 표시하고 0개·짧은 활동도 정상 표시. 미측정 걸음은 줄 자체 생략 | `Tile` + `Txt` | — |
| ④ | 분류 요약 | `byCategory`의 수량 있는 카테고리를 전부 표시. 최대 7종, 줄바꿈 | `Chip` | — |

| ⑦ | 공유 | 본인·서버 저장 완료·현재 소속 있음일 때 "피드에 공유하기" | `Button` primary | 날짜·시각·거리·시간·개수와 측정된 걸음을 요약 이미지로 생성해 5-6. 경로 포함은 별도 선택, 기본 끔 |

공유 이미지의 경로 선택은 활동의 `locationShared`와 별개다. 게시물은 독립 이미지이므로 활동 참조·게시물 역조회·게시물 보기 버튼이 없다. 활동을 삭제해도 이미 게시한 이미지는 남는다. 미측정·권한 없음·비걷기 활동은 유효한 기록이며 걸음을 임의로 0으로 채우지 않는다.

## 줍기 목록 편집 시트

본인 여부는 상세 응답 `user.id`와 로그인 `id`로 확인한 뒤 버튼을 연다. 7종 카테고리 선택과 수량 입력, 삭제만 제공한다.

| 요소 | 내용 | 컴포넌트 |
|---|---|---|
| 제목 | "줍기 항목 수정" | `Txt` title |
| 항목 | `items`의 항목별 카테고리 선택·1 이상 정수 수량·출처(AI/직접)·[삭제] | `SelectRow` + `Field` number + `Button` |
| 수량 | 48dp [−]/[+]와 직접 숫자 입력. 0으로 삭제하지 않고 [삭제] 사용 | `Field` + `Button` |
| 삭제 | 확인 후 해당 `DELETE /activities/{id}/items/{itemId}`. 성공 항목만 제거 | `Button` danger |
| 저장 | 바뀐 항목을 각 `PATCH /activities/{id}/items/{itemId}`로 카테고리·수량 저장. 순차 실행, 성공 항목 표시를 유지하고 실패 항목만 재시도 | `Button` primary |
| 오류 | 입력 오류는 항목 아래, 요청 오류는 시트 안 배너와 [다시 시도]. 입력을 유지 | `Field` error + `Banner` |
| 빈 | "아직 담긴 항목이 없어요". 기록은 삭제하지 않음 | `EmptyState` |

| 상태 | 보이는 것 | 눌리는 것 |

## 인터랙션

- 스크롤: 헤더 외 전체 세로 스크롤. 사진 썸네일은 가로 스크롤.
- 당겨서 새로고침: 없음. 재진입·수정 완료 때 갱신.
- 길게 누르기: 없음. 사진 순서 변경·대표 지정·사진 추가 없음.
- 시트: 본인 항목 수정·삭제 확인. 서버 요청 중에는 닫기 비활성.
- 뒤로 가기: 진입 화면과 스크롤 위치 복원. 수정 중 미저장 입력은 시트 초안으로 유지, 저장 요청 완료 뒤 닫을 수 있음.
- 키보드: 수량은 숫자 키보드. 필드·오류·저장까지 스크롤로 접근.
- 사진: 본인·타인 모두 이전/다음·썸네일로 이동. 첫/마지막에서 순환하지 않음.
- 전환: 공유는 5-6 푸시. 소속 없는 5-5 기록 모드로 돌아갈 때 가입 화면으로 강제 이탈하지 않음.

## 접근성

- 제목 "활동 기록 상세", 날짜와 지표는 순서대로 읽으며 미측정 걸음은 읽지 않는다.
- 사진은 "전체 N장 중 M번째 사진", 이전/다음·썸네일에 이동 라벨 제공.
- 카테고리 선택·수량·삭제를 항목별로 구분하고 오류를 해당 필드에 연결한다. 진행·오류는 live region.
- 최소 터치 크기 예외: 없음. 모든 버튼·수량 스텝퍼·썸네일은 48dp 이상.
- 작은 화면·큰 글자에서는 지도·사진 미리보기 높이를 먼저 줄이고 전체 내용은 스크롤. 글자·터치 크기는 줄이지 않는다.

## 옛 화면과의 차이

- 활동 사진은 모든 허용된 뷰어에게 조회만 제공하고 순서·대표 편집을 제거했다.
- 본인의 카테고리·수량 변경과 항목 삭제는 항목별 API로 처리한다.
- 공유는 요약 이미지뿐이다. 연결 게시물 표시·이동은 없다.
- 현재 크루 밖 자기 기록도 유지하며 소속 없는 기록 모드에서 접근한다.
