# 5-6 게시물 작성

**목적** 사진과 글로 새 게시물을 만들어 크루 전체 또는 나만 보기로 올린다.
**원본** `../legacy/android-res/layout/fragment_publish.xml` (사진 타일 `item_photo_pick.xml`, `item_photo_thumb.xml`) · **변경** 활동 기록 카드·기록 범위 선택(내 기록만/모임 전체)이 빠졌다(활동은 요약 이미지로만 붙는다 — 기능범위·4-7). 공개 범위가 크루 전체/나만 보기 두 가지로 정리됐다. 사진 최대 4장 → 10장(계약)
**진입** 저장 완료 내 활동 상세(5-3)의 공유 · 피드(5-1) "+ 글쓰기" · 활동 종료 요약(4-7) "공유하기"(요약 이미지가 사진 첫 칸에 미리 붙어서) · **이탈** 게시 완료 → 피드(5-1), 스택에서 이 화면과 4-7 을 함께 지운다 · 뒤로 가기 → 초안 유지

이 화면은 항상 새 게시물만 만든다. 계약에 `PATCH /posts/{postId}` 가 없어 게시물 수정은 지원하지 않는다 — 5-2 의 더보기 시트에도 [수정] 이 없다.

## 배치

옛 XML 의 세로 순서(글 라벨·입력·글자수 → 사진 라벨·선택 → 활동 기록 카드 → 공개 범위 → 버튼 줄)를 그대로 따르되, 활동 기록 카드와 기록 범위 선택을 통째로 뺀다. 헤더는 고정, 그 아래가 세로 스크롤이며 버튼 줄은 옛 화면처럼 스크롤 맨 아래에 있다(화면 밖에 고정하지 않는다). 사진은 옛 세로 4슬롯 리스트 대신 가로로 스크롤하는 정사각 썸네일 줄로 바꿨다 — 10장까지 늘어난 목록엔 슬롯형 리스트보다 어울린다.

게시 순서.

| 순서 | 하는 것 | 결과 | 다음 |
|---|---|---|---|
| 1 | 사진마다 순서대로 `POST /media` (`mediaId` 앱이 만든 uuid · `file` · `purpose` POST) | 200 | 다음 사진. 마지막까지 끝나면 2 |
| 1 | 같은 요청 | 4xx/5xx | 그 사진만 실패 표시, 나머지는 계속 진행(부분 실패 참고). 하나라도 실패하면 2 로 넘어가지 않는다 |

| 2 | 같은 요청 | 4xx/5xx | 오류 상태(아래) |

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | **해당 없음.** 서버에서 받아 올 것이 없다. 4-7 에서 왔으면 요약 이미지가 이미 기기 안 파일이라 ③ 첫 칸에 바로 보인다(업로드는 아직 안 함) | 전부 |
| 새로고침 | **해당 없음.** 당겨서 새로고침 없음 | — |

| 오류 | 사진은 모두 올렸는데 `POST /crew/posts` 가 인증 외 4xx/5xx. ⑤ 위에 `Banner` "게시하지 못했어요. 다시 시도해 주세요." 값(글·사진·공개 범위)은 그대로 남는다. NO_CREW 403 이면 화면을 닫고 `GET /users/me` 결과대로 1-6 또는 1-9 로 | [게시하기] 다시 누르면 같은 `id` 로 재시도 · 나머지 전부 |

## 인터랙션

- 스크롤: ① 헤더만 고정, ②③④⑤ 가 세로로 스크롤. ③ 사진 줄은 그 안에서 가로로 스크롤한다
- 당겨서 새로고침: 없음
- 길게 누르기: 사진 썸네일을 길게 눌러 끌거나 사진을 선택한 뒤 [앞으로]/[뒤로]로 옮긴다. 맨 앞자리 사진에 "대표" 배지가 옮겨 붙는다
- 시트: 없음. 사진 추가는 시스템 선택기를 바로 연다
- 뒤로 가기: 입력 초안을 유지한 채 진입 화면으로 돌아간다. 게시 중에는 뒤로 이동을 막고 결과를 기다린다. 실패하면 입력을 보존하고 재시도·뒤로를 다시 허용한다. 응답 유실 시 같은 id로 재시도한다.
- 키보드: 글 입력에 포커스하면 키보드가 올라오고 그만큼 스크롤 영역이 줄어든다. 엔터는 줄바꿈, 게시는 버튼으로만 한다
- 전환: 진입한 화면(5-1 · 4-7 · 5-3)으로 pop, 또는 게시 성공 시 5-1 로 교체. 초안은 화면 이동 시 자동 보존

## 접근성

- 모든 내용과 동작을 유지한다. 작은 화면·큰 글자에서는 장식과 미리보기 높이를 먼저 줄이고 본문을 스크롤하며, 글자와 48dp 터치 영역은 줄이지 않는다.

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로 가기"
  - 글 입력: "게시물 본문 입력". 남은 글자는 1000자에 닿기 전까진 읽지 않고, 닿으면 "1000자, 더 입력할 수 없어요"
  - 사진 추가 타일: "사진 추가, N장 중 M장 골랐어요"
  - 사진 썸네일: "N번째 사진, 순서 선택". 맨 앞 사진은 "대표 사진, N번째"
  - 업로드 실패 아이콘: "업로드 실패, 다시 시도하려면 두 번 탭"
  - 공개 범위 행: "크루 전체, 크루원 모두에게 보여요, 선택됨" / "나만 보기, 나에게만 보여요"
  - 진행바: 나타나는 순간과 값이 바뀔 때 "게시하는 중, N장 중 M장 올림" (live region)
  - [뒤로]: "뒤로, 작성 중인 내용 유지"
  - 순서 버튼: "N번째 사진 앞으로 이동" / "뒤로 이동", 첫/마지막 방향은 비활성. 삭제는 별도 라벨과 48dp 영역.
  - [게시하기]: "게시하기". 비활성이면 "게시하기, 비활성" + 힌트 "글이나 사진을 먼저 넣어 주세요"
  - 배너·대화상자: 뜨는 순간 문구를 읽어 준다(live region)
- 최소 터치 크기 예외: 없음. 사진 추가 타일·썸네일은 64dp 라 삭제 버튼만 48dp 로 터치 영역을 넓힌다(옛 `item_photo_thumb` 과 같다). 공개 범위 행·뒤로·게시하기는 48dp 이상

## 옛 화면과의 차이

- 활동 기록 카드(`recordCard`, 지표 3분할·지도 스냅샷·"줍기 기록 없음"/"수정됨" 배지·[기록 카드 제거]·"첨부된 활동 기록이 없어요")와 기록 범위 선택(`scopeGroup`, "내 기록만"/"모임 전체 포함") → 모두 없음. `Post` 에 활동 참조 필드가 없어 활동은 요약 이미지 한 장으로만 붙는다
- 공개 범위 선택(`visibilityRow`, FlexboxLayout — 옛 값 불명, 아마 전체공개/친구공개/비공개 계열) → "크루 전체"/"나만 보기" 두 행(계약 `visibility` enum CREW/PRIVATE)
- 사진 세로 4슬롯 리스트(`item_photo_pick`, "사진 선택 (최대 4장)") → 가로 스크롤 정사각 썸네일 줄(`item_photo_thumb` 스타일: 삭제 ×·대표 배지), 최대 10장(계약 `mediaIds` maxItems)으로 늘었다
- 글자 수 상한 300자(`hint_post_body`, EditText maxLength) → 1000자(계약 `text` maxLength)
- 헤더 부제 "게시글 작성"/"게시글 수정"(`pub_title_new`/`pub_title_edit`) → "게시물 작성" 하나만. 수정 모드는 없다(계약에 `PATCH /posts/{postId}` 가 없다)
- 하단 왼쪽 버튼은 "뒤로". 입력은 자동 유지하고 별도 초안 저장 버튼은 두지 않는다
- "게시하기"(`pub_cta_new`)는 그대로 두고 "수정 완료"(`pub_cta_edit`)는 없다
- "배출 인증 사진 포함" 토글(`pub_disposal_toggle`/`pub_disposal_desc`) → 없음. 배출 인증이라는 기능 자체가 이 기능범위에 없다
- "내용을 한 글자라도 써 주세요."(`pub_need_note`, 글 필수) → 글 또는 사진 중 하나만 있으면 게시 가능
- 사진 업로드 진행바·부분 실패 재시도·초안 보존은 새로 정했다. 옛 XML 흔적으로는 확인 없이 바로 나갔다

## 미결

- 구현 검증: Android 시스템 포토 피커로 최대 10장 선택, 화면 이동 후 URI/로컬 파일 재접근과 업로드 성공분 재사용을 보장해야 한다.
- 구현 검증: 게시 응답 유실 시 동일 요청 id로 재시도하여 중복 게시를 막는다. 게시물 수정 기능은 추가하지 않는다.
