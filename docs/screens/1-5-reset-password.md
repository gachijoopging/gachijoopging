# 1-5 비밀번호 재설정·확인

**목적** 비밀번호를 잊은 사람이 가입한 이메일로 코드를 받아 새 비밀번호를 정한다.
**원본** `../legacy/android-res/layout/fragment_password_reset.xml` (A 요청) · `../legacy/android-res/layout/fragment_password_reset_confirm.xml` (B 확인) · **변경** 배치·문구는 그대로. 메일의 **링크**로 열리던 B 가 메일로 받은 **코드를 입력**하는 화면이 됐다(계약 `POST /auth/password-reset/confirm` 이 `email`·`code` 를 받는다). A 의 발송 후 패널에서 B 로 넘어가는 버튼이 생겼다
**진입** A: 1-2 로그인 "비밀번호를 잊으셨나요?" · 5-7 설정 "비밀번호 재설정". B: A 의 발송 후 패널 "코드 입력하기" 에서만 · **이탈** B 성공 → 진입 위치와 무관하게 1-2 로그인(기존 세션 종료). 뒤로 가기 → 온 곳

## 배치

두 장 모두 옛 XML 의 세로 순서를 그대로 따른다. A 는 헤더 → 헤드라인 → 설명 → 이메일 라벨·입력·오류 → [재설정 메일 보내기] 이고, 발송이 끝나면 같은 자리가 ✉️ 원 → 제목 → 설명 → 버튼 2개로 바뀐다(옛 `formState`/`sentState` 전환). B 는 헤더 → 헤드라인 → 비밀번호 → 보기 토글 → 비밀번호 확인 → 오류 → [비밀번호 변경] 이며, 헤드라인 아래에 인증 코드 입력이 하나 늘었다. A·B 모두 장식·여백을 먼저 줄이고 필요하면 본문 전체를 스크롤한다. 입력·오류·버튼을 보존한다.

A 요청 — 발송 전

```
┌──────────────────────────────────────┐
│ ① ‹  비밀번호 재설정                    │
│      계정 복구                         │
├──────────────────────────────────────┤
│ ② 가입한 이메일을 알려 주세요             │
│    입력한 주소로 비밀번호 재설정 코드를     │
│    보내 드려요.                         │
│                                      │
│ ③ 이메일                               │
│   [ you@example.com              ]   │
│   이메일 형식이 올바르지 않아요.           │  ← 평소 숨김
│                                      │
│ ④ [     재설정 메일 보내기      ] 비활성  │
└──────────────────────────────────────┘
```

A 요청 — 발송 후 (②③④ 자리가 통째로 ⑤ 로 바뀐다)

```
┌──────────────────────────────────────┐
│ ① ‹  비밀번호 재설정                    │
│      계정 복구                         │
├──────────────────────────────────────┤
│ ⑤               (✉️)                 │
│        재설정 요청을 접수했어요            │
│   요청을 접수했어요. kwan@example.com     │
│   계정이 있으면 메일을 확인해 주세요.       │
│                                      │
│          [   코드 입력하기   ]           │
│            메일 다시 보내기              │
└──────────────────────────────────────┘
```

B 확인

```
┌──────────────────────────────────────┐
│ ⑥ ‹  새 비밀번호 설정                   │
├──────────────────────────────────────┤
│ ⑦ 새로 사용할 비밀번호를 입력해 주세요      │
│                                      │
│ ⑧ 인증 코드                            │
│   [ 메일로 받은 코드               ]   │
│                                      │
│ ⑨ 비밀번호                             │
│   [ 8자 이상                 ●●●● ]   │
│   보기                                │
│                                      │
│ ⑩ 비밀번호 확인                         │
│   [ 비밀번호를 한 번 더 입력          ]   │
│   비밀번호가 서로 달라요.                 │  ← 평소 숨김
│                                      │
```

## 인터랙션

- 스크롤: A·발송 후 패널·B 모두 작은 화면·큰 글씨·키보드에서 장식부터 줄인 뒤 본문 전체 스크롤. 글씨·터치를 줄이지 않는다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음. 입력칸은 OS 기본(붙여넣기)만 — ⑧ 코드는 메일에서 복사해 붙이는 것이 주 경로다
- 시트: 없음
- 뒤로 가기: A 발송 전 → 온 곳(1-2 또는 5-7). A 발송 후 패널 → 발송 전 폼이 아니라 온 곳으로 간다(패널은 되돌릴 화면이 아니다). B → A 발송 후 패널. 전송 중에는 결과 확인까지 이탈을 잠근다. 실패 시 입력을 유지하고 재시도한다
- 키보드: A ③ 이메일 키보드, 완료 키 = ④ 와 같다(활성일 때만). B ⑧ 기본 키보드, 다음 → ⑨ · ⑨ 다음 → ⑩ · ⑩ 완료 = ⑪ 과 같다(활성일 때만). 빈 곳을 탭하면 키보드가 내려간다
- 발송 전 → 발송 후: 같은 화면 안에서 ②③④ 가 사라지고 ⑤ 가 페이드 인. 헤더는 그대로
- 전환: 1-2·5-7 → A 는 푸시. A → B 는 푸시. B 성공은 기존 인증 세션을 끝내고 1-2로 대체하며 A·B와 이전 인증 화면 스택을 지운다 — 뒤로 가기로 B 에 되돌아오지 않는다. `Snackbar` 는 도착한 화면 위에 뜬다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로"
  - A 헤더: "비밀번호 재설정, 계정 복구" · B 헤더: "새 비밀번호 설정"
  - ③⑧⑨⑩: 라벨을 입력칸 라벨로 묶어 "이메일, 편집 상자" 처럼 읽힌다. 오류가 뜨면 그 칸의 오류로 붙여 읽는다(live region)
  - 보기 토글: "비밀번호 보기" ↔ "비밀번호 숨기기"
  - ④⑪ 비활성: "비활성" 으로 읽히고, 스피너 중에는 "보내는 중" / "변경하는 중"
  - ⑤ 봉투 원: 장식이라 읽지 않는다(옛 XML 도 `importantForAccessibility=no`)
  - ⑤ 설명: 이메일을 포함한 본문 그대로 읽는다
  - `Snackbar`: 뜨는 순간 문구를 읽어 준다
- 최소 터치 크기 예외: 없음. 뒤로는 48dp. 보기 토글은 글자가 작아 위아래 여백까지 터치 영역에 넣어 48dp 를 채운다

## 옛 화면과의 차이

- B 진입: 메일의 **링크**(토큰) → 메일로 받은 **코드**를 직접 입력. 그래서 B 에 ⑧ 인증 코드 칸이 새로 들어갔고, B 는 A 를 거쳐서만 열린다(딥링크 없음)
- A ⑤ 버튼: "메일 다시 보내기"(ghost) · "로그인으로 돌아가기"(primary) → "코드 입력하기"(primary) · "메일 다시 보내기"(ghost). 로그인 복귀는 뒤로 가기가 맡는다
- 옛 A 설명 "재설정 링크를 보내 드려요." 를 없앴다
