# 1-5 비밀번호 재설정

**목적** 비밀번호를 잊은 사람이 가입한 이메일로 코드를 받아 새 비밀번호를 정한다.
**원본** `../legacy/android-res/layout/fragment_password_reset.xml` (요청) · `../legacy/android-res/layout/fragment_password_reset_confirm.xml` (확인) · **변경** 옛 앱은 요청과 확인이 두 화면이었다. 메일의 **링크**로 열리던 확인 화면이 메일로 받은 **코드를 입력**하는 단계가 됐고(계약 `POST /auth/password-reset/confirm` 이 `email`·`code` 를 받는다), 그 단계를 요청 화면 안으로 합쳤다(GAC-61). 코드 입력 하나 때문에 화면을 따로 두지 않는다
**진입** 1-2 로그인 "비밀번호를 잊으셨나요?" · 5-7 설정 "비밀번호 재설정" · **이탈** 변경 성공 → 진입 위치와 무관하게 1-2 로그인(기존 세션 종료). 뒤로 가기 → 온 곳

## 배치

한 화면이 두 단계로 바뀐다. 발송 전은 헤더 → 헤드라인 → 이메일 라벨·입력·오류 → [재설정 메일 보내기]. 발송이 끝나면 같은 화면에서 ②③④ 가 사라지고 안내 → 인증 코드 → 새 비밀번호 → 보기 토글 → 새 비밀번호 확인 → 오류 → [비밀번호 변경] → [메일 다시 보내기] 가 나온다. 장식·여백을 먼저 줄이고 필요하면 본문 전체를 스크롤한다. 입력·오류·버튼을 보존한다.

발송 전

```
┌──────────────────────────────────────┐
│ ① ‹  비밀번호 재설정                    │
│      계정 복구                         │
├──────────────────────────────────────┤
│ ② 가입한 이메일을 알려 주세요             │
│                                      │
│ ③ 이메일                               │
│   [ you@example.com              ]   │
│   이메일 형식이 올바르지 않아요.           │  ← 평소 숨김
│                                      │
│ ④ [     재설정 메일 보내기      ] 비활성  │
└──────────────────────────────────────┘
```

발송 후 (②③④ 자리가 ⑤~⑩ 으로 바뀐다)

```
┌──────────────────────────────────────┐
│ ① ‹  비밀번호 재설정                    │
│      계정 복구                         │
├──────────────────────────────────────┤
│ ⑤ ✉  메일로 받은 코드를 입력해 주세요     │
│      kwan@example.com 계정이 있으면     │
│      6자리 코드를 보냈어요. 10분 동안     │
│      쓸 수 있어요.                     │
│                                      │
│ ⑥ 인증 코드                            │
│   [ 6자리 숫자                    ]   │
│                                      │
│ ⑦ 새 비밀번호                          │
│   [ 8자 이상                 ●●●● ]   │
│   비밀번호 보기                         │
│                                      │
│ ⑧ 새 비밀번호 확인                      │
│   [ 비밀번호를 한 번 더 입력          ]   │
│   비밀번호가 서로 달라요.                 │  ← 평소 숨김
│                                      │
│ ⑨ [        비밀번호 변경        ] 비활성 │
│ ⑩          메일 다시 보내기              │
└──────────────────────────────────────┘
```

소셜 전용 계정(`hasPassword` false)에 비밀번호를 새로 만드는 기능은 제공하지 않는다. 기존 로그인 상태에서 활동 진행 중 또는 계정별 미동기화 활동이 있으면 5-7의 진입을 막고 완료·동기화 후 진행한다. 비밀번호 두 칸은 원문 그대로 비교·전송한다.

검증 시점: ③ 은 보내기를 누를 때, ⑦⑧ 은 포커스를 떠날 때 검사하고, 고치는 동안(입력 중) 오류를 지운다. 버튼 활성 조건은 글자마다 다시 본다.

## 인터랙션

- 스크롤: 작은 화면·큰 글씨·키보드에서 장식부터 줄인 뒤 본문 전체 스크롤. 글씨·터치를 줄이지 않는다
- 당겨서 새로고침: 없음
- 길게 누르기: 없음. 입력칸은 OS 기본(붙여넣기)만. ⑥ 코드는 메일에서 복사해 붙이거나 자동완성으로 채우는 것이 주 경로다
- 시트: 없음
- 뒤로 가기: 단계와 무관하게 온 곳(1-2 또는 5-7)으로 간다. 발송 후 단계는 되돌릴 단계가 아니다. 요청 중에는 결과 확인까지 이탈을 잠근다
- 키보드: ③ 이메일 키보드, 완료 키 = ④ 와 같다. ⑥ 숫자 키보드, 다음 → ⑦ · ⑦ 다음 → ⑧ · ⑧ 완료 = ⑨ 와 같다(활성일 때만)
- 발송 전 → 발송 후: 같은 화면 안에서 ②③④ 가 사라지고 ⑤~⑩ 이 나타난다. 헤더는 그대로
- 전환: 1-2·5-7 → 이 화면은 푸시. 변경 성공은 기존 인증 세션을 끝내고 1-2로 대체한다. 뒤로 가기로 이 화면에 되돌아오지 않는다

## 접근성

- 스크린리더 라벨이 필요한 요소:
  - 뒤로: "뒤로"
  - 헤더: "비밀번호 재설정, 계정 복구"
  - ③⑥⑦⑧: 라벨을 입력칸 라벨로 묶어 "이메일, 편집 상자" 처럼 읽힌다. 오류가 뜨면 그 칸의 오류로 붙여 읽는다(live region)
  - 보기 토글: "비밀번호 보기" ↔ "비밀번호 숨기기"
  - ④⑨ 비활성: "비활성" 으로 읽힌다
  - ⑤ 봉투 아이콘: 장식이라 읽지 않는다
  - `Snackbar`: 뜨는 순간 문구를 읽어 준다
- 최소 터치 크기 예외: 없음. 뒤로는 48dp. 보기 토글은 위아래 여백까지 터치 영역에 넣어 48dp 를 채운다

## 옛 화면과의 차이

- 요청·확인 두 화면 → 한 화면 두 단계(GAC-61). "코드 입력하기" 버튼과 확인 화면을 없앴다
- 확인 진입: 메일의 **링크**(토큰) → 메일로 받은 6자리 **코드**를 직접 입력. 딥링크 없음
- 발송 후 패널의 "로그인으로 돌아가기" 버튼은 없다. 로그인 복귀는 뒤로 가기가 맡는다
- 옛 설명 "재설정 링크를 보내 드려요." 를 없앴다
- 오류 문구 "링크가 만료되었거나 이미 사용됐어요. 재설정 메일을 다시 요청해 주세요." → "코드가 만료되었거나 올바르지 않아요. 재설정 메일을 다시 요청해 주세요."
- 비밀번호 확인 불일치 문구는 옛 문자열에 없어 "비밀번호가 서로 달라요." 를 새로 정했다
- 5-7 설정에서 들어오는 경로에서 이메일 미리 채움은 새로 정했다
