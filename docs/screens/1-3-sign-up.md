# 1-3 회원가입

**목적** 이메일·비밀번호·닉네임을 한 화면에서 입력하고 약관·개인정보 동의를 거쳐 이메일 가입을 완료한다.
**원본** `../legacy/android-res/layout/fragment_signup.xml` · **변경** 닉네임을 합쳤다. 사진은 가입 뒤 5-8 프로필 수정에서 설정한다.
**진입** 1-1 시작 · 1-2 로그인의 회원가입 · **이탈** 가입 완료 → 소속 상태에 따라 1-6·1-9·2-1 · 로그인 링크 → 1-2 · 뒤로 → 온 화면. 이메일 가입은 1-4로 가지 않는다.

## 배치

헤더 아래 워드마크·설명 → 이메일 → 비밀번호 → 닉네임 → 동의 항목 → 회원가입 → 로그인 링크 순서다. 작은 화면·큰 글씨·키보드에서는 장식과 여백부터 줄이고 본문 전체를 스크롤한다. 입력·오류·동의 전문·버튼을 잘라내거나 글씨·터치 영역을 줄이지 않는다.

```
┌──────────────────────────────────────┐
│ ① ‹ 회원가입                         │
│ ② 가치줍깅에 오신 걸 환영해요          │
│ ③ 이메일 [you@example.com]           │
│    (이메일 오류)                     │
│ ④ 비밀번호 [8자 이상       보기]      │
│    (비밀번호 오류)                   │
│ ⑤ 닉네임 [2~12자]                    │
│    (닉네임 오류)                     │
│ ⑥ □ 필수 약관 동의        [내용 보기] │
│    □ 필수 개인정보 동의  [내용 보기] │
│    □ 선택 동의 항목      [내용 보기] │
│ ⑦ [회원가입]                         │
│ ⑧ 이미 계정이 있어요 · 로그인        │
└──────────────────────────────────────┘
```

## 요소

| 구역 | 요소 | 내용 (계약 필드) | 컴포넌트 | 탭하면 |
|---|---|---|---|---|
| ① | 헤더·뒤로 | 회원가입 | `AppHeader` | 온 화면 |
| ② | 워드마크·제목 | 기존 워드마크, "가치줍깅에 오신 걸 환영해요" | `Txt` + 기존 워드마크 | — |
| ③ | 이메일 | `POST /auth/signup`의 `email`, 이메일 형식. 앞뒤 공백만 제거 | `Field` | 이메일 키보드 |
| ④ | 비밀번호·보기 | `password`, 8자 이상. 공백·줄바꿈·문자열을 임의 정규화하지 않는다 | `Field` + `Chip` neutral | 보기/숨기기, 커서 유지 |
| ⑤ | 닉네임 | `nickname`, 줄바꿈 제거·앞뒤 공백 제거 뒤 2~12자. 별도 문자 제한 없음 | `Field` | 입력 |
| ⑥ | 동의 항목·전문 보기 | 필수 약관·개인정보 동의와 선택 항목을 구분. 기본 미선택. 실제 전문·항목·버전·저장 계약은 미결 | `Checkbox` + `Button` ghost | 전문 보기 후 입력·선택을 유지하고 복귀 |
| ⑦ | 회원가입 | 필드 검증과 필수 동의를 충족할 때 활성. 선택 미동의는 차단하지 않는다 | `Button` primary lg | `POST /auth/signup` (`email`, `password`, `nickname`); 동의 저장 연동은 계약 보완 후 구현 |
| ⑧ | 로그인 링크 | 이미 계정이 있어요 · 로그인 | `Button` ghost | 1-2로 대체 전환 |

이메일·비밀번호·닉네임의 로컬 오류는 해당 필드 아래에 표시하고 포커스 이탈·키보드 완료 시 검사한다. 비활성 버튼은 탭 이벤트를 받지 않는다. 닉네임 중복은 별도 조회 버튼 없이 저장 시 확인한다. 필수 동의 내용과 저장 계약이 준비되지 않은 상태를 가입 완료로 취급하지 않는다.

| 응답 | 처리 |
|---|---|
| 201 | 토큰 저장. 가입·필수 동의 완료를 확인한 뒤 `GET /users/me` 소속 분기(NONE → 1-6, PENDING → 1-9, MEMBER → 2-1) |
| 409 EMAIL_TAKEN | ③ 아래 “이미 가입된 이메일이에요. 로그인해 주세요.”, 값 유지 |
| 409 NICKNAME_TAKEN | ⑤ 아래 “이미 사용 중인 닉네임이에요. 다른 이름을 입력해 주세요.”, 값 유지 |
| 422 VALIDATION | 식별 가능한 필드 아래 오류. 대상 필드를 모르면 폼 요청 오류로 표시하며 닉네임 오류로 단정하지 않는다 |
| 네트워크·기타 실패 | 폼 `Banner` “가입하지 못했어요. 다시 시도해 주세요.”, 값과 동의 선택 유지·재시도 |

## 상태

| 상태 | 보이는 것 | 눌리는 것 |
|---|---|---|
| 첫 진입 로딩 | 별도 조회 없음, 필드·동의 미선택 | 입력·전문 보기·로그인·뒤로, 가입은 조건 충족 시 |
| 저장 중 | 가입 버튼 스피너, 요청 하나만 진행 | 중복 제출·편집·화면 이탈 잠금 |
| 새로고침 | 해당 없음. 조회 목록 없음 | — |
| 빈 | 빈 폼이 초기 상태 | 입력 가능 |
| 오류 | 필드 아래 오류 또는 폼 요청 배너 | 수정 후 가입·요청 재시도 |
| 오프라인 | 입력 유지, 제출 실패 시 연결 안내 | 입력·재시도 |
| 권한 거부 | 해당 없음. 기기 권한을 묻지 않는다 | — |
| 부분 실패 | 계정 생성 뒤 상태 조회/동의 완료 확인 실패면 저장한 인증을 유지하고 완료 확인만 재시도. 가입 요청을 다시 보내지 않는다 | 완료 확인 재시도 |

## 인터랙션

- 스크롤: 헤더 아래 전체. 장식부터 축소하고 필드·오류·동의·버튼까지 도달할 수 있게 한다.
- 당겨서 새로고침·시트: 없음. 전문 보기는 입력을 유지한 채 돌아온다.
- 길게 누르기: OS 입력 선택·붙여넣기.
- 뒤로 가기: 요청 전에는 온 화면으로. 진행 중에는 결과를 확인할 때까지 잠가 중복 가입을 막는다.
- 키보드: 이메일 → 비밀번호 → 닉네임 순서. 완료 시 검증하며 필수 동의 없이 가입하지 않는다. 비밀번호는 새 비밀번호 자동완성 힌트, 가림 처리.
- 중단 복귀: 인증 후 미완료 온보딩은 서버 완료 상태를 먼저 확인하고 이어간다. 비밀번호를 재개용 평문 저장소에 보관하지 않는다.
- 전환: 가입 완료 시 가입·시작 스택을 지운다. MEMBER는 위치 권한 없이 2-1로 간다.

## 접근성

- 필드 라벨과 해당 오류를 연결하고 오류를 live region으로 알린다. 첫 오류 필드로 포커스를 옮긴다.
- 필수/선택·체크 상태·전문 보기 대상을 구분해 읽는다. 오류와 선택 상태를 색만으로 표시하지 않는다.
- 보기 버튼은 “비밀번호 보기/숨기기”, 제출 중은 “가입 중”. 터치 영역은 모두 48dp 이상.

## 옛 화면과의 차이

- 이메일·비밀번호·닉네임을 한 화면에서 받아 여기서 가입 요청을 보낸다. 1-4는 소셜 첫 가입 전용이다.
- 가입 사진 설정을 없애고 5-8로 미뤘다. 필수·선택 동의 UI를 가입 완료 전에 배치했다.

## 미결

- 실제 약관·개인정보 전문과 선택 동의 항목, 버전·동의 시각·서버 저장 및 가입 완료 계약은 준비가 필요하다. UI 결정만으로 법적 콘텐츠/저장이 완성된 것은 아니다.
- `GET /users/me`의 `profileComplete`는 닉네임 설정 완료만 뜻한다. `isNew`만으로 복귀를 판정하지 않으며 필수 동의 완료의 판별/전이는 별도 계약 보완이 필요하다.
