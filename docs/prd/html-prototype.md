# HTML 프로토타입 PRD

## 목적

승인된 화면설계 43장을 앱 구현 전에 한 파일에서 탐색·검토한다. 팀은 화면 배치, 주요 이동, 역할별 노출, 상태 표현이 설계와 맞는지 빠르게 확인한다.

이 산출물은 앱이 아니다. React Native, backend, AI 서버의 구현 계약·동작을 대체하지 않는다.

## 사용자

- **기획·디자인 검토자**: 화면설계와 사용자 흐름을 브라우저에서 확인한다.
- **앱 개발자**: 화면 구현 전 화면 정책·전환·상태의 시각 기준을 확인한다.

## 정본

| 항목 | 정본 | 프로토타입 역할 |
|---|---|---|
| 제품 목적·제외 범위 | [`../../intent.md`](../../intent.md), [`../기능범위.md`](../기능범위.md) | 정본을 시각화한다 |
| 용어 | [`../../CONTEXT.md`](../../CONTEXT.md) | 용어를 그대로 쓴다 |
| 화면 정책 | [`../화면.md`](../화면.md), [`../화면설계/`](../화면설계/) | 43개 승인 화면을 렌더한다 |
| 디자인 토큰·부품 | [`../../design-system/`](../../design-system/) | 토큰과 부품 의도를 CSS로 재현한다 |

화면 정책이 충돌하면 `docs/screens/`가 우선한다. 프로토타입에서 발견한 정책 문제는 원본 화면설계서를 고친 뒤 반영한다.

## 범위

### 포함

1. 단일 `prototype/gachijoopging.html`.
2. [`../화면.md`](../화면.md)에 색인된 43개 승인 화면.
3. 하단 탭, 주요 CTA, 뒤로가기, 시트 열기·닫기, 신고 진입.
4. 목 역할 `크루원`·`크루장` 전환과 역할별 버튼 노출.
5. 화면설계서에 정의된 기본·로딩·빈·오류/재시도·오프라인·권한 거부·제출 중 상태.
6. 정적 지도·카메라 프레임·AI 분류 결과.

### 제외

- API·인증·저장·실제 입력 반영.
- 카메라·GPS·지도 SDK·Health Connect·AI 호출.
- 파일 업로드·오프라인 동기화·푸시·소켓.
- 보조기기 실연·실서비스 반응형 웹·앱 빌드.
- 화면설계 정책의 재정의 또는 복제.

## 성공 기준

1. 파일을 `file://`로 열어 설치·빌드·네트워크 없이 동작한다.
2. 43개 화면 모두 탐색 가능하다.
3. 현재 화면에 번호와 대응 화면설계서 경로가 보인다.
4. 화면 전환과 역할별 노출이 이동 지도·화면설계와 맞는다.
5. 핵심 상태를 클릭해 검토할 수 있다.

## 완료 정의

- [ ] 43개 화면이 화면 레지스트리에 등록됨
- [ ] 각 화면이 설계서 번호·이름·경로를 표시함
- [ ] 주요 이동·시트·뒤로가기가 동작함
- [ ] 크루원·크루장 차이가 확인됨
- [ ] 외부 요청 없이 로컬 파일로 열림
