# 기능 범위

새 저장소(GitHub)의 기준 문서다. 백엔드는 옛 코드에서 global·auth·media 만 가져오고 나머지는 새로 쓴다(ADR-0004).
용어는 `../CONTEXT.md` 를 따른다.

**1차** 는 이번에 만드는 범위, **이후** 는 다음 릴리스로 미룬 것이다.

## 진행 순서

1. API 계약 문서(OpenAPI) 작성
2. 앱 프론트 완성 — 목 데이터 기반
3. 백엔드 — 가져온 global·auth·media 를 잇고, ERD·계약대로 나머지 도메인을 새로 쓴다(`backend/docs/01-구조.md`)
4. 앱과 백엔드 연결, 테스트, 마무리

| 기록 | 개인 활동으로만 쌓이고 크루 전체 기록에 합산된다. 조(소그룹) 없음. 크루를 나가거나 추방돼도 개인 기록·크루 합산 모두 그대로 남는다. 본인은 이전 크루를 포함한 전체 기록을 보고, 다른 크루원에게는 현재 같은 크루에서 한 활동만 공개한다. 비소속이어도 크루 선택 화면에서 내 활동 기록을 열 수 있다 |
| 위치 공유 | 지도에는 활동 중이며 위치 공유를 켠 크루원만 표시한다. 보는 사람은 활동 중일 필요가 없다. 일시정지도 활동 중이다. 종료하면 실시간 지도에서 빠지며, 같은 크루에서 한 공개 경로는 기록 상세에서 본다. 공유를 꺼도 본인 기록에는 경로가 남는다. 게시물 요약 이미지의 경로 포함은 별도 선택이며 기본은 제외 |
| 채팅 | 크루마다 단체 채팅방 하나. 크루가 있는 동안 계속 이어지며 모이깅 탭과 줍깅 화면 어디서든 같은 방을 연다. 1:1 없음. 폴링 → 소켓 |
| 백그라운드 | 활동 시작~종료 사이에만 배경 추적. 경로 기록·거리·시간·크루원 위치 전송·알림창 현황(거리·시간·개수)이 화면을 꺼도 유지된다. 포그라운드 서비스 알림으로. 종료하면 즉시 끔. 활동 밖에서는 위치를 올리지 않는다 |
| 위치 품질 | 오차 반경 30m 초과 점 버림 · 초속 5m 초과 이동 버림 · 최근 3~5점 평균 평활화. 활동 구간의 유효한 걸음수가 있을 때만 걸음 × 0.7m와 대조해 GPS 거리가 그보다 30% 넘게 크면 보정한다. 걸음수 미측정·권한 없음·걷지 않는 활동은 GPS로 기록하며 0걸음 때문에 거리를 0으로 보정하지 않는다. 경로 맞춤(map matching)은 이후 |
| 걸음수 | 선택 정보. Health Connect 미지원·권한 거부·걸음수 없음·걷지 않는 활동이어도 시작·줍기·종료를 허용한다. 일시정지 구간 걸음은 누적과 거리 보정에서 제외한다. 미측정은 null이며 0걸음과 구분한다. 활동 중·요약·상세에 표시하고 공유 이미지에는 측정값이 있을 때만 넣는다 |
| 권한 요청 | 위치는 활동 시작 직전에만 요청한다. 홈·피드·모이깅·내 기록은 위치 권한 없이 이용한다. 걸음수·알림 권한 거부는 활동을 막지 않는다 |
| 활동 저장 | 오프라인이어도 기기에서 즉시 종료하고 추적을 끈다. 계정별로 줍기와 종료 요청을 보존하며 줍기 → 종료 순서로 동기화한다. 종료 저장 전에는 공유·다음 활동을 막고 저장 대기와 재시도를 제공한다. 재실행·오류·다음 시작 때문에 미저장 데이터를 삭제하지 않는다 |
| 계정·크루 이탈 | 진행 중이거나 동기화 대기인 활동이 있으면 로그아웃·크루 나가기·회원 탈퇴 전에 종료와 동기화를 안내한다. 저장 실패는 기록을 보존하며 재시도한다 |
| 로고·캐릭터 | 기존 캐릭터를 로고·앱 아이콘·홈 게이미피케이션·빈 상태 화면에 공통으로 쓴다. 필요한 에셋: 홈 단계 5장 · 앱 아이콘(Android adaptive 전경/배경) · 스플래시 1장 · 빈 상태 3장(활동 없음·게시물 없음·알림 없음). `design-system/assets/character/` 에 둔다. 생성 프롬프트는 `docs/character-prompts.md` |
| DB | Supabase 의 Postgres(PostGIS) 만 쓴다. Spring 이 JDBC 로 접속. Supabase Auth·Storage·Realtime 은 안 쓴다. EC2 Postgres 컨테이너 제거. 리전은 서울로 맞춤 |
| 음성 입력 | 이후. 인터뷰의 음성 요구는 기존 앱의 수동 입력이 불편해서 나온 것이라, 사진 분류와 줍기 UI 가 그 자리를 채운다. 실제 사용에서 여전히 불편하면 다시 검토 |
| 소속 | 한 사람은 크루 하나에만 소속된다. 동네(hood) 개념은 끔 — 온보딩·홈·백엔드에서 제거 |
| 회원 탈퇴 | 크루 합산 숫자는 유지. 게시물·댓글은 "탈퇴한 크루원" 이름으로 보존. 개인 활동 상세(경로 포함)는 삭제. 크루 나가기·추방과 다르다 — 그 경우 계정이 살아 있어 기록이 이름 붙은 채 남는다 |
| 크루장 | 한 명. 다른 크루원이 있으면 위임 후 나가기·탈퇴한다. 혼자 남았으면 크루 해산 확인 후 나갈 수 있고 크루는 소프트 삭제한다. 운영진 층 없음 |
| 초대 코드 | 복사와 휴대폰 기본 공유창을 제공한다. 사용자가 앱과 받는 사람을 고른다. 재발급하면 이전 코드로 새 신청은 못 하지만 기존 신청은 유지한다. 거절·추방 후에도 현재 유효한 코드로 재신청할 수 있다 |
| 기존 데이터 | 이관하지 않는다. 새 스키마로 빈 DB 에서 시작. Flyway 도 V1 부터 다시 쓴다 |
| 인프라 | 옛 EC2 구성은 버린다. Lightsail VM 한 대에 docker compose 로 백엔드·Redis·Nginx(ADR-0005). `dev` 머지가 스테이징, `main` 머지가 운영이고 이미지는 태그만 승격한다. 감시는 헬스체크 + 외부 핑 + Mattermost 알림이고 Prometheus·Grafana 는 되살리지 않는다. 구성과 환경 변수 키 목록은 `operations.md` |
| 플랫폼 | 1차는 **Android 만**, React Native. iOS 는 이후(Apple 개발자 계정·Apple 로그인·HealthKit·Live Activity 가 함께 따라온다). 걸음수·운동 인식은 Health Connect(삼성헬스 데이터 포함) |
| 지도 | 카카오맵 Android SDK 를 RN 네이티브 모듈로 감싼다. 옛 앱의 지도 코드(경로 선·마커·카메라 추적)를 참고. iOS 를 넣을 때 지도 SDK 를 다시 정한다 |
| 온보딩 화면 수 | 비밀번호 재설정은 요청·확인을 한 화면에서 한다. 크루 만들기는 1-6 의 시트, 위치 권한 안내는 활동 시작 시트 안에서 한다. 이름 하나·권한 하나 때문에 화면을 따로 두지 않는다 |
| 계정 메뉴 | 크루가 없거나 승인 대기여도 설정에서 로그아웃·탈퇴할 수 있다 |
| 화면 방향·테마 | 세로 고정이다. 활동 중 지도와 촬영 화면이 걷는 자세에서 쓰여 가로가 필요 없다. 다크 모드는 기기 설정을 따른다 |
| 크루 화면 수 | 크루 정보·초대 코드·크루원은 3-11 크루 정보 한 화면이다. 초대 코드는 그 화면의 시트다. 가입 신청(3-8)과 신고 처리는 목록이 길어 별도 화면으로 남기고 3-11 에서 들어간다. 공지 목록은 3-1 모이깅의 공지 탭이다 |
| 줍기 입력 | 사진 줍기는 셔터 → AI 확인(4-5) 두 단계다. 셔터를 누르면 바로 올리고, 다시 찍기는 4-5 가 맡는다. 빠른 줍기 카드는 한 번 누르면 하나, 길게 누르면 수량 입력이다. 줍깅 버튼에는 첫 안내 화면이 없다 |

## 화면별 유지 · 변경 · 신규 · 끔

### 온보딩
- 가입 전 동의 목록은 공개 `GET /agreements` 로 조회한다. 인증 뒤 동의 상태 조회·저장은 `/users/me/agreements` 로 하며 현재 버전의 필수 동의가 완료되어야 소속 분기로 진행한다. 전문 URL·버전이 설정되지 않았으면 가입을 완료시키지 않는다.
- 이메일 가입은 한 화면에서 이메일·비밀번호·닉네임을 받는다. 소셜 첫 가입은 닉네임만 받고 사진은 프로필 수정에서 받는다. 가입 완료 뒤 크루 만들기 또는 가입하기로 간다
- 가입 완료 전 약관·개인정보 안내와 동의를 제공하며 필수·선택을 구분한다. 동의 상태·저장은 `/users/me/agreements` 별도 경로이고, 약관 버전이 오르면 다음 진입 때 1-4 에서 재동의한다
- 앱을 다시 열면 완료하지 못한 온보딩 단계로 복귀한다. 승인 대기는 푸시 수신·앱 복귀·수동 새로고침으로 갱신한다. 거절은 안내와 크루 선택 버튼으로 보여준다
- 끔: 동네 선택
- 크루 만들기: 1-6 의 시트에서 이름만 입력. 초대 코드는 자동 생성. 소개·대표 사진·크루 목표는 모이깅 탭의 크루 정보 수정에서 크루장이 채운다. 목표 기본값은 서버가 정한 값으로 시작
- 가입: 초대 코드로 크루를 지정하고 크루장이 승인하면 크루원이 된다. 크루 검색·공개 목록 없음

### 홈
- 유지: 화면 구조(인사 · 상단 선택 · 알림 버튼 · 카드 3장 · 오프라인 카드)
- 변경: 동네 선택 → 크루 이름 표시
- 변경: "이번 주 우리 동네" 카드 → "최근 7일 우리 크루가 주운 쓰레기" (개수 + 7일 스파크라인 유지). 누르면 모이깅 탭의 크루 기록으로

## 공통 화면 원칙

- 기존 디자인 시스템의 색·폰트·간격·반경·48dp 최소 터치 영역을 따른다. 장식과 미리보기를 먼저 줄이고 부족하면 세로 스크롤한다. 글자와 터치 영역은 줄이지 않는다. 프로필 소개는 2줄 뒤 더 보기로 펼친다
- 입력 오류는 해당 필드 아래, 요청 실패는 입력을 보존한 상태로 재시도를 제공한다. 제출 중 중복 요청을 막는다. 실제 요청이 계속되는 상태를 "취소됨"으로 안내하지 않는다
- 이름은 앞뒤 공백과 줄바꿈을 정리하고 계약 길이를 적용한다. 불필요한 문자 제한을 추가하지 않으며 중복은 저장 시 확인한다. 비밀번호 입력값은 임의 변경하지 않는다
- 사진은 OS 선택기를 공통으로 사용하고 필요한 곳에 촬영을 제공한다. 게시물 사진 순서 변경은 드래그와 앞·뒤 버튼을 함께 제공한다
- 문구는 상태와 다음 행동을 알려준다. 용어는 `CONTEXT.md`, 시간·거리·카테고리 표기는 화면 사이에 동일하게 쓴다. 목록·입력·메뉴·확인은 기존 `ListRow`·`Field`·`BottomSheet`·`Dialog`를 재사용한다

## 미결

- 줍기 항목에 연결되지 않은 활동 사진의 정리 시점. 활동 도메인 백엔드가 생긴 뒤 정한다
- 승인 대기 중 회원 탈퇴 시 남은 가입 신청의 처리. 앱은 탈퇴를 막지 않는다. `DELETE /users/me` 계약에 아직 적혀 있지 않아 백엔드 구현 때 정한다
- 캐릭터 홈 5단계·빈 상태 3종은 기존 새싹의 형태와 팔레트를 유지하는 방향으로 확정. 누락 에셋 제작과 작은 화면·큰 글자·실기기 검증은 구현 단계 산출물이다
