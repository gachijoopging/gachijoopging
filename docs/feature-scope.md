# 기능 범위

새 저장소(GitHub)의 기준 문서다. 백엔드는 옛 코드에서 global·auth·media 만 가져오고 나머지는 새로 쓴다(ADR-0004).
용어는 `../CONTEXT.md` 를 따른다.

**1차** 는 이번에 만드는 범위, **이후** 는 다음 릴리스로 미룬 것이다.

## 진행 순서

1. API 계약 문서(OpenAPI) 작성
2. 앱 프론트 완성 — 목 데이터 기반
3. 백엔드 — 가져온 global·auth·media 를 잇고, ERD·계약대로 나머지 도메인을 새로 쓴다(`backend/docs/01-구조.md`)
4. 앱과 백엔드 연결, 테스트, 마무리

## 결정된 것

| 영역 | 결정 |
|---|---|
| 저장소 | GitHub 새 저장소. 옛 모노레포에서 가져온 것: `design-system` · backend 의 `global`·`auth`·`media` 와 빌드 파일 · `backend/docs/02-conventions.md` · `ai/` 전체 · 옛 안드로이드 `res/`(`docs/legacy/`, 화면설계서 참고용) · 로고·사진 에셋. 가져오지 않은 것: 데이터 도메인·Flyway·infra·admin-web·Kotlin 소스. 옛 저장소는 지운다 |
| 협업 도구 | 이슈는 **Linear** 한 곳(가치줍깅 전용 워크스페이스). GitHub Issues 는 끈다. 브랜치 이름에 든 Linear 이슈 ID 가 PR 과 이슈를 잇고 상태를 자동으로 옮긴다. 알림은 Mattermost 웹훅으로 **PR 이벤트만**. 리뷰어는 `.github/CODEOWNERS` 가 폴더별로 지정. 절차는 `conventions.md` |
| 제품 | 여러 크루가 각자 쓰는 크루 운영 앱 |
| 무전(LiveKit) | 끔. 앱·서버·인프라에서 제거 |
| 인증 | 이메일+비밀번호, 카카오·구글 소셜 모두 유지. 이메일 계정에 소셜을 연결하는 기존 흐름 유지 — 계약 `PUT /users/me/social` 을 그대로 두고 진입점은 5-7 설정이다(2026-10-11). 로그아웃하면 서버가 그 기기의 푸시 토큰을 지운다 — `POST /auth/logout` 이 `pushToken` 을 선택 필드로 받는다(2026-10-11). iOS 를 넣을 때 Apple 로그인 문제(ADR-0003)를 다시 본다 |
| 관리자 웹 | 새 저장소로 옮기지 않는다. 코드와 `openapi-admin.yaml` 은 이 모노레포에 남고, 이후 크루 웹을 만들 때 참고만 한다 |
| 계정 정지 | 끔. 관리자 웹이 없어 정지할 주체가 없다. 제재는 크루장의 신고 처리·추방으로 한다 |
| 크루 웹 | 이후. 크루장 운영 도구(가입 승인·공지·활동 내역·CSV 다운로드) + 외부용 크루 소개 페이지 |
| CSV 내보내기 | 1차. 크루장만. 기간(시작일·종료일)을 골라 활동 한 회가 한 행: 날짜 · 크루원 · 거리 · 시간 · 카테고리별 수량 7열. 앱의 내보내기 버튼 → OS 공유 시트. 기존 관리자 Export(줍기 좌표 단위)와 형식이 다르므로 새 API |
| 기록 | 개인 활동으로만 쌓이고 크루 전체 기록에 합산된다. 조(소그룹) 없음. 크루를 나가거나 추방돼도 개인 기록·크루 합산 모두 그대로 남는다. 본인은 이전 크루를 포함한 전체 기록을 보고, 다른 크루원에게는 현재 같은 크루에서 한 활동만 공개한다. 크루에 가입하지 않은 사람도 로그인했으면 본인의 과거 활동·통계(`/users/me/activities`·`/users/me/stats`)를 볼 수 있다 — 앱은 1-6 의 내 활동 기록 → 5-5 기록 전용 모드로, 서버는 소속 여부와 무관하게 본인 데이터만 돌려준다 |
| 위치 공유 | 지도에는 활동 중이며 위치 공유를 켠 크루원만 표시한다. 보는 사람은 활동 중일 필요가 없다. 일시정지도 활동 중이다. 종료하면 실시간 지도에서 빠지며, 같은 크루에서 한 공개 경로는 기록 상세에서 본다. 공유를 꺼도 본인 기록에는 경로가 남는다. 게시물 요약 이미지의 경로 포함은 별도 선택이며 기본은 제외 |
| 채팅 | 크루마다 단체 채팅방 하나. 크루가 있는 동안 계속 이어지며 모이깅 탭과 줍깅 화면 어디서든 같은 방을 연다. 1:1 없음. 폴링 → 소켓 |
| 백그라운드 | 활동 시작~종료 사이에만 배경 추적. 경로 기록·거리·시간·크루원 위치 전송·알림창 현황(거리·시간·개수)이 화면을 꺼도 유지된다. 포그라운드 서비스 알림으로. 종료하면 즉시 끔. 활동 밖에서는 위치를 올리지 않는다 |
| 위치 품질 | 오차 반경 30m 초과 점 버림 · 초속 5m 초과 이동 버림 · 최근 3~5점 평균 평활화. 활동 구간의 유효한 걸음수가 있을 때만 걸음 × 0.7m와 대조해 GPS 거리가 그보다 30% 넘게 크면 보정한다. 걸음수 미측정·권한 없음·걷지 않는 활동은 GPS로 기록하며 0걸음 때문에 거리를 0으로 보정하지 않는다. 경로 맞춤(map matching)은 이후 |
| 걸음수 | 선택 정보. Health Connect 미지원·권한 거부·걸음수 없음·걷지 않는 활동이어도 시작·줍기·종료를 허용한다. 일시정지 구간 걸음은 누적과 거리 보정에서 제외한다. 미측정은 null이며 0걸음과 구분한다. 활동 중·요약·상세에 표시하고 공유 이미지에는 측정값이 있을 때만 넣는다 |
| 권한 요청 | 위치는 활동 시작 직전에만 요청한다. 홈·피드·모이깅·내 기록은 위치 권한 없이 이용한다. 걸음수·알림 권한 거부는 활동을 막지 않는다 |
| 활동 저장 | 오프라인이어도 기기에서 즉시 종료하고 추적을 끈다. 계정별로 줍기와 종료 요청을 보존하며 줍기 → 종료 순서로 동기화한다. 종료 저장 전에는 공유·다음 활동을 막고 저장 대기와 재시도를 제공한다. 재실행·오류·다음 시작 때문에 미저장 데이터를 삭제하지 않는다 |
| 계정·크루 이탈 | 진행 중이거나 동기화 대기인 활동이 있으면 로그아웃·크루 나가기·회원 탈퇴 전에 종료와 동기화를 안내한다. 저장 실패는 기록을 보존하며 재시도한다 |
| 로고·캐릭터 | 기존 캐릭터를 로고·앱 아이콘·홈 게이미피케이션·빈 상태 화면에 공통으로 쓴다. 필요한 에셋: 홈 단계 5장 · 앱 아이콘(Android adaptive 전경/배경) · 스플래시 1장 · 빈 상태 3장(활동 없음·게시물 없음·알림 없음). `design-system/assets/character/` 에 둔다. 생성 프롬프트는 `docs/character-prompts.md` |
| DB | Supabase 의 Postgres(PostGIS) 만 쓴다. Spring 이 JDBC 로 접속. Supabase Auth·Storage·Realtime 은 안 쓴다. EC2 Postgres 컨테이너 제거. 리전은 서울로 맞춤 |
| 음성 입력 | 이후. 인터뷰의 음성 요구는 기존 앱의 수동 입력이 불편해서 나온 것이라, 사진 분류와 줍기 UI 가 그 자리를 채운다. 실제 사용에서 여전히 불편하면 다시 검토 |
| 소속 | 한 사람은 크루 하나에만 소속된다. 동네(hood) 개념은 끔 — 온보딩·홈·백엔드에서 제거 |
| 앱 이용 조건 | 크루에 소속돼야 앱을 쓴다. 크루를 만들거나 공개 크루에 가입하면 바로, 비공개 크루는 크루장 승인 뒤부터 쓴다. 미가입자(소속 없음·승인 대기)는 크루 만들기·검색·가입·가입 신청과 그 상태 확인·취소·거절 안내 확인만 한다. 예외로 늘 열어 두는 것: 계정 기능(로그아웃·회원 탈퇴)과 본인 활동·통계 조회(위 "기록") |
| 회원 탈퇴 | 크루 합산 숫자는 유지. 게시물·댓글은 "탈퇴한 크루원" 이름으로 보존. 개인 활동 상세(경로 포함)는 삭제. 크루 나가기·추방과 다르다 — 그 경우 계정이 살아 있어 기록이 이름 붙은 채 남는다. 그 사람의 추방 이력(`crew_expulsions`)과 확인하지 않은 거절 안내도 계정과 함께 지운다(2026-10-11) — 재가입은 새 계정이라 이력을 이어받을 수 없고, 개인정보는 최소로 보관한다 |
| 크루장 | 한 명. 다른 크루원이 있으면 위임 후 나가기·탈퇴한다. 혼자 남았으면 크루 해산 확인 후 나갈 수 있고 크루는 소프트 삭제한다. 운영진 층 없음 |
| 크루 가입 방식 | 초대 코드는 끔(2026-10 회의). 크루 검색에서 크루를 골라 가입한다. **공개 크루**는 크루장 승인 없이 바로 크루원이 되고, **비공개 크루**는 가입 신청을 보내 크루장이 승인·거절한다. 승인 전 신청은 승인 대기(PENDING)이며 크루원이 아니다. 공개·비공개는 검색 노출이 아니라 **승인 필요 여부**다 — 두 유형 모두 검색된다 |
| 가입 신청 | 승인 대기 신청은 한 사람에 한 건이다. 대기 중에는 다른 크루 검색·가입·가입 신청·크루 만들기를 할 수 없고, 1-9 의 [요청 취소]로 직접 취소해야 다시 할 수 있다. 다른 크루 가입·만들기가 기존 신청을 자동 취소하지 않는다. 거절된 사람은 같은 비공개 크루에 기다림 없이 다시 신청할 수 있다 |
| 재가입 | 추방된 사람은 같은 크루에 다시 들어올 수 없다 — 공개 크루 가입도, 비공개 크루 가입 신청도 막는다(403 EXPELLED_FROM_CREW). 공개 전환 자동 가입에서도 추방 이력을 다시 확인해 우회를 막는다. 추방 이력은 크루별로 남기며, 크루장이 이 제한을 풀어 주는 기능은 이번 범위에 없다 |
| 거절 안내 | 거절은 1-9 를 보고 있을 때뿐 아니라 다음 로그인·앱 실행 때도 알린다. 확인하지 않은 거절 안내가 있으면 1-9 의 거절 상태를 보이고, [확인]을 누르면 확인 처리 뒤 1-6 으로 간다. 확인한 안내는 다시 보이지 않는다. 거절 뒤 `membership.status` 는 NONE 이고, 미확인 거절은 `membership.rejection` 으로 따로 온다 |
| 크루 정원 | 크루장 포함 **50명**. 승인 대기 신청자는 세지 않는다. 공개 크루 즉시 가입, 비공개 크루 **가입 신청**, 가입 승인, 공개 전환 때 검사하고 넘으면 409 CREW_FULL 이다. 정원이 찬 비공개 크루에는 새 신청을 받지 않고, 자리가 생기면 다시 신청할 수 있다. 이미 들어와 있던 대기 신청은 자동 취소하지 않는다(승인 때 다시 검사). 정원이 찬 크루도 검색에 나오며 앱은 "정원이 찼어요"를 보이고 가입·신청 버튼을 막는다 |
| 활동 지역 | 크루가 주로 활동하는 곳을 보여 주는 크루의 설명 속성이다. 사람의 소속 단위가 아니며 동네(hood) 개념을 되살리지 않는다. 시·도 17개 목록에서 하나를 고른다(자유 입력 없음). 크루 만들기 때 필수이며 크루장이 나중에 바꿀 수 있다 |
| 공개 설정 변경 | 크루장은 만든 뒤에도 공개/비공개와 활동 지역을 바꿀 수 있다. 비공개 → 공개로 바꾸면 기존 승인 대기 신청자를 즉시 모두 가입시킨다(신청자에게 승인 알림). 기존 크루원 + 대기 신청자가 50명을 넘으면 **전환 자체를 막고**(409 CREW_FULL) 크루장에게 대기 신청을 정리한 뒤 다시 바꾸라고 안내한다. 일부 신청자만 골라 가입시키지 않는다 |
| 보존·정리 | 이용자에게 약속한 기간은 `docs/legal/privacy.md` §2 가 정본이고, `ERD.md` §보존·정리 가 그 구현 표다. privacy.md 에 없던 둘을 정한다(2026-10-13): 종료 없이 갱신이 끊긴 실시간 위치는 **마지막 갱신 뒤 30분 안에** 지운다(5분마다 25분 넘은 행을 정리) — 5초 갱신이라 30분이면 잠깐의 통신 끊김과 구별되고, 활동이 이어지면 다음 갱신이 다시 만든다. 직접 지운 콘텐츠(활동·게시물·댓글·공지·채팅)의 소프트 삭제 행은 **30일 안에 물리 삭제**한다(매일 29일 넘은 행을 정리) — 신고 처리에 쓸 짧은 유예다. 주기 작업의 선정 기준을 약속 기한보다 주기만큼 앞당기는 이유는 `ERD.md` §보존·정리 에 있다. 탈퇴한 `users`·해산한 `crews` 행은 게시물·활동 기록이 가리키므로 개인정보만 지우고 행은 남긴다 |
| 회원 탈퇴와 가입 신청 | 탈퇴하면 그 사람의 대기 신청을 모두 자동 취소(CANCELED)한다. 취소된 신청은 이후 승인·공개 전환 자동 가입 대상이 아니다 |
| 개발 데이터 | 새 크루 스키마(`region`·`join_policy` NOT NULL) migration 은 기존 개발 DB 의 크루 데이터를 지우고 시드로 다시 만든다. 운영 데이터는 아직 없다 |
| 기존 데이터 | 이관하지 않는다. 새 스키마로 빈 DB 에서 시작. Flyway 도 V1 부터 다시 쓴다 |
| 인프라 | 옛 EC2 구성은 버린다. Lightsail VM 한 대에 docker compose 로 백엔드·Redis·Nginx(ADR-0005). **스테이징은 두지 않는다** — `dev` 머지는 이미지만 만들고 `main` 머지가 그 태그를 운영에 배포한다. 감시는 헬스체크 + 외부 핑 + Mattermost 알림이고 Prometheus·Grafana 는 되살리지 않는다. 구성과 환경 변수 키 목록은 `operations.md` |
| 플랫폼 | 1차는 **Android 만**, React Native. iOS 는 이후(Apple 개발자 계정·Apple 로그인·HealthKit·Live Activity 가 함께 따라온다). 걸음수·운동 인식은 Health Connect(삼성헬스 데이터 포함) |
| 지도 | 카카오맵 Android SDK 를 RN 네이티브 모듈로 감싼다. 옛 앱의 지도 코드(경로 선·마커·카메라 추적)를 참고. iOS 를 넣을 때 지도 SDK 를 다시 정한다 |
| 온보딩 화면 수 | 비밀번호 재설정은 요청·확인을 한 화면에서 한다. 위치 권한 안내는 활동 시작 시트 안에서 한다. 권한 하나 때문에 화면을 따로 두지 않는다. 크루 만들기는 바텀시트가 아니라 별도 화면 1-7 이다(입력 넷: 이름·설명·활동 지역·공개 설정) |
| 계정 메뉴 | 크루가 없거나 승인 대기여도 설정에서 로그아웃·탈퇴할 수 있다. 이때 설정에는 로그아웃·회원 탈퇴만 보인다 |
| 화면 방향·테마 | 세로 고정이다. 활동 중 지도와 촬영 화면이 걷는 자세에서 쓰여 가로가 필요 없다. 다크 모드는 기기 설정을 따른다 |
| 크루 화면 수 | 크루 정보·크루원은 3-11 크루 정보 한 화면이다. 크루 나가기도 3-11 에서만 한다 — 설정(5-7)은 계정(로그아웃·탈퇴·로그인 연결)만 다룬다(2026-10-13). 가입 신청(3-8)과 신고 처리는 목록이 길어 별도 화면으로 남기고 3-11 에서 들어간다. 공지 목록은 3-1 모이깅의 공지 탭이다 |
| 줍기 입력 | 사진 줍기는 셔터 → AI 확인(4-5) 두 단계다. 셔터를 누르면 바로 올리고, 다시 찍기는 4-5 가 맡는다. 빠른 줍기 카드는 한 번 누르면 하나, 길게 누르면 수량 입력이다. 줍깅 버튼에는 첫 안내 화면이 없다 |

## 화면별 유지 · 변경 · 신규 · 끔

### 온보딩
- 가입 전 동의 목록은 공개 `GET /agreements` 로 조회한다. 인증 뒤 동의 상태 조회·저장은 `/users/me/agreements` 로 하며 현재 버전의 필수 동의가 완료되어야 소속 분기로 진행한다. 전문 URL·버전이 설정되지 않았으면 가입을 완료시키지 않는다.
- 이메일 가입은 한 화면에서 이메일·비밀번호·닉네임을 받는다. 소셜 첫 가입은 닉네임만 받고 사진은 프로필 수정에서 받는다. 가입 완료 뒤 "기존 크루에 들어가기" 또는 "크루 만들기" 선택(1-6)으로 간다
- 가입 완료 전 약관·개인정보 안내와 동의를 제공하며 필수·선택을 구분한다. 동의 상태·저장은 `/users/me/agreements` 별도 경로이고, 약관 버전이 오르면 다음 진입 때 1-4 에서 재동의한다
- 앱을 다시 열면 완료하지 못한 온보딩 단계로 복귀한다. 승인 대기는 푸시 수신·앱 복귀·수동 새로고침으로 갱신한다
- 첫 로그인·재로그인·앱 실행 때마다 `GET /users/me` 의 `membership` 으로 최신 소속과 신청 상태를 확인한다
  - MEMBER → 가입한 크루의 메인(2-1 홈). 대기 중 승인됐으면 대기 안내 없이 바로 홈
  - PENDING → 1-9 "{크루명} 크루 가입 승인 대기 중입니다." + [요청 취소]. 크루원이 아니므로 하단 탭·크루 기능을 열지 않는다
  - NONE 이고 `membership.rejection` 이 있음 → 1-9 거절 안내. [확인] → 확인 처리 → 1-6
  - NONE 이고 미확인 거절 없음 → 1-6
- 끔: 동네 선택 · 초대 코드
- 1-6: "기존 크루에 들어가기"(→ 1-8 크루 검색) · "크루 만들기"(→ 1-7) 두 선택지, 내 활동 기록(→ 5-5 기록 전용 → 5-3), 설정(로그아웃·탈퇴)이 있다
- 크루 만들기(1-7, 별도 화면): 크루 이름(필수) · 크루 설명(선택) · 활동 지역(필수, 시·도 목록 선택) · 공개/비공개(필수, 기본값 없이 사용자가 고른다). 만든 사람이 크루장. 대표 사진·크루 목표는 모이깅 탭의 크루 정보 수정에서 크루장이 채운다. 목표 기본값은 서버가 정한 값으로 시작
- 크루 검색(1-8): 검색어 없이 들어오면 전체 크루, 크루 이름 부분 일치와 활동 지역(시·도)으로 찾는다. 둘 다 주면 둘 다 맞는 크루만(AND). 결과는 크루 이름 오름차순. 공개·비공개 모두 나온다. 미가입자만 쓴다
- 가입: 1-8 에서 크루를 골라 가입한다. 공개 크루는 바로 크루원이 되어 홈으로, 비공개 크루는 가입 신청 후 1-9 승인 대기로 간다. 정원(50명)이 찬 크루는 가입·신청·승인이 안 된다. 추방된 크루에는 가입도 신청도 안 된다

### 홈
- 유지: 화면 구조(인사 · 상단 선택 · 알림 버튼 · 카드 3장 · 오프라인 카드)
- 변경: 동네 선택 → 크루 이름 표시
- 변경: "이번 주 우리 동네" 카드 → "최근 7일 우리 크루가 주운 쓰레기" (개수 + 7일 스파크라인 유지). 누르면 모이깅 탭의 크루 기록으로
- 변경: "지금 근처에서 함께 줍는 사람" 카드 → "지금 활동 중인 크루원" (수 + 얼굴, 누르면 목록)
- 변경: "이번 주 내가 주운 쓰레기" → "최근 7일 내가 주운 쓰레기"
- 변경: 가운데 지도 → 크루 캐릭터(기존 캐릭터 사용). 최근 14일 크루 줍기 개수를 크루장이 정한 목표와 비교해 5단계로 모습·표정이 바뀐다 — 목표 대비 비율 0~19% 축 처짐 · 20~49% 보통 · 50~79% 신남 · 80~99% 반짝 · 100% 이상 파티. 굴러가는 14일 창이라 절벽 리셋 없이 서서히 변한다. 누르면 "최근 14일 N개, 목표까지 M개". 내 것 보기·다시보기·전체화면 지도는 끔
- 끔: GPS 약함 배너(지도가 빠지므로)

### 피드
- 변경: 게시물은 자유 게시물 하나. 사진 여러 장 + 글. 활동 종료 화면의 "피드에 올리기" 는 요약 이미지를 첨부한 자유 게시물을 만드는 것
- 변경: 탭 2개 = 전체(크루) / 내 게시물. 내 게시물에는 본인의 CREW·PRIVATE 게시물이 모두 포함된다
- 글 또는 사진 중 하나만 있어도 게시할 수 있다. 사진은 최대 10장. 이번 범위에 게시물 수정 기능은 없다
- 변경: 검색 버튼 → 달력(날짜로 찾기)
- 유지: 좋아요·댓글

### 모이깅 탭 (크루)
- 신규: 크루 정보(이름·소개·대표 사진·활동 지역·공개/비공개·크루원 수/정원·크루원 목록). 크루장은 수정(활동 지역·공개 설정 포함)·목표 설정·가입 신청 승인·추방·위임을 여기서 한다
- 신규: 공지사항 — 크루장이 쓰는 글 목록. 최신 공지 하나가 모이깅 탭 상단에 고정. 댓글 가능
- 유지: 채팅 — 크루 단체방 하나 (소켓으로). 공지·채팅은 텍스트 중심으로 두고 검색·공지 이미지·별도 임시저장 버튼·시스템 메시지는 추가하지 않는다. 화면 이동 중 초안과 전송 실패 입력은 보존한다
- 신규: 일자별·멤버별 활동 내역 달력
- 신규: 크루 기록 — 한국 시간 기준 이번 주(월요일 시작)·이번 달·전체. 순위는 줍기 수 기준으로 동점은 같은 순위. 전체 추이는 월 단위, 달력은 활동 건수로 표시한다. 홈의 최근 7일·14일과 기간을 구별한다
- 끔: 모임 만들기·찾기·가입·관리·초대 링크·초대 코드 (크루 찾기는 모임 찾기와 별개로 온보딩 1-8 에만 있다)

- 신규: 내 위치로 돌아가기
- 끔: 함께줍깅, 음소거
- 신규: 유효한 걸음수가 있을 때만 거리 보정에 활용한다. Health Connect는 선택이며 시간은 시작·일시정지·종료 시각으로 계산한다
- 0개 또는 매우 짧은 활동도 저장한다. 종료 요약에 기록 삭제를 제공한다. 미전송 데이터가 남았으면 먼저 동기화하고 서버 기록을 삭제한다

### 프로필·기록
- 유지: 내 프로필·프로필 수정·활동 기록 상세
- 설정 유지: 프로필 편집 · 비밀번호 재설정 · 차단 관리 · 로그아웃 · 회원 탈퇴
- 설정 신규: 활동 시작 알림 켬/끔(팔로우와 별개의 전체 스위치) · 위치 공유 기본값(활동 시작 때 미리 선택된 값)
- 비밀번호 재설정 성공 후에는 다시 로그인한다. 소셜 전용 계정에 이메일 비밀번호를 새로 만드는 기능은 이번 범위에서 제외한다
- 본인 활동의 줍기 종류·수량 수정과 삭제를 제공한다. 사진 순서·대표 사진 편집은 제외하고 타인 활동의 사진도 모두 열람할 수 있다
- 설정 끔: 우리 동네 변경 · 지도에 내 활동 표시
- 변경: 타인 프로필 = 기본 정보 + 탭 2개(기록: 누적 거리·개수·활동 달력·활동 상세 / 게시물: 그 사람이 크루 전체에 올린 것)
- 끔: 모임별 기록

### AI 줍기
- 유지: 카테고리 7종(담배꽁초·캔·플라스틱·종이·유리·비닐·일반). AI 확인·빠른 줍기는 같은 2열 카드와 수량 입력 부품을 쓴다. −/+는 48dp 이상이며 숫자로 직접 입력할 수 있다
- 신규: 사진 없이 카테고리 버튼만 눌러도 줍기가 기록된다(빠른 수동 입력). AI 는 사진을 찍었을 때만
- 변경: 사진 한 장에서 찾은 물체를 전부 기록한다. 서버 탐지 모델은 이미 박스 여러 개를 돌려주고 앱이 최고 신뢰도 하나만 남기고 있었다. 찾은 것을 카테고리별 수량으로 묶어 보여 주고 사용자가 수정한 뒤 저장
- 변경: AI 신뢰도 0.7 미만인 항목이 있는 카테고리에 "확인 필요"를 표시한다. 신뢰도를 정답 확률 %로 표현하지 않는다. 모델 개선 실험 수치는 실환경 정확도와 구별한다
- 활동 사진은 직접 촬영만 제공한다. 오프라인은 빠른 줍기를 사용하고, 업로드 성공 후 AI만 실패하면 사진을 유지한 채 수동 입력으로 이어간다
- 빠른 줍기는 기기에 즉시 보존하고 전송한다. 되돌리기는 미전송 항목 취소 또는 저장된 항목 삭제로 처리하며 열린 시트 안에서도 접근할 수 있다. 5초 묶음 전송은 하지 않는다

## 공통 화면 원칙

- 기존 디자인 시스템의 색·폰트·간격·반경·48dp 최소 터치 영역을 따른다. 장식과 미리보기를 먼저 줄이고 부족하면 세로 스크롤한다. 글자와 터치 영역은 줄이지 않는다. 프로필 소개는 2줄 뒤 더 보기로 펼친다
- 입력 오류는 해당 필드 아래, 요청 실패는 입력을 보존한 상태로 재시도를 제공한다. 제출 중 중복 요청을 막는다. 실제 요청이 계속되는 상태를 "취소됨"으로 안내하지 않는다
- 이름은 앞뒤 공백과 줄바꿈을 정리하고 계약 길이를 적용한다. 불필요한 문자 제한을 추가하지 않으며 중복은 저장 시 확인한다. 비밀번호 입력값은 임의 변경하지 않는다
- 사진은 OS 선택기를 공통으로 사용하고 필요한 곳에 촬영을 제공한다. 게시물 사진 순서 변경은 드래그와 앞·뒤 버튼을 함께 제공한다
- 문구는 상태와 다음 행동을 알려준다. 용어는 `CONTEXT.md`, 시간·거리·카테고리 표기는 화면 사이에 동일하게 쓴다. 목록·입력·메뉴·확인은 기존 `ListRow`·`Field`·`BottomSheet`·`Dialog`를 재사용한다

## 미결

- 줍기 항목에 연결되지 않은 활동 사진의 정리 시점. 활동 도메인 백엔드가 생긴 뒤 정한다
- 캐릭터 홈 5단계·빈 상태 3종은 기존 새싹의 형태와 팔레트를 유지하는 방향으로 확정. 누락 에셋 제작과 작은 화면·큰 글자·실기기 검증은 구현 단계 산출물이다
