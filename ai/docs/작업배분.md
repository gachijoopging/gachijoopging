## 1. 무엇을 위한 사진인가

**검증셋 전용입니다.** 학습은 TACO(1,500장 / 4,031박스)와 AI Hub 가 맡습니다.

검증셋은 성적표입니다. 그리고 남은 6주의 판단이 전부 그 성적표 위에서 이뤄집니다 —
`GENERAL` 포함/제외 A/B, confidence 보정, `CONF_MIN` 실측. TACO(유럽 길거리)로만 성적을
매기면 지표는 시연(한국 길거리)을 예측하지 못하고, **잘 될지를 데모 당일 처음 알게 됩니다.**

그래서 목표는 총 장수가 아니라 **클래스당 인스턴스 수**입니다. 클래스당 50 아래면 AP 가
사진 한두 장에 출렁여 판단 자체가 불가능해집니다.

## 2. 인원 · 이니셜 · 구역

| 이름 | 이니셜 | 담당 구역 |
|---|---|---|
| 서상혁 | `ssh` | (현장 배정) |
| 김해찬 | `khc` | (현장 배정) |
| 백관열 | `bky` | (현장 배정) |
| 김영현 | `yh` | (현장 배정) |
| 김윤영 | `yy` | (현장 배정) |

이니셜은 폴더 이름과 파일명에 쓰는 값입니다. 김영현·김윤영을 `kyh`/`kyy` 로 하면 한 글자
차이라 오타가 나므로 2자로 줍니다.

**구역을 나누는 이유** — 같이 다니면 같은 페트병을 두세 명이 각자 찍습니다. 그 사진들이
학습셋과 검증셋으로 갈리면 **mAP 가 부풀려집니다.** 사진만 보고 같은 물체인지 판정하기
어려워 나중에 걸러낼 수 없으므로 사전에 막습니다. 이니셜이 곧 구역 식별자라, 필요하면
파일명만으로 같은 구역 사진을 같은 쪽에 몰아넣을 수 있습니다.

## 3. 얼마나 — 1인 70개

| 카테고리 | 1인 | 5명 합계 | 어디서 흔한가 |
|---|---|---|---|
| `CIGARETTE` 담배꽁초 | 10 | 50 | 흡연구역 주변·화단·보도블록 틈 |
| `CAN` 캔 | 10 | 50 | 벤치·정류장·공원 |
| `PLASTIC` 플라스틱 | 10 | 50 | 어디나 |
| `PAPER` 종이 | 10 | 50 | 어디나 |
| `GLASS` 유리 | 10 | 50 | **가장 어렵습니다 — 아래 참고** |
| `VINYL` 비닐 | 10 | 50 | 어디나 |
| `GENERAL` 일반 | 10 | 50 | 이사철 골목·공사장 주변 |
| **합계** | **70** | **350** | |

사진 장수로는 **1인 20~35장** (한 장에 2~4개가 자연스럽습니다).

**장수가 아니라 개수가 목표입니다.** 눈에 띄는 대로 30장을 찍으면 꽁초와 플라스틱만 나오고
유리병은 다섯 개도 안 나옵니다. 그러면 유리병은 시연 날까지 못 잡습니다.

`GLASS` 10개를 자연 상태로 찾기는 어렵습니다. 못 채우면 연출로 찍어 `-s` 폴더에 넣어
주세요 — 검증셋에는 들어가지 못하지만 학습에는 그대로 씁니다. 부족분은 기록해서 W4 ⑱
타깃 보강으로 넘깁니다.

## 4. 세션

| 항목 | 값 |
|---|---|
| 날짜 | **미정 — 8/11 까지. 빠를수록 라벨링에 여유가 생깁니다** |
| 시간 | 16:00~19:00 사이 **1~1.5시간** |
| 준비물 | 폰(기본 카메라·JPEG) · USB 메모리 공용 1개 · 연출용 유리병 몇 개 |

**왜 오후~해질녘인가** — 한 세션에 다 찍으면 조명이 균일해집니다. 촬영가이드가 요구한
"1/4 이상은 어려운 조건"이 물리적으로 불가능해지는 것이죠. 이 시간대는 **주광 → 역광 →
박명이 한 세션에 자연스럽게 섞입니다.**

주광 사진은 TACO 가 1,500장을 이미 공급합니다. 우리가 채워서 가치가 큰 쪽은 **TACO 에 없는
저조도**입니다. 완전한 야간과 비 온 뒤 젖은 상태는 AI 담당이 따로 보충합니다.

**왜 8/11 이면 되나** — 검증셋만 찍으면 100~150장이고, 단독 라벨링에 5~12시간입니다.
8/11 세션이면 8/16 마감까지 5일, 하루 1~2.5시간이라 ⑨⑩ 과 병행할 수 있습니다.

## 5. 전송 — USB 현장 복사

한자리에 모이니 그 자리에서 USB 로 받습니다. **이 구조로 넣어 주세요:**

```
USB/
  ssh/      실제로 발견한 것   (폰 파일명 그대로)
  ssh-s/    연출한 것
  khc/
  khc-s/
  ...
```

- **파일명은 바꾸지 마세요.** 폰이 준 이름(`IMG_0001.jpg`) 그대로 복사하면 됩니다.
  규칙에 맞는 이름은 [`scripts/prep_labeling.py`](../scripts/prep_labeling.py) 가 붙입니다
- **연출한 사진만 `-s` 폴더로 갈라 주세요.** 팀원이 지킬 규칙은 이것 하나입니다
- 카톡·문자·DM 금지 — 리사이즈되고 EXIF 가 삭제되는데 **육안으로는 멀쩡해 보여서 발견이
  늦습니다** (촬영가이드 §5)

## 6. 라벨링 — AI 담당 단독

### 도구: Label Studio Community (로컬)

Roboflow 무료는 **좌석 2명**이고 데이터를 Roboflow Universe 에 **공개 강제**라 탈락했습니다.
CVAT Online 무료는 500MB / 태스크 10개로 부족합니다. 단독 작업이 되면서 중앙 호스팅·계정
초대 자체가 불필요해져 로컬로 갑니다.

```bash
uv tool install --python 3.11 label-studio
```

**`--python 3.11` 이 필수입니다.** 빼면 uv 가 3.14 를 고르고, `django-environ` 이 3.14 에서
제거된 `pkgutil.find_loader` 를 임포트하다 부팅 중에 죽습니다.

```bash
label-studio start -b -p 8080
```

### 프로젝트 설정

1. `http://localhost:8080` 에서 계정 생성 (로컬 SQLite 에만 남습니다)
2. 프로젝트 생성 → Labeling Setup → **Custom template**
3. [`configs/label_studio_config.xml`](../configs/label_studio_config.xml) 내용을 붙여넣기

그 파일은 **ASCII 만** 담습니다. `label_studio_sdk` 가 config 파일을 `io.open()` 으로
인코딩 지정 없이 읽어서, 한글이 있으면 한국어 Windows 가 cp949 로 디코딩하다 터집니다.
그래서 근거는 이 문서에 있고 파일에는 없습니다.

hotkey `1`~`7` 이 `app/classes.py` 순서와 같습니다 — 손이 인덱스를 외우게 됩니다.

### 사진 준비

```bash
uv run python scripts/prep_labeling.py <USB경로> --date 20260811
```

`datasets/own/labeling/` 에 **정방향 사본**을 만들고 파일명을 붙입니다. 추적표
(`_manifest.csv`)에 `사본 → 받은폴더 → 원본파일명` 이 남습니다.

**원본에 직접 라벨하지 않습니다.** 라벨링 도구가 EXIF Orientation 을 어떻게 다루는지 통제할
수 없고, 무시하는 순간 세로 사진에 가로 좌표가 찍히면서 **에러 없이 조용히 틀어집니다.**
사본에는 EXIF 가 없으므로 도구가 무엇을 하든 결과가 같습니다. bbox 는 정규화 좌표라 사본에서
딴 값이 원본에도 그대로 유효합니다 (학습 로더가 EXIF 를 적용합니다 — `진행상황.md` §3.3).

### Export → ⑨ 계약

- 형식은 **YOLO**
- **⑨ 는 export 의 클래스 인덱스를 신뢰하지 않습니다.** `classes.txt` 의 **이름**을 읽어
  `app/classes.py` 의 인덱스로 다시 매핑합니다
- 그래야 하는 이유는 실측입니다 (2026-08-02). Label Studio 는 라벨을 `set` 에 담고
  `sorted()` 로 인덱스를 매깁니다 — config 순서가 아니라 **알파벳순**입니다.
  `GLASS` 가 4 대신 3 으로 나가고 txt 는 완벽히 정상으로 보입니다.
  config 에 `category="N"` 을 박아 현재는 순서가 맞지만, 그 속성이 빠지면 다시 어긋납니다
- 좌표는 **YOLO 중심 정규화**(`class cx cy w h`)입니다. API 계약의 좌상단 형식과 다릅니다
- `-s` 파일은 검증셋에서 기계적으로 제외합니다

### 애매한 사례

단독 라벨링이라 라벨링가이드 §6 의 "팀에 공유해서 함께 정한다"가 성립하지 않습니다. 대신:

1. 그 물체는 **라벨하지 않고** 넘어갑니다
2. 파일명과 무엇이 애매했는지를 [`개발일지.md`](../개발일지.md) 에 적습니다
3. 판단이 서면 [`진행상황.md`](../진행상황.md) §3.2 에 한 줄 추가합니다

혼자 정하는 것 자체는 문제가 아닙니다. **판정이 흔들린 자리를 기록하지 않는 것**이
문제입니다 — 나중에 confusion matrix 를 봐도 원인이 안 보이기 때문입니다.
