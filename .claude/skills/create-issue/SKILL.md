# 가치줍깅 이슈 등록 (Linear)

## 핵심 계약

범위가 잡힌 일감만 만든다. 담당을 폴더로 가르고, 완료를 검증 가능하게 쓰고, 다른 워크스페이스에 쓰지 않는다.

Linear MCP 도구(`list_issues` · `list_teams` · `save_issue` · `list_issue_labels`)로만 접근한다.

## 필수 선행 로드

작성 전에 아래를 읽는다. `docs/` 전체를 읽지 않는다 — 정본이 갈라져 있는 이유가 그것이다.

1. **`docs/feature-scope.md`** — 결정된 것·권한표·화면별 유지/변경/신규/끔. 다른 문서와 어긋나면 여기가 맞다
2. **`CONTEXT.md`** — 용어. 이슈 제목과 본문의 이름은 여기 것을 쓴다
3. 건드리는 것만 추가로:
   - 계약 변경 → `docs/openapi.yaml`
   - 화면 → `docs/screens/<번호>-<이름>.md`
   - 테이블 → `docs/ERD.md` · 실시간 → `docs/realtime.md`
   - 백엔드 도메인 → `docs/backend-migration.md` · `backend/docs/02-conventions.md`
4. **`docs/conventions.md`** — 브랜치·PR·커밋 형식

## 담당 (폴더 오너십)

| 담당 | 폴더 | scope |
|---|---|---|
| 백관열 | `mobile/` · `ai/` | `app` · `ai` |
| 김영현 | `backend/` | `backend/<도메인>` |
| 김윤영 | `infra/` · `.github/` | `infra` |
| 공용 | `design-system/` · `docs/` | `design-system` · `docs` |

폴더가 둘로 갈리면 **이슈를 쪼갠다.** 한 사람에게 양쪽을 주지 않는다.
예외: 계약(`docs/openapi.yaml`) 변경은 conventions.md 대로 앱·백엔드를 같은 PR 에서 고치므로 쪼개지 않는다.

## 프로젝트 = 주 단위 5개

| Project | 기간 |
|---|---|
| `W0 레포 정비` | 9/10 ~ 9/11 |
| `W1 골격` | 9/27 ~ 10/4 |
| `W2 도메인` | 10/5 ~ 10/11 |
| `W3 통합·마무리` | 10/12 ~ 10/18 |
| `W4 마무리` | 10/19 ~ 10/25 |

이슈는 **할 주**의 Project 에 넣는다. 어느 주인지 모르겠으면 묻는다.

## 라벨

폴더 이름과 맞춘다 — 커밋 scope 와 한 단어로 꿰어진다.
`app` · `ai` · `backend` · `infra` · `design-system` · `docs` + 유형 `feat` · `fix` · `chore`

## 추정 (팀 합의)

```
1 = 1시간 이내   2 = 3~4시간   3 = 하루   5 = 이틀   8 = 3일
```

9/10~10/25 일정에서 **8점이 나오면 쪼개라는 신호다.**

## 설명 템플릿 (필수)

무엇을 만들지만 있고 제약과 완료 조건이 없는 티켓은 받지 않는다. **팀원이 설계 문서를 안 열고도 그 티켓만으로 움직일 수 있어야 한다.**

문서 내용을 티켓에 붙여넣지 않는다. 경로를 링크한다.

**API 구현**

```
## 설명
## 요구사항
## 계약        docs/openapi.yaml 의 경로·메서드. 요청·응답은 링크로
## DB          ERD.md 의 테이블. 새 컬럼이면 Flyway 버전
## 예외        실패 응답과 코드
## 완료 조건    통과해야 하는 테스트 이름
```

**일반 작업**

```
## 설명
## 요구사항
## 산출물      파일 경로
## 완료 조건    검증 방법. 실행 명령이 있으면 명령으로
## 참고        docs 경로
```

## 중복 검사 (초안 전 필수)

어떤 이슈든 만들기 전에 워크스페이스 전체를 검색하고, 후보를 보고한 뒤 멈춘다.

- **모든 담당자·모든 상태**를 검색한다. 내게 배정된 것만 보고 없다고 결론짓는 게 가장 흔한 실패다. 남이 가진 백로그 항목이나 이미 Done 인 티켓도 중복을 만든다
- 제목만이 아니라 **구체적 식별자**로 찾는다: 엔드포인트 경로(`/crew/live`), 화면 번호(`4-3`), 클래스·파일 이름, 기능 명사. 여러 변형으로 여러 번 돌린다
- 연결된 상위 이슈의 자식과 관련 이슈도 본다 — 중복은 링크 한 칸 옆에 있는 경우가 많다
- 후보가 있으면 **만들지 않는다.** 기존 키·제목·담당·상태와 겹치는 부분·다른 부분을 제시하고 어떻게 할지 묻는다
- 검색한 용어와 범위를 초안에 적는다

## 실행 경계

- 중복 검사 → 초안 → **승인 후 생성**. "바로 등록해" 는 승인으로 본다
- 가치줍깅 워크스페이스에만 쓴다. 다른 워크스페이스(예: Pet's port)를 대체물로 쓰지 않는다
- 이슈 타입·상태·라벨은 실행 시점에 조회한다. 이 문서의 값은 확인용 스냅숏이지 정본이 아니다

## 완료 시 반환

만든 이슈마다 **키 · 제목 · URL · 브랜치 이름**을 돌려준다.

브랜치 이름은 Linear 가 주는 이름에서 슬러그를 잘라 `<계정명>/gac-<번호>` 만 쓴다 (`conventions.md` §브랜치):

```
djm062954/gac-12
```

한글 슬러그를 그대로 두지 않는다 — 팀 전원 Windows 라 한글 브랜치명이 터미널에서 깨지거나 탭 완성이 꼬인다.
이 이름으로 브랜치를 만들면 PR 열림 → In Review, 머지 → Done 이 자동으로 걸린다.
만들기 전에 `git check-ref-format "refs/heads/<이름>"` 으로 검증한다.
